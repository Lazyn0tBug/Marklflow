# U5b 固定双Worker运行与开销测量实施审查

日期：2026-10-25；分支：architecture-refactor；父提交：49e62c7。范围为草案6 U5b；一次本地提交，不推送、不接应用UI、不启用生产双角色。

## 实现与模块边界

core/platform/web/MarkdownWorkerRuntime仅组合两个固定MarkdownWorkerAdapter与原PreviewActivation。它持有foreground/background各一个实例，正常任务完成后复用；每角色串行由原RoleTaskQueue/RoleExecutor及适配器busy检查共同约束。没有通用池、额外宿主、心跳、重试编排或重复预算层。应用入口未导入该运行宿主，真实双角色仅在独立浏览器夹具使用。

协调器仍负责唯一切换规则。宿主activate只在委托前检查闲置故障实例是否需更换；预览策略不在平台层复制。每个角色在停止及主宿主清理确认后，经一个released通知更换已停止/阻塞实例，先dispose旧实例，再以递增generation安装新实例。旧taskId及旧回调仍由原门禁拒收。后台FIFO/轻量合并和前台最新需求沿用现有实现。

原生宿主error/messageerror返回host错误并将执行器标为不可复用；清理完成后可以换实例。失败任务保持failed，取消任务保持cancelled，不自动重新入队；已存在的新待办在更换后继续。空闲Worker加载失败不会启动循环重建；下次用户请求再尝试。构造替代Worker失败保留角色阻塞及诊断，不派发到旧死亡实例，也不后台反复构造。

关闭宿主先解除活动预览固定、作废所有排队/活跃任务，再终止两个实例；released回调看到disposed不再重建。清理使用既有局部列表和停止证明，保留必要执行期限。缓存产物与源文会话独立持有，关闭计算宿主不删除它们，也不残留阻止LRU的活动固定。只新增releasePreviewReference小接口，没有新建交付/资源状态机。

## 审查与测试

6项新增单元覆盖：固定两个独立角色、停止清理后重建、host故障不重试旧任务、替代构造失败阻塞与新请求恢复、空闲故障无重建循环、关闭活动/待办/两个实例及活动缓存引用释放。既有队列、实例、期限和清理回归继续保留。

4项新增真实浏览器测试：开发、生产Worker资源、普通HTTP三环境运行双角色流程与开销采样；另用一次原生Worker模块请求中断验证失败任务不自动重试、重建后新任务成功。正常流程验证前后台同时有任务但每角色最多1活跃、后台C/B/D的FIFO和B待办合并、切出A只重建前台且C继续、切入后台未完成A时两侧未完成任务均丢弃并重算、缓存命中零生成、最终释放和无残余待办。

审查修正两项遗漏：host错误应使旧执行器保持不可复用，避免替代构造失败后派发到已死亡实例；关闭运行宿主必须释放活动缓存固定，而不是只终止Worker。没有修改Worker解析算法或升级依赖。

## 开销测量口径

- 固定96节、包含中文/emoji、公式源码及代码块的合成文档；同时处理A/C，1次冷执行和3轮已加载实例的重复执行。每轮增加短标签使MD键失效，确保测到真实生成而不是缓存命中。
- constructionMs只测主宿主创建两个Worker对象和安装适配器，不等于模块就绪；cold.wallMs覆盖请求准备到首次双角色完成，含模块加载/传输/校验/入库；各角色Ms从待办提交后的观察起点计到completed，以5ms轮询观察，不能当作纯Worker CPU耗时。
- 记录每轮原始值、输入UTF-8/快照字节、产物序列化字节、缓存估算字节，以及10ms定时器最大延迟。该延迟是主线程可响应性的代理，不是实际编辑器输入延迟。
- 记录构造前、冷完成、3轮热执行、切换后、释放后的页堆公开值、角色实例引用和任务资源趋势。Chromium performance.memory不标准且可能粗粒度，不代表两个Worker独立堆；Worker物理堆记null。未强制GC，不据此声称无泄漏或已测得物理内存上限。
- 原始记录见[开销记录](../acceptance/architecture-u5b-runtime-overhead.json)；不看结果后调整阈值，不修改A0冻结预算、不恢复每Worker16MiB保留量。此轮采样是可重现基线，不宣称性能提升或跨设备结论。
