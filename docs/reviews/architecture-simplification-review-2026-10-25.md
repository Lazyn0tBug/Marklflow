# A2、U0—U2 过度设计审查与小步调整计划

日期：2026-10-25；基线：architecture-refactor / 656c041。状态：仅文档审查与规划；未修改代码、未提交、未推送；R/U/P/V完整路线已规划，尚未实施。本文与AR-01、AR-03草案6共同取代此前任务治理的过度细化要求，不改变产品功能范围。

## 1. 审查依据与结论

按当前编辑器场景评估：用户编辑单一激活Tab；切换、导入、导出由用户操作；后台仅为切出未完成文档补渲染。人工操作之间仍可能存在异步读取或渲染，但只需守住操作入口和完成回调，不应据此建立通用并发治理平台。

只读核对contracts.ts、identity.ts、lifecycle.ts、resources.ts、deadlines.ts、executors.ts、queue.ts、supervisor.ts、dualWorkerPolicy.ts、previewIdentity.ts、roleQueue.ts、roleScheduler.ts及其生产引用。A2和U2组件目前未被生产UI/渲染入口调用；Worker夹具仅导入/构造。旧生产渲染队列仍独立运行，不能写成“TaskSupervisor已供生产路径使用”。U2证据为176项单元、30项Chromium历史通过，不证明这些抽象必要，也不证明双物理Worker已接入。

原则：每个状态、令牌、计时器或接口应对应本轮明确的用户操作或已发生故障；没有对应场景就不作为接入前提。严格化依靠清楚的类型与边界校验，不依靠更多身份字段和状态层级。

## 2. 场景裁决

| 场景 | 最少需要的机制 | 不需要的扩展 |
| --- | --- | --- |
| 编辑当前文档，旧预览稍后返回 | 当前任务ID；MD散列、渲染配置版本；完成时核对 | 多组指纹、每阶段授权检查、恢复票据链 |
| 切换Tab | 一个入口；完成则缓存引用，未完成则作废并从头排队 | 再次切回/快速切换专用状态机、中间状态迁移 |
| 后台有多个待办 | 一条FIFO；文档/模式合并；每Worker一个活跃 | 排队到期、到期标记及自动恢复体系 |
| 用户点导出并继续编辑 | 单个busy、冻结输入/配置/已读资源；来源文档标识 | 与预览共用整套生命周期和交付锁平台 |
| 用户导入文档 | 文件读取、大小/格式校验、创建或聚焦文档、明确错误 | 通用任务票据/租约；与预览共用调度器 |
| 引擎失败、Worker失去响应 | 错误/执行超时；适配器停止或重建；清理后再接任务 | 心跳体系、重试编排、故障宿主累积池 |
| 切回完成文档 | 内存Map命中后换引用；源映射/位置恢复 | 异步缓存恢复票据、持久化后端模拟器 |
| 保存草稿、未来本地写回 | 保留现有存储恢复；按所属文档记录保存结果 | 将未来Tauri权限/原子写回状态塞进每个预览请求 |

## 4. 最终保留的运行模型

- 会话保存文档内容、编辑状态/撤销、光标位置、未保存状态及缓存引用。一个激活Tab；任务ID应用内不复用，旧关闭会话的结果不可能匹配新任务。
- 前台一个Worker、后台一个Worker，各自串行。轻量后台待办按文档/模式合并FIFO；每次执行取得最新快照。DOM步骤单独串行，逻辑任务等待DOM时仍占本角色槽位。
- 切换统一执行：离开未完成任务作废并停止、后台重新排队；进入未完成后台任务作废；有效完成缓存直接更替指针，否则前台新生成。无关后台任务继续。
- 每次接受新编辑需求、配置变更、关闭或相关切换时使旧taskId失效。完成回调核对taskId及散列/配置键，完整产物校验后同步写内存缓存；前台显示再核对当前文档。无需独立恢复令牌。
- 导出单独busy，冻结来源文档/配置及实际资源，读取校验沿用既有规则。切换不取消已接受导出；关闭来源Tab可等待导出结束或明确取消。纯MD导出直接生成；其余格式复用有限生成函数和共享DOM串行入口，不强制全走Worker任务协议。DOM优先级只在步骤边界：导出、前台、后台；不抢占正在执行步骤，不新建导出Worker。
- 导入、源保存不放入预览队列。读取失败/损坏不创建空文档覆盖原件；保存结果仅作用于来源文档。重复导入操作在读取期间显示busy即可，不建立通用导入队列。
