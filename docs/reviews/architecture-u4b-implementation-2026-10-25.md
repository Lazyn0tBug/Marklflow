# U4b 唯一缓存与完整产物提交实施审查

日期：2026-10-25；分支：architecture-refactor；父提交：280924b。依据AR-03草案6 U4b；一次本地提交，不推送，不接UI或真实Worker。

## 单一路径与完成语义

PreviewActivation移除独立lookup及任意generated写缓存钩子的组合，改为接收同一个MemoryPreviewCache与一个必需的同步PreviewArtifactValidator；激活查询、正式入库、活动引用与会话预览引用都走此实例。原U3b/ U4a测试迁移到实际缓存，不保留临时Map写入路径或兼容分支。

执行器消息边界仍以unknown/schema校验实例、任务和产物，协调器不重复解析同一可信结构。RoleTaskScheduler先核对仍有效的taskId；协调器再核对claim/submission任务ID、文档仍打开、当前MD散列与配置版本。停止/已作废任务的迟到结果在交接前被拒绝，不能写缓存。

正式提交先拒绝错误诊断、非空源文对应空内容、重复节点/越界源范围及非法JSON，随后调用格式/引擎的完整性断言。断言接收独立副本，只能同步成功返回undefined或抛错，不能修改缓存候选或异步完成；误返回Promise时拒绝本次提交并处理拒绝回调。断言后再次核对源/配置键和taskId，最后同步put并更新对应会话引用。只有上述步骤成功才返回completed；校验/入库失败为failed，不提前设置完成。底层不接缓存的单独组件仍使用generated表示计算交接，这不是第二条应用完成路径。

格式断言是必需端口，没有默认放行函数。它必须检查目标格式的完整内容、所需源映射/资源及净化策略，不能把“返回了字符串”当完整。此次可控JSON生成器明确核对complete标志及源文一致性；真实HTML/Mermaid/MathJax/Paged.js校验与适配在后续U6接入，不把本次纯组件测试视为实际HTML净化或版面完整性证明。

## 展示及后台规则

前台产物只有在会话仍为当前文档且所选模式/键一致时才固定为活动缓存引用；后台完成只入缓存和更新所属会话，不改展示指针。currentPreviewReference是展示读取入口，每次核对当前文档、所选键、当前源/配置及引用是否仍可解析；任一失效则返回undefined并解除活动固定，不返回旧产物。切换先解除旧活动固定，缓存命中直接固定有效引用并返回，不调用生成器。

完成产物由缓存拥有，会话只留可失效引用；LRU不删除活动产物。缓存拒绝入库时任务失败、不更新会话或展示引用，不建立无预算的旁路产物。超限直出/其他格式的后续处理必须继续遵守预算，未在此步实现。真实展示挂载、浏览器布局和源位置恢复仍在U6，不把返回引用等同已完成DOM恢复。
