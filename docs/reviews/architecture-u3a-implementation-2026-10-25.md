# U3a 多Tab会话模型实施与审查

日期：2026-10-25；分支：architecture-refactor；父提交：13f7e8f。依据AR-03草案6 U3a；本地提交一次，不推送。

## 实现边界

新增纯应用模块application/sessions/documentSessions.ts，按DocumentRecord.id管理最多32个打开会话与唯一激活ID。打开自动激活；重复打开只聚焦已有草稿，保持内容、历史、位置和未保存状态，不用磁盘传入记录覆盖。只读接口和输入均隔离对象引用；没有DOM、React、任务调度、存储或平台副作用。

每个会话独立持有完整文档、最多100步撤销/重做历史、选区、编辑器横纵滚动及预览纵向位置。修改遵循原DocumentRecord契约，必须为下一个安全整数修订；撤销/重做恢复内容及配置，但修订继续递增，保留当前更新时间，不自行读取系统时钟。新修改清空本会话重做历史；选区按当前文本长度收缩，实际视口滚动约束留给后续UI。

打开已有文档默认已保存；新建未保存文档可显式传unsaved。保存标记仅接受当前修订，旧异步保存完成不能清除新编辑的dirty。撤销后即使内容与已保存版本相同，按修订保守标记未保存，沿用当前编辑器修订语义。关闭未保存会话返回unsaved并保留全部状态，调用方明确选择丢弃才删除；本组件不弹对话框、不执行保存。关闭激活会话选择右侧相邻会话，其次左侧，全部关闭后激活ID为空；关闭非激活会话不改激活ID。

会话是后续编辑状态的唯一所有者。U3b再把统一activate操作组合到任务协调器，IdentityGate只作为任务准入投影，不另建编辑会话。当前未接入生产App、不取消/重排任务、不接缓存，不修改现有存储后端或自动保存路径；真实Tab UI恢复仍在U6e。也不引入Tauri SDK。
