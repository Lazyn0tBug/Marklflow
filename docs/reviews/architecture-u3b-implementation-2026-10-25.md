# U3b 统一activate切换实施与审查

日期：2026-10-25；分支：architecture-refactor；父提交：225b0be。依据AR-03草案6 U3b；本轮一次本地提交，不推送，不接UI或真实Worker。

## 实现及模块边界

application/workspace/PreviewActivation组合U3a DocumentSessions与既有RoleTaskScheduler；activate(documentId,previewKind)为应用切换入口。会话继续唯一持有源文、撤销、位置及未保存状态，IdentityGate仅保留任务准入投影。workspace可依赖sessions/tasks及纯核心，sessions/tasks不能反向依赖workspace；全部纳入无DOM严格类型配置与依赖门禁。不引入缓存后端、框架、平台或引擎依赖。

activate先读取当前源文/配置版本并同步查询缓存，再执行切换；未知文档、非法配置或lookup异常不作废现有任务。协调器持有当前请求键和前台任务ID，不复制会话编辑数据或产物。原文散列/模式/配置版本相同、打开会话投影不变且当前需求仍排队/运行时，重复激活不重排；失败后再激活允许重新发起。打开或关闭会话导致投影变化时仍执行同步，不能被重复激活短路。

RoleTaskScheduler.activateDocument在同一同步调用内：校验打开文档投影，作废切出/切入及已关闭文档的当前任务ID，删除其各模式待办，要求其活跃任务停止，然后同步打开文档和唯一激活ID，最后继续调度。RoleTaskQueue.cancelDocument只移除对应文档待办，不影响其他FIFO位置。停止/清理未确认，原执行角色仍被占用，后续需求仅排队；作废任务的迟到结果不得交接。共享原有停止/计时/清理路径，不新增第二套生命周期。

切出文档按最近请求的预览模式查询最新MD/配置键：已有完整缓存则不重新生成；没有完整缓存则建立新的后台待办。后台待办继续仅保存文档/模式引用，在实际执行时重新读取最新源文和配置。切入文档的未完成后台工作统一丢弃；有效完整缓存只返回引用，没有缓存才建立新的前台需求。无关后台C不被A/B切换停止；每角色最多一个活跃任务，前后台各自串行。

## 缓存与后续边界

唯一缓存端口为同步lookup(key): string | undefined；输入为documentId/previewKind/原文UTF-8 SHA-256/renderConfigVersion，返回完整有效产物的引用或未命中。回调收到键副本，协调器不持有完整产物、不迁移中间数据、不实现put/LRU/预算/持久化。配置版本由应用提供，后续接入方负责在主题、选项及资源上下文等影响渲染的变化时推进版本，不能只跟踪MD。

本轮内存夹具在既有同步generated交接钩子中记录完整产物引用；这只是验证lookup及切换规则，不是生产缓存。结果返回缓存引用、前后台准入结果或重复需求不变；capacity/unsupported等结果不伪装成已开始，未来UI负责展示失败。完整校验、实际缓存入库/失效/LRU仍归U4，物理停止/重建归U5，工作台和DOM接入归U6。没有实现跨Tab DOM恢复，也不宣称缓存命中已在生产UI实现零重渲染。
