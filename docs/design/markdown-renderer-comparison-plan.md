# Markdown 转 HTML 对照方案

状态：条件性验证计划，尚未启动。主设计见 [预览重渲染优化设计](preview-rerender-plan-2026-11-06.md)。

## 启动条件

现阶段保留 remark/rehype。先完成 V2，确认渲染器内少一次语法解析且产物语义等价。以通过验证的 V2 构建建立基线。只有实测能定位仍可缩减的阶段或生产依赖，并能指出 markdown-it 原型预计删除的具体工作，才启动对照。缺少基线或明确假设时维持现有实现。

## 对照方法

仅替换 Markdown 到 HTML 的转换段。两组使用相同文档、资源、渲染配置、运行环境、构建模式和调度策略，保留现有公式、图表、净化、分页及导出交付路径。记录提交、运行环境、样本和冷暖状态，分别重复测量。

先验证等价性。样本涵盖普通文档、长文档、GFM、行内及块级公式、宏和编号、作者 HTML 混排、Mermaid/DOT、相对资产、分页符和错误输入。核对 HTML 语义及净化结果、编辑器所需的源位置和滚动定位、诊断与降级行为。用同一批样本检查流式、A4 和冻结导出。源码位置包含行内公式偏移以及多字节字符和不同换行的边界。HTML 序列化差异按语义判断。

| 核算项 | 记录 |
| --- | --- |
| 生产依赖 | 逐项列出可从生产依赖图移除的直接和传递依赖，区分仍由其他入口引用的包，以及新增的插件和适配代码。 |
| 包体 | 比较生产构建初始加载、按需块和总产物字节。若进入桌面包，用相同平台与打包配置记录安装包增量。 |
| 性能 | 记录解析、转换、整体预览就绪耗时，区分冷暖和普通、长文档。单独报告转换段节省和用户实际可见的收益。 |
| 语义迁移 | 列出需重写的转换规则、回归夹具、适配代码和长期维护面。若需要补回 HTML 树重写，将其依赖与耗时一并计入。 |

## 采纳标准

开始对照前，依据 V2 基线为拟改善项和可接受退化设定阈值。先通过语义与安全等价性，再判断依赖、包体或性能收益是否达到阈值，是否足以覆盖迁移及维护成本。结论列出实际可删项、保留项和新增项。收益无法确认、功能存在缺口或回补复杂度抵消收益时，保留 remark/rehype。
