## 3. 目标与不目标

**目标** ✓：

1. 一个导出入口 ✓，两个根（Web ✓／Tauri ✓）✓，**共用 ExportService** ✓ ✓。
2. 六个格式在两个根上**行为一致** ✓：同操作 ✓、同快照 ✓、同命名 ✓、一次确认 ✓ ✓。
3. 原生根交付**字节与 PDF** ✓（`select_native_save` ✓ → `write_native_bytes` ✓ ／ `print_native_pdf` ✓）✓。
4. PDF 有**独立回执** ✓ ✓。

**不目标** ✓：

- **不改 Web 路径的语义** ✓ ✓（它的短板是既成事实 ✓，留给 Mac/Linux 那一轮 ✓ ✓）。
- **不引入用户端依赖** ✓ ✓（不装 poppler ✓、不引 PDF 库 ✓ —— COM 写出器自带 ✓ ✓）。
- **不碰其他 OS** ✓ ✓（Mac/Linux 原生 PDF 排在 D9 之后 ✓ ✓）。
- **不再建隔离层** ✓ ✓（一道闸 ✓ ✓）。
- **不重验 PDF 的性质** ✓ ✓ —— 机制那一侧已证 ✓；M9 要证的是**接线** ✓ ✓。

## 4. 三个待定问题（动手之前定下来 ✓）

### ① 两个根怎么选 ✓

- **启动时选** ✓ —— 计划原文「启动选择 Web/Tauri 双组合根」✓ ✓。取值在**配置文件** ✓ ✓（`[export] root = "web" | "native"` ✓ ✓）。
- **非 Windows 只有 Web 根** ✓ ⇒ 配置选了原生而平台没有 ⇒ **不许自动回落** ✓（回落就是"降级" ✓ ✗）⇒ 要**明说**「此平台不支持静默 PDF」✓ ✓。
- 选了 Web 根 ⇒ 行为与今天**一模一样** ✓ ✓（默认 ✓）。

### ② PDF 回执的形状 ✓

现在 `deliverPdf(html): Promise<void>` ✓ —— 没有回执 ✓ ⇒ Web 路径**分不出取消与失败** ✓ ✓。M9 要给它一个**独立**的一套 ✓：

| 状态 | 含义 | 对应 ExportResult |
| --- | --- | --- |
| `saved` ✓ | 目标提交成功 ✓ | `completed` ✓ |
| `cancelled` ✓ | 用户取消 ✓（**没写任何文件** ✓） | `cancelled` ✓ |
| `failed` ✓ | 打印或提交失败 ✓（**原文件未动** ✓） | **`failed`** ✓（**独立状态** ✓ —— 失败不是完成 ✓） |

**不与字节格式那四态混用** ✓（`saved`／`download-started`／`recovered-download`／`activation-expired` ✓）—— PDF 没有"浏览器接管"这一说 ✓ ✓。

### ③ 原生根打印的就是**同一份导出 HTML** ✓

- 不重新生成 ✓ —— 沿用同一生成 ✓ ✓（`generatePdfHtml(artifact,{title:file.baseName})` ✓）✓。
- 由此**守卫仍是双保险** ✓ ✓：那份 HTML 带 CSP `default-src 'none'` ✓ + DOMPurify ✓ + 零脚本 ✓ ✓ → 它本来就作不了恶 ✓ ✓。
- **不因 M9 而变** ✓ —— 若将来打印的不再只是那份被清洗过的导出 ✓，那时守卫才成为唯一一道 ✓（见 `source_guard.rs` 的模块文档 ✓ ✓）。

## 5. 形状（已实施 ✓）

```
ExportService（不变 ✓：prepare 一次 ✓ / busy ✓ / exportFile 命名 ✓ / 源快照 ✓）
  └─ ExportPorts
       ├─ selectSave(file)   → 字节路径 ✓（Web 下载 ✓ ／ 原生对话框 ✓）
       └─ deliverPdf(html, file) → PdfDeliveryReceipt ✓
                                 {handed-off | saved | cancelled | failed} ✓
```

**两个根各有一套 ports ✓**，共用同一个 ExportService 类 ✓ ✓（"共用 ExportService"✓ ✓）。

| | Web 根 ✓ | 原生根 ✓ |
| --- | --- | --- |
| 字节格式 ✓ | 浏览器下载 ✓（四态回执 ✓） | 原生保存对话框 ✓ → `write_native_bytes` ✓（`saved` ✓） |
| PDF ✓ | 浏览器打印对话框 ✓ → **`handed-off`** ✓（它自己说不准 ✓） | 原生保存对话框 ✓ → `print_native_pdf` ✓ → **`saved`/`cancelled`/`failed`** ✓ |
| 目标释放 ✓ | 无授权可撤 ✓ | **finally 释放** ✓（成败都撤 ✓ ✓） |

原生实现 ✓（命令**已注册** ✓，主窗口在允许范围内 ✓ —— 9 个命令 ✓ ✓）：

```
select_native_save（拿 key ✓）→ write_native_bytes / print_native_pdf（按 key 换路径 ✓）
  → 目标 finally 释放 ✓ ✓（授权用完即撤 ✓ ✓）
```

**注意** ✓：原生侧拿到的只是 **key** ✓ —— 路径只在原生侧可见 ✓ ✓（前端只拿到 key 与文件名 ✓ ✓）。

**静默打印随产品构建走** ✓ ✓（原先在探针特性后面 ✓，产品够不着 ✓ —— 已移出 ✓ ✓）。

## 6. 验收项与证据形态

| 验收项 | 证据 |
| --- | --- |
| **同一份生成** ✓ | 同一份导出 HTML ✓ → 两个根各印一次 ✓ → 两份 PDF 并排 ✓ ✓ |
| **并排对照** ✓ | 同一份真实文档 ✓：Web 一份 ✓（`Producer: Microsoft: Print To PDF` ✓、无字体 ✓、无文本层 ✓）vs 原生一份 ✓（`Skia/PDF` ✓、字体全嵌入 ✓、有文本层 ✓）⇒ **差别即价值证明** ✓ ✓ |
| **命名** ✓ | 原生那份落在**真实文档的文件名**上 ✓ ✓（`exportFile` 的规则 ✓ ✓）；Web 那份只是 title 提示 ✓ ✓ |
| **取消** ✓ | 原生根取消 ✓ → **没写任何文件** ✓ ✓ + 独立回执 `cancelled` ✓ ✓ |
| **覆盖失败保护** ✓ | 目标被占住 ✓ → 提交失败 ✓（`print-not-committed` ✓ ✓）→ **原文件未动** ✓ ✓ + 回执 `failed` ✓ ✓ |
| **错误不降级** ✓ | 原生失败**不改投 Web** ✓ ✓ —— 不许悄悄换个根 ✓ ✓ |
| **不覆盖源** ✓ | 失败时源文件一字未动 ✓ ✓ |
| **源快照** ✓ | 回执里的 `documentId` + `revision` ✓ 与所印的那份一致 ✓ ✓ |
| **一次确认** ✓ | 一次 `prepare` ✓ ✓；一次目标选择 ✓ ✓ |
| **busy** ✓ | 并发导出被挡 ✓ ✓（服务自己的 `active` ✓ ✓） |
| **敏感命令宿主核对** ✓ | D8 核对**当时所有实际宿主** ✓ ✓：确需允许且路径可用 ✓，或有意受限且限制有效 ✓ ✓ —— **清单只有来源守卫那一份** ✓ ✓ |

## 7. 风险

1. **爆炸半径变了** ✓ —— 前几轮全在夹具里 ✓；M9 第一次动**产品的导出** ✓ ✓ → 先写注记（本文 ✓）再动代码 ✓ ✓。
2. **别顺手加隔离层** ✓ —— 能力清单文件刚删 ✓ ✓，M9 若引入第二道闸就把刚简化掉的又装回去 ✓ ✓。
3. **只在 Windows 有原生根** ✓ ⇒ 别的平台的声明照旧 ✓ ✓（不标不支持 ✓、不宣称已支持 ✓、未验不自动回退 ✓ ✓）。
4. **真实文档的字体环境** ✓ —— 冻结样本的字体是钉住的 ✓（`Microsoft YaHei UI` ✓ `Consolas` ✓）；生产里用户的文档可能用别的字体 ✓ → 机器上没装就替换 ✓ → **分页度量跟着变** ✓ —— 但导出与打印在同一台机器上 ✓ → 仍自洽 ✓ ✓；**换机器复现不了** ✓ ✓（已写进冻结文档 §8.4 ✓ ✓）。
