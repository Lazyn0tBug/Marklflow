# Markdown 编辑器总体设计方案 V0.2.10

日期：2026-10-23  
状态：开发设计基线草案；尚未实现或完成技术验证。  
定位：开箱即用、支持公式与图表、具备 HTML 预览与多格式导出的 Markdown 编辑器。

本次修订：承接 V0.2.9，新增大纲导航、编辑器/HTML 双向同步滚动、中心章节强调、视图显隐与编辑/阅读内容最大宽度配置；同步 1.0 前版本规划和验收。显隐按用户确认逐步隐藏，最后一个视图不可隐藏；只更新设计，不修改原型或源码，其余范围不变。

## 1. 产品目标与设计约束

### 1.1 核心目标

用户在 Markdown 编辑器中编写内容，获得语法高亮、实时预览、版式配置、资源管理和文件导出能力。HTML 是展示、预览和视觉输出的共同基础；结构化文档模型用于保持语义，并支撑可编辑 Word、PPTX 等输出。

“依赖少”的准确含义是统一管理开发依赖、消除用户自行准备转换环境的步骤。开发侧优先使用 Bun 安装和运行 npm 生态中的 JavaScript、TypeScript、WASM 和打包工具；发布产物必须包含相应运行资源。用户无需另行安装 Bun、Node、Python、TeX、Graphviz 命令行或办公软件，才能使用已发布的核心功能。

### 1.2 强制原则

1. Markdown 原文是内容的权威来源，不能从展示 DOM 反向猜测恢复原文。
2. 编辑器是核心产品，不能只提供粘贴 Markdown 后转换的表单。
3. 解析、渲染、分页、导出和持久化分离；插件不能直接控制保存逻辑。
4. 所有依赖通过统一包管理和构建流程发布；默认不调用外部转换程序。
5. 开发时可以有多个模块，用户文档默认单文件交付。
6. 无账号、无后端也能完成核心编辑、预览和导出；不自动上传正文。
7. 离线能力按资源清单验证，不能把“配置了 PWA”当成“全部功能可离线”。
8. 原生可编辑、视觉保真、文字可选取是不同能力，导出界面必须准确标注。

### 1.3 首版范围

首版发布包含 Markdown 编辑、高亮、撤销重做、查找替换、文件打开和下载保存、草稿恢复、大纲、阅读预览、A4 分页预览、主题、图片、数学公式、Mermaid、Graphviz、单文件 HTML、浏览器打印 PDF 和基础 DOCX。

后续扩展 EPUB、图片导出、PPTX、桌面文件关联和自动 PDF。首版不加入协同编辑、插件市场、任意脚本执行、AI 服务配置、PDF 反向编辑或 DOCX 往返转换。

现代 HTML/CSS 支持和显式交互内容按第 16 章 H0–H4 分阶段推进；首版先实现已验证的静态能力，不要求一次完成现代特性清单、交互脚本或所有输出适配。后续交互模式不改变普通 Markdown 默认不执行脚本的规则。

## 2. 总体架构

```text
应用界面
  ├─ CodeMirror 编辑器：Markdown、光标、选区、事务历史
  ├─ 大纲 / 资源 / 主题 / 文件操作
  └─ 阅读预览 / A4 预览 / 导出面板
                 │ 编辑事务生成文档修订号
                 ▼
文档会话：Markdown + 元数据 + 主题 + 资源 + 修订号
                 ▼
解析适配器：Markdown → mdast → Document IR
                 ▼
渲染调度：正文 / 数学 / Mermaid / DOT → HTML / MathML / SVG / 资源
  ├─ 解析 Worker / Shiki Worker / Graphviz Worker
  ├─ 区块缓存、修订号检查、视口优先队列
  └─ 临时标记：CSS Custom Highlight API；导出不携带运行时 Range
                 ▼
冻结的 RenderSnapshot：修订号、主题、渲染资源、诊断
  ├─ 阅读布局 → 流式 HTML
  ├─ 分页适配器 → A4 页面 → 打印 PDF
  ├─ HTML 打包 → 单文件阅读 / 可重新导入的 HTML
  └─ 导出协调器
       ├─ IR + 主题 + 渲染资源 → DOCX
       ├─ IR + XHTML + 资源 → EPUB
       ├─ 页面 / 图表 → PNG、SVG
       └─ 幻灯片模型 + 渲染资源 → PPTX

平台适配器：Browser / 后续 Tauri
存储适配器：IndexedDB / 文件下载 / 可选桌面文件系统
```

IR 指内部文档结构，不要求写入本地中间文件。除显式保存或导出外，中间状态保存在内存；大型资源存入 IndexedDB。

核心模块不得导入 React、CodeMirror 或 Tauri。浏览器 DOM 操作集中在渲染适配器和布局层；纯解析、模型迁移、诊断可以独立测试。

## 3. 技术选型

以下选型作为开发默认基线。Bun 优先承担包管理、脚本和开发工具运行，React 19 负责 UI，Vite 继续承担开发服务与生产构建。版本号分为设计基线和工程精确锁定版本：前者如下，后者须在 P0 安装、兼容验证后记录于 package.json、bun.lock 和工具链记录，不能把文档中的版本族当成已验证组合。

| 领域 | 建议 | 用途与边界 |
|---|---|---|
| 语言 | TypeScript 6.0.x 验证基线，严格模式 | 使用 tsc --noEmit 单独类型检查；是保守兼容基线，不声称为最新版本 [S24] |
| 开发运行时 | Bun 1.4.x，P0 锁定具体补丁 | 优先开发、脚本和 CI；Node 仅作具体工具的兼容回退，不作为应用运行依赖 [S21][S23] |
| 包管理 | Bun + bun.lock 文本锁文件 | 使用 bun install --frozen-lockfile 复现；仅维护一份锁文件；单仓库起步 [S22] |
| 构建 | Vite 8.x + @vitejs/plugin-react | 静态部署、代码分割、Worker 和 WASM 资源打包；验证插件、PWA 与 Bun 的兼容组合 [S1][S21] |
| UI | React 19.x + react-dom 19.x，优先验证 19.3.x | 两包对齐版本，使用 createRoot；类型包使用 @types/react 和 @types/react-dom 19.x；不启用 SSR/RSC [S25] |
| 编辑 | CodeMirror 6 | Markdown 高亮、编辑事务、快捷键、选区和语言扩展；先验证中文输入与嵌套代码语言 [S2] |
| 代码展示高亮 | Shiki 4.x 验证基线，优先 JavaScript 正则引擎 | Worker 内复用实例、按需加载语言/主题，输出 token 数据后适配预览和导出；替换 highlight.js [S29][S30] |
| 临时文字标记 | CSS Custom Highlight API | 阅读预览中的搜索、当前源位置与文本诊断；无需新增运行库；不替代 CodeMirror 或语法分析 [S31] |
| Markdown | unified / remark-parse / remark-gfm / remark-math | 建立可扩展语法树；保留源位置，不用正则实现通用解析 [S3] |
| HTML 转换 | remark-rehype 或 IR 到 hast 适配器 | 首版采用 IR 到 hast 的统一出口；remark-rehype 用作生态适配参考，避免两套正文渲染逻辑 [S3] |
| 样式 | Tailwind CSS v4 + 语义化文档 CSS | 编译后发布；应用 UI 保留 OKLCH，文档预览/输出默认 HEX/RGB；两套主题隔离 [S4] |
| 公式 | MathJax 4.x，使用 @mathjax/src 单一核心入口适配 | LaTeX 输入、MathML/SVG 双输出；不同时引入重复的 MathJax 分发包；浏览器资源打包路径须 P0 验证 [S5][S17][S18][S19] |
| Mermaid | mermaid 12.x 验证基线 | 图表转 SVG；异步完成后才允许进入导出快照 [S6] |
| Graphviz | @viz-js/viz | 使用 WASM Graphviz；不安装 dot；首版限定常用布局与 SVG 输出 [S7] |
| 分页 | Paged.js，经可行性验证后接入 | 封装 Paginator；不承诺完整 CSS Paged Media 或直接下载 PDF [S8] |
| Word | docx | 浏览器生成原生 OOXML 和 Blob；不经过 Word/LibreOffice [S9] |
| PPTX | PptxGenJS，后续阶段 | 原生文本/形状/图片；不能自动复现任意 HTML [S10] |
| 资源容器 | fflate + 自定义版本化清单 | 可选项目 ZIP 和 EPUB ZIP；需验证 EPUB 打包约束 |
| 校验 | Zod，包名 zod | 导入配置、插件选项、版本化文档的运行时校验 |
| 安全清理 | DOMPurify + URL/CSS 策略 | HTML/SVG 清理；不能把它视为任意 CSS 或 JS 的沙箱 [S11] |
| 存储 | IndexedDB，使用 idb 薄封装 | 草稿、资源、快照；浏览器数据不等于已下载文件 |
| 离线 | vite-plugin-pwa / Workbox | 资源预缓存与升级；大型 WASM、字体必须进入缓存检查 [S12] |
| 测试 | Vitest + @playwright/test | Vitest 统一单元/集成测试；Playwright 验证真实浏览器；用 bun run test，不混用 Bun 原生测试器 [S26] |
| 后续桌面 | Tauri 2；@tauri-apps/api、plugin-dialog、plugin-fs | 复用 Bun + React 19/Vite 前端；桌面阶段引入 Rust/系统构建工具及受控文件系统适配；本轮不安装 [S33][S34] |

选择 CodeMirror 而非从 textarea 自建编辑器；选择 AST 生态而非从已渲染 HTML 恢复 Word 语义。Graphviz WASM 先采用一个实现，不同时引入多个同类运行时。

高亮分为三个职责：编辑区由 CodeMirror 原生语言机制处理；阅读/A4/导出代码块由 Shiki 处理；预览搜索、当前源位置和文本诊断使用 CSS Custom Highlight API。首版不再引入 highlight.js，也不在 CodeMirror 内叠加第二套全量 Shiki 高亮。

### 3.2 Bun 运行与 Node 兼容边界

Bun 管理 npm 生态依赖，不代表所有依赖都已在 Bun 下验证。Vite CLI 首选显式使用 bun run --bun vite，避免工具 shebang 悄悄转用机器上的 Node。自动化脚本使用 TypeScript + Bun；浏览器核心代码仍只依赖标准 Web API，不把 Bun API 打包进客户端。[S21][S23]

Vitest、Playwright、PWA 构建、MathJax 打包及 Worker/WASM 路径分别做 Bun 冒烟测试。某工具不兼容时，仅该工具在开发/CI 兼容任务中使用其支持的固定 Node LTS；记录版本、原因与回退命令，其他流程保持 Bun。不能无证据宣称工程完全不需要 Node，也不能以全局切回 npm 处理局部问题。

后续 Tauri 阶段增加 @tauri-apps/cli、Rust/Cargo 及各操作系统构建前置条件；Bun 继续管理前端依赖与命令，但不能替代原生构建工具。只允许经过审查的必要安装脚本，不对所有依赖开放执行。Web 首版不安装桌面依赖，用户端不要求安装 Bun、Rust 或开发工具；系统 WebView 前置条件需纳入发行包准备与验收。

### 3.3 版本、配置与复现

- package.json 设置 type: "module"，使用 scripts 和 packageManager 字段；packageManager 记录实际验证后的完整 bun@版本。提交 bun.lock，初建项目不生成 package-lock.json/yarn.lock/pnpm-lock.yaml。
- React/react-dom 精确版本对齐；@types/react/@types/react-dom 保持 19 系列并检查 peerDependencies。先采用标准 React 插件，React Compiler 不作为首版必需项。
- Bun 和 CI 使用同一补丁版本；新增直接依赖用 bun add --exact，开发依赖用 bun add --dev --exact。传递依赖由锁文件固定，升级走单独变更。
- tsconfig 显式设置 strict、noEmit、jsx: react-jsx、moduleResolution: bundler，明确 target、lib 与 rootDir；浏览器/Worker、构建脚本及测试分开 types。不要让 Bun 全局类型泄漏到浏览器代码。
- 浏览器使用 DOM/WebWorker 标准类型；脚本安装 @types/bun 并设置 types: ["bun"]；React 应用显式包含所需 React/Vite 类型，避免依赖自动发现。Node 类型仅用于实际引用 Node API 的兼容工具；后续 Tauri 不默认加入 Node 主进程，不额外直接安装 bun-types。[S27]
- 新增 bunfig.toml、vite.config.ts、vitest.config.ts、playwright.config.ts、eslint.config.js 和 Prettier 配置；保持简洁，未使用的配置不占位堆叠。
- P0 输出 docs/contracts/toolchain.md，记录精确版本、运行时、测试浏览器、扩展/字体清单、兼容回退、校验日期与验证结果。任何设计版本基线都不能代替这一份实测记录。

## 4. 编辑器设计

### 4.1 视图与基本操作

提供编辑、双栏、阅读、A4 四种视图。多栏可调整宽度；桌面与手机均保持所有开启视图同时显示，不按断点自动隐藏，空间不足时在工作台内部横向滚动。编辑器和文档主题分别配置字体、字号、行距及明暗外观。

主工作台采用“左侧导航 + 中间编辑 + 右侧渲染/导出”三栏；本节的双栏指中间与右侧两块内容区。详细视觉及交互见第 4.5 节。

首版编辑能力：

- Markdown 标题、强调、引用、列表、链接、图片、表格、代码围栏、公式围栏高亮。
- 围栏代码块按已安装语言包高亮；未知语言仍保持代码文本可编辑。
- 行号、自动缩进、括号配对、列表续写、折叠、快捷键和软换行。
- 撤销/重做、查找/替换、选区统计、文档统计、跳到行与标题大纲。
- 常用格式按钮通过编辑事务插入或修改 Markdown，保留光标、选区和撤销语义。
- 图片粘贴/拖入、插入公式/图表模板、手动分页指令。
- 中文 IME 输入期间避免强制格式化、重建编辑器或打断组合输入。

### 4.2 状态与更新

CodeMirror 持有编辑状态，应用通过增量事务同步 Markdown。普通按键不能触发整份编辑器重建。建议预览防抖 250ms，输入持续时允许更长的后台等待；草稿保存防抖 800ms，并在离开会话前尽力刷新，不能依赖 unload 一定成功。

每次内容、主题或资源变动递增 revision。解析和渲染任务携带 revision；旧结果不得覆盖新结果。切换预览、导出、保存文件均使用明确的文档快照。

首版使用区块级缓存减轻代码、公式与图表重渲染，允许正文在 Worker 中重新解析；不承诺首版完成真正的增量 Markdown 编译器。普通正文更新不得无条件重跑未变化的 Shiki、MathJax 或图表任务。阅读预览优先可见区块，A4 分页使用独立的空闲调度，具体见第 7.5 节。

### 4.3 源码与预览联动

IR 节点保存 sourceRange，预览元素设置 data-node-id。点击大纲或预览区块可定位到源位置。滚动同步以区块锚点为主，不用全文滚动比例猜测位置；程序性滚动加来源标记避免循环。

源位置的 offset 统一采用 JavaScript UTF-16 代码单元，line 从 1 起，column 从 1 起；必须验证中文、emoji 和换行符映射。节点 ID 在一次修订内唯一，重解析时尽力匹配旧区块；不能承诺任意重写后 ID 永久稳定。

语法错误定位到源区块，保留原文可编辑。单个图表失败只影响该区块，不阻止其他内容阅读。

#### 4.3.1 同步滚动与章节状态

同步联动属于 1.0 必需功能，默认开启；提供“同步滚动”开关，关闭只暂停编辑器与 HTML 自动跟随，大纲点击定位仍可用。此处 HTML 指应用内阅读/A4 预览，独立导出 HTML 不连接编辑器会话。

| 用户动作 | 编辑器 | HTML 预览 | 大纲 |
|---|---|---|---|
| 选中大纲标题（鼠标或键盘） | 对应标题滚至内容视口顶部，扣除固定工具栏遮挡 | 同一标题居顶 | 选中标题强调并保持可见 |
| 编辑器滚动 | 保持用户操作，不反向纠正 | 跟随编辑器视口中心对应源区块及块内位置 | 强调中心位置所属章节，必要时滚动使条目可见 |
| HTML 预览滚动 | 跟随预览中心对应源区块及块内位置 | 保持用户操作，不反向纠正 | 按预览中心对应章节强调 |

编辑器中央指可用内容视口的垂直中心，不是光标位置。章节采用中心源位置之前最近标题，按标题层级确定最深所属章节；文首无标题区域不假指向第一章。无标题文档显示既有空大纲状态。重复标题使用节点身份/源位置区分。点击大纲后的显式选中与滚动派生的当前章节分开存储：定位完成时显示选中项，下一次用户主动滚动再按中心更新，避免长章节居顶后立即被中心判定覆盖。

大纲当前章节用稳定行高的加粗、背景/边框和 aria-current 表达，不以放大字号改变列表高度；焦点、选中和当前章节可辨别，不仅依赖颜色。自动揭示条目不抢键盘焦点；用户单纯滚动大纲列表浏览其他标题不触发文档跳转，只有激活标题才导航。

#### 4.3.2 锚点映射、反馈与异步边界

以当前修订 IR 的 sourceRange/data-node-id 建立双向区块映射；编辑器通过实际可见行/坐标定位中心，预览通过实际区块边界定位中心。优先区块锚点，再用局部文本/子锚点或块内相对进度对齐，不用全文滚动百分比。长代码、列表、表格、图片、公式、图表和空白也须有源范围和可定位容器；非文本块仅保证区块及块内近似位置，不承诺源码每行与渲染像素一一对应。折叠源码定位需展开必要范围；文尾无法居顶时在合法最大滚动位置定位，不添加伪正文改变文档。

同步协调器记录 documentId、revision、origin、导航事务和用户意图序号。程序滚动事件不得成为反向同步源；新的真实用户操作接管，连续事件每帧合并，不对每个 scroll 启动平滑动画。程序反馈在事务完成/被接管时释放，不能仅靠固定时长锁或 event.isTrusted 区分滚动来源。

HTML 落后于当前编辑修订时不得把旧位置误当新映射：提示更新中，保留最新导航锚点，待对应修订就绪后应用；必要时在新 IR 匹配最近有效源区块，不能用旧节点 ID 猜测。视口外目标优先生成并挂载后测量。图片/字体/公式高度变化、缩放、软换行、分隔线或最大宽度改变后，按最近语义锚点重建测量并校正，用户接管后不回拉。

A4 采用分页区块到源节点及分片位置映射，中心落在页边距/页间空白时选最近内容；分页未就绪保留导航意图。编辑器→A4 同步不在滚动时触发重新分页。隐藏视图不执行滚动/尺寸测量，只保留最新语义目标；重新显示且布局就绪后恢复。切换文档时隔离队列，避免旧文档导航影响当前文档。

### 4.4 高亮、搜索与临时标记

编辑区的 Markdown/围栏语言高亮、搜索选区及诊断使用 CodeMirror 自身机制，统一跟随编辑事务。CSS Custom Highlight API 仅用于应用管理的阅读/A4 预览 DOM，不接管编辑器虚拟视口和内部文本节点。

预览建立按区块索引的 UTF-16 文本位置映射，搜索命中和源定位转换为 Range 后按语义分组注册，例如搜索命中、当前命中、当前源区块及诊断范围。注册名包含会话/视图标识；清理时仅删除本视图拥有的项，不调用 CSS.highlights.clear() 影响其他视图。错误图表或非文本区块使用容器样式提示，不强行映射为文本 Range。

DOM 替换、分页、区块卸载后废弃旧 Range，依据最新区块重新映射；不得假定浏览器的 Range 自动调整能维持业务上的正确位置。重叠标记明确优先级。文档切换和视图销毁时释放注册项及引用。临时标记默认不保存、不打印、不导出；需要永久强调时写入 Markdown 语义或显式导出标记，由导出器生成持久化样式。

### 4.5 三栏 UI 与交互设计

#### 4.5.1 工作台结构

使用开发工具类 Operate 界面：紧凑、清楚、低装饰，信息围绕当前文档组织。顶栏容纳工作区、全局主题、保存与导出；下方三栏分别滚动；底部状态栏展示文件/草稿状态、文本信息和可展开诊断。产品名称未定，原型使用“Markdown 工作台”作为描述性标题。

```text
顶栏：工作台 / 工作区                           主题  保存  导出
┌────────────────┬──────────────────────┬──────────────────────┐
│ 文件 / 大纲     │ 文档标签 / 编辑工具    │ 阅读 / A4 / 预览设置    │
│ 本地目录树      │ Markdown 源码编辑器    │ 渲染状态与修订         │
│ 文档列表        │ 行号、语法高亮、选区   │ 文档阅读 / 分页预览    │
│ 当前文档大纲    │ 独立滚动              │ 导出设置按需展开       │
└────────────────┴──────────────────────┴──────────────────────┘
状态栏：文件/草稿状态 · 字符 · 编码 · 当前行列 · 诊断入口
```

桌面默认左栏约 238px，中栏约占视口 40%，右栏填充剩余空间。1280px 左栏可缩至约 210px；导航建议范围 190–340px，编辑/预览内容区最小约 320px。分隔线提供鼠标拖动、键盘方向键微调、清楚焦点态；正式实现保存布局偏好并提供重置。不能拖动到内容不可操作的宽度。

#### 4.5.2 左栏：文件访问与大纲

- 文件和大纲作为一级切换；文件视图下可在下方显示当前文档的简化大纲，两者共享源位置索引。
- 后续 Tauri 文件区支持授权打开目录、按需展开目录树、文件筛选与路径显示；仅监听已打开工作区，外部修改提供重载/保留的冲突处理。文件访问、写回与本地导出本轮仅预留入口，不借原型视作已实现。
- Web 默认展示会话文档和导入入口；浏览器文件/目录授权能力采用平台适配和渐进增强，不伪装成可任意访问本地磁盘。关闭权限后明确恢复入口。
- 当前文件有持续选中态，未保存修改有文本状态及标记；切换文档不丢内存内容。正式版关闭/重载未保存文档前提供保存或恢复路径，不仅依赖颜色小点。
- 大纲按标题层级缩进；点击定位源文与预览。长标题截断但可查看完整文本；文档没有标题时提示如何创建标题。

#### 4.5.2a 工作区导入与本地访问

左栏工作区操作包含三个明确入口：“导入工作区”“添加 Markdown 文件”“打开本地目录（Tauri 版）”。导入将用户选择的文档/项目副本加入会话，不自动创建本地目录映射；打开本地目录建立受授权的磁盘关联，两者不能共用同一种“已连接”状态。

Web 首版的工作区导入采用多文档选择，并按既定格式逐步支持工作区/Markdown ZIP、可编辑 HTML 的源载荷导入；项目包读取需要 schema/资源验证。导入前显示数量、重名策略和错误；默认追加保留已有文档及未保存修改，替换整个工作区必须显式选择。相对资源路径依据导入包内索引解析，缺失资源提示，不能自动获得同目录任意文件访问权。

本轮原型支持最多 100 个 .md/.markdown 文件、总计 20 MB 的批量导入；成功后追加到内存工作区，同名自动增加序号。读取失败不部分提交，取消不改变会话；尚不实现 ZIP/HTML 项目载荷和图片资产导入。单文件添加保留为轻量入口。“打开本地目录”禁用并标注 Tauri 待实现，避免请求不属于当前功能的权限。

#### 4.5.2b 保存与导出位置

保存源文与导出派生文件分开：Web 保存当前 Markdown 是下载；后续 Tauri 的“保存”写回已关联源文件，“另存为”建立新关联。HTML/DOCX 等导出只生成独立产物，不改变当前源文关联，也不清除源文未保存修改标志。

导出面板增加“输出位置”：当前为浏览器下载；后续 Tauri 提供保存对话框、选择目标目录/文件名及覆盖确认。先冻结内容并生成字节，再交给平台文件写入器。取消不是失败，不显示成功；无权限、磁盘不足、目标被占用或外部修改失败时保留会话，提供重新选择位置和重试。导出设置可记忆每个工作区的上次位置，但需重新检查权限。

原型展示“选择本地导出位置（Tauri）”不可用入口；不会写盘或伪造本地绝对路径，现有 HTML/MD 继续下载，PDF 仍调用打印对话框。打印 PDF 的目标由系统打印流程选择，不能把普通文件目标选项当成自动 PDF 实现。

#### 4.5.3 中栏：编辑优先

文档标签显示文件名和修改态；下方显示路径及少量常用操作：加粗、代码、查找。高级命令通过菜单/命令面板逐步开放，不将全套格式按钮挤在首屏。

正式编辑器使用 CodeMirror 6，保持行号、插入点、选区、软换行设置、搜索/替换及既定语言高亮。编辑器内的主题和字号独立于交付文档样式；无需为了预览主题重建编辑器。专注模式隐藏导航与预览，并提供固定可达的退出入口。

原型使用轻量文本编辑及覆盖层示意高亮，不代表 CodeMirror 或 Shiki 已接入；正文可以修改、切换内存文件和下载 .md，但不承诺原型具备完整正式语法兼容与撤销栈行为。

#### 4.5.4 右栏：渲染、排版和导出

阅读/A4 为同一文档的两种视图。阅读使用流式文档布局；A4 展示独立纸张、页边距、页码及分页诊断。右栏保留预览设置与打印入口；导出面板由顶栏“导出文档”打开，在右栏内按需占用空间，不额外形成常驻第四栏。

导出面板显示格式、文件名、内容修订、能力或降级提示及执行动作。浏览器打印路径准确标为“打印 / 保存为 PDF”；Word 公式不可原生编辑等差异在选择格式时出现。等待、准备完成、失败和重试状态在同一位置显示，禁止未完成渲染时展示成功导出。

面板尽量非模态；Esc 关闭且返回触发按钮焦点，键盘可访问所有选项。正式版超窄屏可使用全宽面板；不同时压缩编辑区、文档区和导出表单到无法阅读。

原型的阅读预览为简化 Markdown，A4 标为“布局示意 / 未分页”，LaTeX 显示源码；Word 禁用并说明尚未接入。HTML 下载标为“轻量原型预览”，不能作为正式 HTML/源载荷导出验收。可打印右侧内容，但不声明完成正式引擎分页或系统 A4 打印验收。

#### 4.5.5 视觉系统和主题

用户确认深浅主题均可切换。工具外壳提供深/浅两套中性灰 token，单一低饱和青绿色作为主操作、焦点和当前选中强调。文档默认独立浅色纸张，不随工具外壳变暗而改变正式打印配色。

UI 使用现代系统无衬线字体及可靠中文回退；代码使用 Cascadia Code/Consolas 等宽字体。字号以紧凑 rem 基准和可调设置为主，文档正文与内容宽度适度流式；界面不通过整体缩放适配屏幕。使用 1px 分隔、较小控件圆角、统一 SVG 图标，避免营销页卡片、发光、渐变和装饰性大标题。

基础状态至少包含 hover、focus、selected、disabled、loading、error、empty；正文及主要说明对比度目标不低于 4.5:1，非文本控件和焦点轮廓清楚。状态不能只靠颜色传达。轻量反馈不遮挡编辑区，无装饰性入场动画，尊重 reduced-motion。

#### 4.5.6 响应式与平台状态

所有开启的导航/编辑/HTML 视图保持并排同时显示，显隐只由用户显式操作控制，不按断点、设备类型或横竖屏自动隐藏，也不自动改成单视图页签。可用宽度不足以维持面板可操作宽度时，仅工作台内容区横向滚动；保留各视图内部的纵向滚动、当前内容、选区及预览状态。顶栏和配置弹窗入口保持可达，不随工作台横向滚动移走。顶栏优先保留主题、保存和导出，路径等次要内容收起。对长文件名、长代码和导出文件名使用局部滚动或截断提示，不能造成全页横向溢出。

正式界面必须区分：已写回本地文件、已保存浏览器草稿、已下载文件、仅内存会话、预览更新中、当前预览落后于源文、导出冻结快照和失败诊断。原型始终显示内存会话边界，不用虚构“自动保存成功”替代实际持久化。

#### 4.5.6a 三视图显隐与内容宽度
视图、同步滚动及内容最大宽度配置默认隐藏，通过始终可达的顶栏“视图”按钮打开“视图与布局”弹出窗口，不使用常驻配置条，也不挤占或推移工作台内容区域。启动/重载不自动打开配置窗口；已保存的配置值仍按原规则恢复。弹窗包含三视图显隐、同步开关、两个最大宽度、应用/重置及校验反馈；关闭只收起窗口，不撤销已应用的配置，未应用的宽度输入不改变实际布局。该规则只涉及工作台布局配置，不改变既有导出面板等其他入口。

优先使用原生 dialog/showModal 或具备等效焦点管理的对话框；打开后焦点进入弹窗，Tab/Shift+Tab 在窗口内导航，Esc、关闭按钮或点击遮罩可关闭，关闭后焦点回到顶栏“视图”。弹窗内部点击不误关闭；手机适配可用宽高，内容超高时内部滚动。弹窗打开期间工作台不接受误操作，打印/导出不包含配置窗口。即使只剩一个视图，入口仍可达，可在弹窗中恢复其他视图；最后一个视图不可隐藏的规则保持。

提供始终可达的“视图”控制，独立切换大纲/左侧导航、编辑器和 HTML 预览；文件/大纲共用左侧宿主时，隐藏该宿主同时收起文件区，不扩建第四栏。顶栏保留恢复入口，不随任一内容视图隐藏。隐藏不关闭文档、不丢编辑状态/撤销/草稿；重新打开按最新语义锚点恢复。隐藏焦点所在视图时将焦点移至控制按钮或可见内容，禁止焦点落入不可见控件。

| 组合 | 布局 |
|---|---|
| 大纲 + 编辑器 + HTML | 默认三栏 |
| 编辑器 + HTML | 隐藏大纲，双栏 |
| 大纲 + 编辑器 | 隐藏 HTML，双栏 |
| 大纲 + HTML | 隐藏编辑器，双栏 |
| 编辑器 | 独立编辑 |
| HTML | 独立阅读 |
| 大纲 | 独立导航，选中章节先更新定位目标；恢复编辑器/HTML 时应用 |

三个视图独立逐步隐藏，允许全部七种非空组合；不允许全部隐藏。只剩一个视图时，其隐藏操作禁用并说明“至少保留一个视图”，其他视图的显示入口仍可达。隐藏任一视图不自动显示或切换到另一个。移动端同样保留开启的多视图；不足宽度通过工作台内部横向滚动访问，不以自动抽屉、页签或响应式收起替代用户的显隐选择。窗口缩放不改写已保存显隐偏好。显隐、分隔比例、两个最大宽度和同步开关作为本地应用偏好保存，可重置，不写入 Markdown 或交付文档。

已确认的逐步操作：三栏→隐藏大纲→编辑器+HTML→隐藏编辑器→仅 HTML，此时 HTML 不可再隐藏；三栏→隐藏 HTML→大纲+编辑器→隐藏大纲→仅编辑器，此时编辑器不可再隐藏。仅大纲时同样保留该视图，仍可通过顶栏恢复内容视图。

编辑器与 HTML 阅读内容区的 max-width 分别默认 1024 CSS px，可独立设置为正整数 px 或“不限制”；设置错误显示校验并保留原值。内容实际宽度为可用面板宽度和最大宽度较小值，扣除内边距/编辑器行号沟槽，宽屏居中；不是面板最大宽度，不对整页缩放，也不把窄面板撑成 1024px。宽代码/表格按既有局部滚动或软换行规则处理。

此宽度仅控制工作台编辑/阅读视图，不覆盖文档主题行长、A4 纸张/页边距或独立导出 HTML 的响应式主题设置。改变宽度后更新坐标和测量，保持当前语义位置；A4 按物理纸张显示/排版，不用该值重定义纸宽。

## 5. 文档结构与文件格式

### 5.1 文档的权威数据

```ts
interface DocumentRecord {
  schemaVersion: 1;
  id: string;
  revision: number;
  markdown: string;
  meta: { title: string; author?: string; createdAt: string; updatedAt: string };
  theme: ThemeSpec;
  assets: AssetRef[];
  options: { syntaxProfile: "commonmark-gfm-v1"; pluginOptions: Record<string, unknown> };
}
interface AssetRef {
  id: string;             // a_ + SHA-256；内容寻址
  sha256: string;
  mime: string;
  byteLength: number;
  originalName?: string;
}
interface AssetStore {
  get(id: string): Promise<Blob>;
  put(blob: Blob, name?: string): Promise<AssetRef>;
}
```

ThemeSpec 为结构化主题：颜色 token、中文/西文字体、字号、间距、表格、代码、图片、封面、目录与纸张设置。所有公开字段均有 schema、默认值和范围限制；初期不允许导入可执行主题。高级 CSS、字体资产、所需浏览器能力及阅读/打印样式按第 16 章扩展；不能用初期主题字段范围限制全部现代 HTML 阅读能力。

### 5.2 内部文档模型 Document IR

区块包含 heading、paragraph、list、blockquote、table、code、math、diagram、image、pageBreak、htmlFragment；行内包含 text、emphasis、strong、delete、inlineCode、link、inlineMath、image。表格需保留表头、对齐和单元格结构，不把表格存成一段 HTML。

每个节点具备 id、type、sourceRange；标题具备 level 和锚点，图片具备 assetId、alt、尺寸与对齐，图表具备 language、source、options，公式保留 LaTeX 源。可选扩展通过具名、带版本的命名空间存放。

公式节点固定使用 syntax: "latex"，同时保存 display、sourceRange 和可选的标签/引用信息；不增加 Typst 输入语法。文档公式配置包含 engine: "mathjax"、viewMode: "mathml" | "svg"、允许的扩展清单和显式宏配置。配置持久化到文档，恢复时验证扩展与宏是否可用；引擎版本写入生成器和缓存元数据，不要求文档固定旧运行时。

IR、HTML、分页和图表渲染结果都是派生数据，不与 Markdown 同时作为可修改正文。导入时先验证源数据再重建 IR；缓存可以删除重建。

### 5.3 Markdown 兼容策略

基础采用 CommonMark + GFM，附加公式、mermaid / dot 围栏、显式分页。扩展属性采用单一、可文档化的语法，例如图表围栏后的属性；实现前锁定正式语法及样例，不同时支持多种歧义写法。

YAML front matter 后续可通过显式启用支持，导入时明确元数据优先级。首版文档设置保存在文档容器，普通 .md 不自动写入用户未要求的配置块。

不支持的代码围栏原样作为代码显示；未知插件区块保留源文并给出诊断。普通 Markdown 中的原始 HTML 首版仅允许清理后的语义标签，不执行用户脚本，不支持 MDX/JSX。后续现代 HTML/CSS 内容块与显式交互块使用独立模式、能力声明和隔离宿主，不因首版标签策略而永久关闭现代特性；具体见第 16 章。

### 5.4 用户可见文件

| 文件 | 内容 | 用途与保证 |
|---|---|---|
| .md | Markdown 原文 | 与通用工具交换；单独下载不保证携带图片和主题 |
| Markdown ZIP | .md + 相对路径资源 | 可迁移、可在其他编辑器打开；转换资源引用时不修改会话原文 |
| 阅读 HTML | 已渲染正文、原生 MathML 或 SVG、内嵌 CSS/图片、打印脚本 | 双击即可阅读和打印；不包含源编辑数据 |
| 可编辑文档 HTML | 阅读 HTML + 嵌入的版本化源数据和资源 | 单文件保存；导入工具后可继续编辑；不在每份文档中嵌入整个编辑器 |
| 项目 ZIP，可选 | manifest.json、document.md、theme.json、assets/ | 大文档备份和开发调试；不是默认强制格式 |

可编辑 HTML 默认明确标注“包含 Markdown 源内容和配置”；用户选择阅读 HTML 时去除源数据与历史。两者均不包含编辑历史、凭证或浏览器内部状态，历史仅在用户选择备份时包含。

### 5.5 HTML 源数据封装

将文档 JSON 和资源字节封装为规范化载荷，以 UTF-8 JSON 的 Base64 文本嵌入固定 ID 的非执行 script 数据块；包含 schemaVersion、载荷哈希与生成器版本。Base64 增加体积，不是加密；哈希用于损坏检测，不证明可信来源。

导入时用惰性的 DOMParser 读取指定数据块，绝不把导入 HTML 的 script 插入应用执行。校验大小、哈希、schema、资源类型后恢复。对不含本工具载荷的普通 HTML，首版提示不支持恢复 Markdown，不能默默声称无损恢复。

单文件中图片可使用 data URL；正文 SVG 统一做 ID 命名空间处理，避免重复图表的 clipPath、marker、字体引用冲突。导出内容不得残留 blob:、临时文件路径或外部字体依赖。大文档允许资源在展示与载荷中重复，先保证可恢复，再评估去重优化。

## 6. 插件机制

### 6.1 插件类别

| 类别 | 负责内容 | 首批实例 |
|---|---|---|
| 语法插件 | 解析扩展、规范化 IR | 数学、图表围栏、分页指令 |
| 编辑扩展 | CodeMirror 语言、命令、补全与诊断 | DOT 高亮、图表模板 |
| 渲染插件 | 将特定 IR 节点渲染为可复用资源 | Shiki、MathJax、Mermaid、Graphviz |
| 导出插件 | 消费 IR、主题、资源和快照生成文件 | HTML、DOCX、EPUB |
| 分页/平台适配器 | 页面布局、文件保存与平台能力 | Paged.js、Browser、Tauri |

首版插件为仓库内受信任代码，通过注册表在构建时注册、运行时动态 import。禁用远程 JS 插件和文档内嵌插件。插件机制的目的首先是隔离变化，而非建立市场。

### 6.2 最小接口契约

以下为建议接口骨架，开发第一阶段需落实为可编译类型与 conformance 测试。

```ts
type Format = "html" | "docx" | "epub" | "png" | "svg" | "pptx" | "pdf";
interface PluginManifest {
  id: string;
  version: string;
  apiVersion: 1;
  kind: "syntax" | "editor" | "renderer" | "exporter";
  requires: string[];        // 插件依赖，注册时检测缺失和循环
  offline: boolean;
  resources: string[];       // 构建资源 ID，生成离线清单
}
interface Diagnostic {
  code: string;
  severity: "info" | "warning" | "error";
  message: string;
  nodeId?: string;
}
interface RenderContext {

  signal: AbortSignal;

}
interface RenderArtifact {
  nodeId: string;
  codeHighlight?: CodeHighlightArtifact; // 可序列化的代码 token 与样式

  svgAssetId?: string;
  pngAssetId?: string;
  htmlFragment?: string;
  widthPx: number;
  heightPx: number;
  baselinePx?: number;     // 行内公式实际布局基线指标

type ExportResult =

```

IRNode、ThemeSpec、ExportSnapshot 定义在核心模型模块。浏览器打印返回 print-request，不能伪装成已经生成 PDF 文件。插件返回的 HTML/SVG 在平台层清理后使用，不能通过接口直接获得任意应用 DOM 或文件系统权限。

代码高亮结果采用独立 CodeHighlightArtifact：包含源哈希、规范化语言、引擎/语法/主题版本、UTF-16 token 起止位置和样式 ID；样式表保存颜色、粗斜体/下划线等信息。token 范围不得越界，原始换行和空白保持不变；多个主题的结果使用独立缓存键。正文 Markdown/代码原文仍是权威数据，token 只作为派生缓存，不持久化浏览器 Range。

Shiki 适配器用公开 token API 建立上述结构；预览和 HTML 使用文本节点与 span/CSS，DOCX/PPTX 导出器按格式能力映射到文字片段和颜色。禁止只保存高亮 HTML，再由 Word 导出器反向猜测 token。CodeHighlightArtifact 的具体类型在 P0 固化并加入插件一致性测试。

### 6.3 生命周期、任务与缓存

注册 → 校验 API 版本与依赖 → 按需加载 → 渲染/导出 → 缓存 → 销毁。重任务设可配置超时；Worker 可通过终止实现硬取消，主线程 DOM 渲染只能协作取消，仍需修订号检查拒收过期结果。

缓存键包含节点源哈希、插件版本、选项、主题、字体配置和相关资源哈希。插件升级或主题变化必须失效相关缓存。按总字节数限制缓存，使用 LRU 淘汰。

公式缓存分为转换缓存和布局缓存。转换缓存包含 LaTeX 源、display、MathJax/扩展版本、宏配置及必要的编号上下文；布局缓存另包含输出模式、主题、字体、字号和容器宽度。编号或宏上下文变化时重算受影响公式，不能把同源公式无条件复用到不同编号位置。MathML 字符串与 SVG 资源分别缓存，只按目标模式生成必要结果，不在每次按键同时生成全部表示。

Markdown 解析与 IR 构建、Shiki token 化、Graphviz 分别使用有界 Worker 任务；MathJax、Mermaid 首版按实际 DOM 需求执行，不强行塞入 Worker。Worker 不是安全沙箱，不允许据此运行不可信第三以1.0的最小可用验证为目标，制定版本规划, 结束在0.9版, 0.9到1.0为审查验证过程
方插件。

任务协议统一携带 taskId、documentId、revision、nodeId（区块任务）、inputHash、configHash 和结果诊断；主线程拒收已过期结果。每个 Worker 首版按串行任务队列执行，不为每个区块新建 Worker。取消消息只能合作取消；同步长任务无法响应取消时可终止并重建 Worker，随后重新准备语言/引擎状态。Worker 崩溃时仅使受影响任务失败并提供重试，不无限重复执行同一失败输入。

跨线程只传可序列化 IR、token、字符串及必要字节，不传 DOM/Range/React 对象。大字节资源使用可转移对象时明确所有权；记录克隆/传输成本，避免每次按键反复发送全部图片和主题。Bun 负责构建和脚本，客户端使用标准浏览器 Worker；不混用 Bun Worker API。

### 6.4 格式能力矩阵

能力注册包括原生语义、矢量、栅格、纯文本回退、不可支持。导出前针对实际内容产生诊断，而不是只展示一张固定宣传表。

例如，公式导出 Word 首版为图片，应提示公式不可原生编辑；未知 HTML 导出 Word 时允许安全文本回退并提示，禁止静默丢弃正文。严重错误阻断导出，可接受降级需由用户在导出面板选择后执行。

## 7. 渲染、分页与主题

### 7.1 渲染就绪屏障

导出任务冻结文档修订号和设置，依次等待解析、资源解析、公式/图表、图片 decode、document.fonts.ready、布局和分页结束。等待字体完成后还要检查目标字体是否实际可用；超时或缺失产生诊断。

状态为 idle → parsing → rendering → layout → paginating → ready / failed / cancelled。导出基于冻结快照；编辑器可以继续编辑，但结果明确属于旧修订，不混入新内容。

### 7.2 两种布局

阅读布局使用语义化 HTML、Grid/Flex、clamp()、舒适行长与手机适配。A4 布局使用物理尺寸、页边距和分页规则，不通过缩小整页实现手机阅读。

应用界面颜色保留 OKLCH token；Markdown 文档主题、阅读/A4 预览及独立输出 HTML 默认采用 HEX/RGB（含所需透明度），不继承应用 OKLCH 变量。Mermaid、Shiki 等插件已有 HEX/RGB 表达按其有效值保留，不强制转为 OKLCH 再转回。Word 等非 CSS 格式按目标映射颜色和透明度，不为统一应用色彩体系增加往返转换。Tailwind 主要服务应用 UI，文档排版使用稳定的 .doc-* 类和独立 CSS 变量，不允许 Markdown 文本任意生成 Tailwind 类名。

### 7.3 分页规则

- 标题避免单独留在页尾，段落设置孤行/寡行控制；实际支持以浏览器验证为准。
- 普通图片、公式、图表尽量整块；超过页面可用高度时按规则缩放或报告超高，不无限重排。
- 长表格允许跨页，重复表头；超高单行要有明确错误或专门拆分策略。
- 代码块允许按行分页；每片保留背景与必要的续页标识。
- 手动分页具有高于自动规则的优先级；防止生成连续空白页。
- 封面、目录、页眉页脚和页码作为页面布局能力实现，首版目录仅含标题与链接；页码目录待分页验证后启用。

Paged.js 通过适配器接入，先验证长表格、代码、中文、SVG、显式分页和目录。若验证不通过，首版缩减复杂页面能力并记录，不在未评估时自研完整排版引擎。Vivliostyle 可作为后续替代评估，不同时引入两套分页引擎。

### 7.4 公式引擎与显示策略

**选型结论：MathJax 为唯一公式主引擎，输入使用 LaTeX 数学语法。** 首版不引入 Typst 或 KaTeX，也不通过引擎切换来补救解析失败。支持度与正确显示优先于包体或单次转换速度；效率通过增量更新、缓存和调度优化。

支持目标是大多数常见及复杂数学公式无需改写，覆盖分式、根式、上下标、大型算符、定界符、矩阵、分段、多行对齐、AMS 环境、编号/引用、字体变体及自定义宏。根据样例配置 ams、mathtools、newcommand、configmacros 等扩展；化学、物理等领域扩展通过显式配置启用并测试冲突，不把所有扩展无差别加载。MathJax 是 LaTeX 数学语法的实现，不承诺任意 TeX 程序、完整文档或任意宏包兼容。[S17][S18]

显示采用文档级模式，不自动猜测单个公式是否应切换格式：

| 模式 | 路径 | 使用与验收原则 |
|---|---|---|
| 原生 MathML | LaTeX → MathJax 解析 → MathML 序列化 → 浏览器布局 | 优先验证方向；验证编号、多行对齐、字体变体、行内基线及打印；不能仅凭输出合法 MathML 判定显示正确 |
| MathJax SVG | LaTeX → MathJax SVG 输出 → 自包含资源 | 优先排版完整性与固定视觉输出；作为复杂公式和正式交付可选模式 |

MathJax 提供 tex2mmlPromise 等转换方法，但原生 MathML 不是 MathJax v4 的内置输出渲染器。其序列化结果与浏览器 MathML Core 在部分表格对齐属性、编号和字体变体上存在差异；适配层需要规范化并测试，不能通过“只支持现代浏览器”跳过这项验证。[S19][S20]

P0 在选定目标浏览器运行同一公式集，对照 MathJax SVG 的排版结果，确定首版文档级默认模式。MathML 为优先方向；若关键样例仍有显示缺口，则默认 SVG，并保留 MathML 模式和转换能力。用户选择的模式作用于阅读、A4 与 HTML；打印前冻结相同模式，不静默改用另一套显示。切换模式必须重新布局及分页。

公式范围由 Markdown 解析器识别，MathJax 只转换公式节点，不对每次更新的全文重复自动扫描。采用 Promise API 并等待全部所需扩展就绪；避免并发任务共享可变编号/宏状态。编号、引用与跨公式宏作为文档级上下文顺序处理，增量失效范围由依赖决定；旧任务结果通过 revision 检查拒收。

宏配置默认显式声明；兼容正文中的定义时应建立依赖或扩大重算范围，不在多个文档间共享可变宏。所有允许的扩展、字体和数据资源随包发布，不在输入中临时从公网获取；异步按需加载仍必须命中本地发行资源。错误回报关联 sourceRange，保留原文；界面不以渲染为普通文本掩盖公式错误。

公式原文始终可恢复。MathML 输出不等于任意 CAS 可理解的代数语义，也不等于 Word 原生可编辑公式。SVG 字形可能为路径，正文可选取的要求不扩展为“所有 SVG 公式字符均可直接选取”；复制 LaTeX/MathML 应作为独立能力实现。

上述要求和第 7.5 节保留为既有首版基线；公式级缓存及调度增强另见第 7.7 节，全部安排在首版发行后。复杂 MathML 适配不纳入初版实施；若原生模式未通过关键样例，则采用 SVG 默认模式，不以新增优化阻塞首版。

### 7.5 Worker、区块缓存、视口与 A4 调度

**首版执行路径：** 输入即时响应 → 最新修订解析 → 普通正文更新 → 可见区块重渲染 → 预读区块 → 空闲任务。显式导出另走冻结快照和完整就绪屏障，不被视口懒加载截断。

1. **编辑优先。** CodeMirror 的编辑和语言高亮不等待 Worker、Shiki、公式或分页；React 只更新相关面板/区块容器，不逐 token 接管代码 DOM。useDeferredValue 可降低部分 UI 更新优先级，但不是计算卸载机制，也不能替代 Worker。[S32]
2. **解析调度。** 以第 4.2 节 250ms 防抖为初始值，连续输入合并等待中的旧任务；已运行任务的结果按 revision 校验。正文边界可能因围栏、列表、引用或定义改变而扩大，允许重新解析全文，但只对新 IR 中失效的重区块重新渲染。源位置和滚动定位跟随新 IR，不能因为渲染缓存命中就沿用过期 sourceRange。
3. **区块缓存。** 代码缓存按代码源、规范化语言、Shiki/语法/正则引擎版本、主题配置命中；布局指标另含字体、字号和容器宽度。图表/公式按其依赖失效。缓存主要存 token、清理后的 SVG/HTML 和资源引用，不长期保存脱离文档的 DOM 树；LRU 同时约束条目数和字节数。切换主题复用代码源，但不能把旧主题颜色误当新结果。
4. **视口优先。** 阅读视图用 IntersectionObserver 和区块索引划分可见区、预读区、后台区，预读初始范围为上下各约一屏，P0 实测调整。可见任务优先，低优先任务设置最大等待避免饥饿。尚未完成高亮时先显示已转义的原始代码；图表使用稳定占位及明确加载状态。保留锚点和高度估计减少跳动，不以空白内容冒充已完成预览。
5. **按视图执行。** 阅读模式不主动执行全篇 A4 分页；未显示的预览视图不反复布局。A4 视图保留上一份完整页面并提示“排版更新中”，初始在停止输入约 800ms 后发起新分页；持续输入合并任务，并提供立即刷新。一次仅运行一项完整分页；不可取消的旧分页在隔离容器结束后丢弃，不能覆盖新修订页面。
6. **A4 准确性。** 分页前解析完整快照并完成所有影响高度的资源、字体和代码样式；不能只渲染可见区块就计算页码。分页 DOM 与阅读懒加载 DOM 分离；允许优先展示当前页，但不承诺首版具备增量分页。字体、图片尺寸、公式模式、代码换行、页边距或纸张变化都重新触发布局和分页。
7. **导出优先且完整。** 导出使用独立冻结修订，将相关任务提升优先级并完成全文渲染、样式收集及必要分页；用户可继续输入，导出任务不会被最新输入自动取消。队列按任务所有者区分预览与导出，不能清理旧预览时误删导出需要的资源。打印的页面和临时标记状态以冻结快照为准。

Shiki Worker 通过细粒度导入加载受控语言与主题，实例复用；语言别名统一，未知语言显示纯文本并提供诊断。默认使用 JavaScript 正则引擎，若批准语法不兼容再单独验证 Oniguruma，不同时发布两套默认引擎。代码尺寸设可配置阈值，超限可暂缓高亮并由用户触发，但不得截断代码内容；正式导出中的高亮降级需要明确记录。

### 7.6 待验证项，不纳入首版承诺

| 实验 | 验证内容 | 进入正式方案的条件 |
|---|---|---|
| Shiki token + CSS Highlights 负责全部代码着色 | 对比 span 数量、Range 建立/更新、重绘、内存、分页拆分和样式表达能力 | 在固定代码样例中有明确净收益，字体样式和导出有持久化路径；不取代 CodeMirror |
| Shiki 预编译语言包 | 验证所选版本的官方已知问题、语言正确性、启动和包体 | 问题已解决或目标语言逐项通过；不能直接套用性能建议中尚有风险的能力 [S30] |
| 替换 unified 或新增 Tree-sitter | 解析成本、源位置、插件、错误恢复和额外语言资源 | 实测解析为主要瓶颈且收益覆盖迁移成本；未通过前保留现有解析路线 |
| 替换分页引擎或自研增量分页 | 中文、表格、代码、MathML/SVG、目录和导出一致性 | 现有路线存在确认缺口且替代方案通过同一验收集；不并行引入多套默认引擎 |
| content-visibility / 预览虚拟化 | 长文档布局节省、查找/定位、可访问性与高度测量 | 不影响内容发现；分页/打印使用完整可测量 DOM，不复用跳过布局的估计高度 |

现代原生 API 优先，但不把“减少 span”“移入 Worker”或“更换新库”直接等同于整体更快。任何实验都要记录基准环境、结果和失败边界，另行确认后才改变默认实现。

### 7.7 MathJax 生成与渲染优化：后续版本规划

#### 7.7.1 范围与处理链

本节所有新增优化仅规划首版发行后的步骤，初版不实施。保持 MathJax 单一引擎、LaTeX 输入和文档级输出模式；先建立基准，再减少重复转换、无效任务和重复布局，不预设 MathML 比 SVG 更快。

处理链分为资源初始化、TeX 解析及宏/编号处理、MathML/SVG 生成、DOM 挂载和浏览器布局、A4/导出，分别记录耗时及输入延迟。Promise 异步不代表计算已离开主线程。MathJax 4 的标准 Promise 转换/排版 API 自动串行协调；不以 Promise.all 增加同实例吞吐，也不照搬 v3 手动改写 startup.promise 的模式。[S20][S44]

#### 7.7.2 公式级缓存

在既有区块缓存上增加稳定公式节点身份；段落改变但公式源及上下文未变时复用结果，sourceRange 始终取最新 IR。缓存键使用结构化配置和内容哈希，不随意删除 LaTeX 空白或宏文本。

| 层次 | 保存内容 | 关键失效输入 |
|---|---|---|
| 转换缓存 | 序列化 MathML、诊断及上下文元数据 | LaTeX、display、引擎/扩展版本、宏及编号/引用上下文 |
| 输出缓存 | 目标模式 MathML/SVG 成品和资源依赖 | 转换输入、适配器版本、输出设置、数学字体及实际影响生成的尺寸参数 |
| 测量缓存 | 宽高、基线、布局及分页占位 | 输出哈希、字体就绪状态、字号、容器宽度、换行策略和目标视图 |

三层是逻辑责任，不要求每次先生成 MathML 再生成 SVG，亦不要求同时生成全部表示。阅读按选定模式生成，其他表示在导出需要时生成。同键进行中任务合并；相同错误可短期缓存，输入或配置改变后允许重试。LRU 同时限制条目数和字节数；持久缓存另验版本迁移、清理与存储配额。

主题色尽量通过继承和 currentColor 更新，几何结果不因此重建；显式公式颜色、字体或参与生成的配置仍按依赖失效。不得把屏幕宽度下的换行/测量结果直接用于 A4。

#### 7.7.3 增量更新与状态依赖

无跨公式状态的表达式优先精确缓存；显式宏配置属于文档上下文。正文宏定义、自动编号、标签、引用和前向引用采用保守顺序处理，无法证明局部独立时扩大至受影响后缀或全篇公式重算。首个优化版本不承诺完整 TeX 依赖分析。

后续再验证标签/引用索引、依赖图及安全的上下文检查点，不能仅用正则扫描命令名判定依赖。跨文档不共享可变宏和编号状态。视口优先的是输出/挂载，不得跳过建立正确宏、编号和引用所需的语义处理。

#### 7.7.4 任务调度与稳定显示

沿用预览/导出所有者和修订协议，增加公式级合并、优先队列及同键在途去重。预览先处理编辑附近及可见公式，再处理预读区和后台；低优先任务有最大等待。导出持有冻结修订，不因新输入被预览淘汰。

公式输入合并窗口可从 100–200ms 做后续实验；它不是新增首版参数，也不与现有 250ms Markdown 解析防抖简单串联，必须测量端到端延迟。调用 MathJax 前淘汰尚未开始的旧请求；运行中的任务不假定可取消，结果按 revision/inputHash/configHash 校验。转换期间保留上次成功显示并标明更新状态，错误可定位；导出不得用旧结果冒充当前修订。

React 保持稳定公式宿主，不随普通正文更新重建全部公式 DOM。应用转换服务自行管理产物、缓存和可访问性交互；若采用 MathJax 管理排版模式，则遵守 MathItem 注册/清理生命周期，不让两套机制同时管理相同内部节点。手动插入转换产物不会自动获得 MathJax 菜单和公式列表管理，相关能力单独验收。[S20]

应用调度不默认叠加 ui/lazy。官方 lazy 可作对照实验，覆盖宏、编号、前向引用和导出完整性，不能代替文档级语义处理。[S45]

#### 7.7.5 输出、字体与导出复用

MathML 路线分别验证解析、原生显示和打印；数学字体、字体变体、多行对齐及编号涉及的复杂 MathML Core 适配为后续待验证项，不追加到首版实现范围。[S19]

SVG 优先验证 fontCache: local，使单公式字形自包含；global 缓存仅在有实测收益且可完整封装依赖时考虑。缓存 SVG 模板重复挂载时，对内部 ID 及引用分配一致的唯一前缀，覆盖阅读/A4 并存及同公式重复出现。[S46]

引擎、批准扩展及字体数据复用并随发行包离线部署；预热范围按样例决定，不启动即加载所有扩展和字形。使用 Promise API 等待必要动态数据。[S20][S44]

A4/导出补齐冻结快照的全文公式，复用有效转换及输出缓存，再按目标宽度等待字体和资源、测量、分页、封装。测量缓存按目标重新判断；不得遗漏视口外公式，不在每次按键后执行全篇分页。

#### 7.7.6 后续版本步骤与验收

M1–M4 均在首版 P4 发行后按需推进，不是设计文档版本号，不强制与 P5/P6 同步；进入开发时再分配实际发布版本。初版不实施本节新增优化。

| 阶段 | 后续工作 | 退出条件 |
|---|---|---|
| M1 基准与优先优化 | 公式级缓存、在途去重、任务合并、稳定节点和过期结果拒收 | 未改变且独立的公式不重复转换；连续输入最终修订正确；性能收益与内存可解释 |
| M2 增量与输出复用 | 保守失效、宏/编号/引用测试、阅读与 A4/导出复用 | 定义变更及前向引用不显示旧语义；完整导出和目标宽度布局通过 |
| M3 Worker 待验证 | 单个常驻 Worker 优先实验 LaTeX→序列化 MathML；SVG 另验适配器、字体、尺寸和离线加载 | 相比主线程有端到端收益，传输、重启、状态隔离与资源成本可接受后才批准正式接入 |
| M4 复杂适配待验证 | MathML Core 复杂适配、细化依赖/检查点、持久缓存，按需研究其他并行策略 | 同样例正确性、可访问性、打印和性能通过后逐项纳入；可不实施无收益或风险过高的实验 |

Worker 只传可序列化输入、配置及结果，不传 MathJax 内部对象或 DOM。浏览器实际字体排版、挂载、尺寸测量和分页仍在有布局能力的环境完成。不预建 Worker 池，不将 Promise 或 Worker 当作安全沙箱，也不将实验成功等同于全面替换主线程路径。

基准覆盖 100/1000 个公式、重复/不同公式、行内/独立、多行对齐、宏与编号引用、中文文本、长公式、错误输入、连续编辑、切换文档及阅读/A4 并存。分别记录冷/热启动、转换、命中、排队、DOM/布局、输入延迟、内存和完整导出；MathML/SVG 使用相同输入和固定环境对照。转换成功、DOM 仿真不替代真实显示与打印验收。

### 8.1 HTML

默认导出静态正文，不要求收件人再次运行 Mermaid、MathJax 或 Graphviz。公式按文档显示模式输出原生 MathML 或自包含 SVG，图表预先渲染为自包含 SVG，图片内嵌；CSS 编译后内嵌。MathML 模式保留所需数学字体与样式；SVG 模式收集所需样式和字形，消除应用全局字体缓存的隐含依赖。只保留目录跳转、折叠等必要交互及打印按钮，不携带编辑器运行环境。

代码高亮在导出前由 Shiki token 生成 span 和必要 CSS，不要求收件人加载 Shiki 或重建 CSS HighlightRegistry。保留所有代码字符、换行和空白，选择可读的打印配色；临时搜索/定位/诊断标记移除。A4 采用最终代码换行及样式计算分页，不能在分页结束后补加会改变尺寸的高亮样式。

以上为静态 HTML 默认路径。后续交互 HTML 是独立导出配置，可携带经过声明的必要运行代码、资产和状态；离线/单文件能力及打印表示需单独验证。现代 CSS、容器结构和字体如何保留、如何适配其他格式，以第 16 章为准。

提供“打印 / 保存为 A4 PDF”按钮，使用 window.print()；配置 @page 和 @media print，隐藏控件，保留可选择文本。阅读 HTML 在不同机器上重新分页可能受字体影响；精确页码需求以已生成 PDF 为交付。

### 8.2 PDF

Web 版按钮命名为“打印 / 保存为 PDF”，导出流程只确认渲染就绪与已发起打印，不宣称已保存。打印预览使用与 A4 预览相同快照和页面资源；关闭浏览器自带页眉页脚、比例及边距的具体操作以实际支持版本验收。

不以 html2canvas + jsPDF 整页截图作为默认 PDF 路径，避免正文全图化和长页切割问题。若未来需要纯 Web 自动 PDF，必须作为独立技术验证：文本可选、字体嵌入、分页、SVG 与表格均通过后才列入正式能力。

### 8.3 DOCX

标题、段落、列表、链接、表格、分页符映射到原生 Word 对象。字号、行距、缩进、页边距统一换算单位，字体和颜色通过主题适配器输出。Word 自行重新分页，不复制浏览器自动分页为大量硬分页符。

公式首版从同一 LaTeX 节点通过 MathJax 生成 SVG，再转为高分辨率 PNG，保留源文作为替代文本；不依赖截取浏览器 MathML 的屏幕显示，也不要求切换文档显示模式。后续单独实现并验证 OMML，不能将 MathML 字符串直接当成 Word 原生公式。图表优先 SVG + PNG 兼容回退，实际支持以目标阅读器验证为准。代码块使用原生文字和必要的高亮样式。水印、复杂 HTML、跨单元格布局等按能力矩阵处理。

不能把 HTML 改扩展名为 .docx，也不依赖特定软件导入 HTML 的临时兼容机制作为正式路线。

### 8.4 EPUB

选择 EPUB 3 可重排模式；目录以标题结构生成，封面和元数据单独映射。删除应用脚本，外链资源转本地；公式优先验证原生 MathML，按目标阅读器能力显式选择 SVG/图片回退，图表采用经验证的 SVG/图片。ZIP 的 mimetype 项必须按 EPUB 规范优先、无压缩写入，并正确生成 container.xml、OPF、nav 和 spine；正式实现时核对规范及校验器。

### 8.5 PPTX 与图片

PPTX 不直接把任意文章每个 A4 页面当成天然幻灯片。增加独立幻灯片模型、宽高比、显式分隔及少量模板。视觉模式标注整页不可分别编辑；可编辑模式只承诺已支持的对象种类，不承诺 CSS 完整复制。

页面 PNG 首选每页分别导出，禁止无限高长图；图表 SVG 的导出需消除外部字体、CSS 和 foreignObject 依赖，不能消除时使用明确的图片回退。

## 9. 资源、保存与异常恢复

图片导入后按 SHA-256 去重，Markdown 使用 asset:<id> 内部引用，由解析器资源适配层解析；导出普通 Markdown ZIP 时改成相对路径。原始资源与压缩副本区分，覆盖前保留可恢复版本或要求显式操作。

远程图片只能在浏览器 CORS 许可下收集，不能承诺任意网址都可离线内嵌。失败时允许用户导入本地文件；不为解决 CORS 默认引入远程代理。离线导出前列出未收集资源，默认阻断“完整离线”交付。

IndexedDB 保存文档记录、资源与必要历史；文档和资源清单的关联更新尽量使用同一事务。配额不足时保留当前编辑内存，提示下载备份；不能把失败状态显示为“已保存”。资源回收扫描活动文档和保留历史，不能只依据当前正文删图。

区分“草稿已保存到本机浏览器”“已下载文档”“已写回原文件”。Browser 默认通过下载保存，不承诺覆盖原文件；本地文件系统访问与写回留待 Tauri 适配器实现。桌面写回通过临时文件和原子替换完成，并检测外部修改冲突。

历史快照按内容哈希去重、限制数量和总字节数；恢复源文通过一次编辑事务或明确的文档恢复操作执行。刷新后首版允许恢复正文与历史快照，不承诺完整恢复编辑器每次按键撤销栈。

### 9.1 工作区与文件访问契约

WorkspaceRecord 保存 id、显示名称、来源类型（session/imported/tauri-directory）、文档引用、可选资源索引和导出偏好。DocumentBinding 独立保存源文件关联、权限/访问令牌和最近磁盘版本指纹；不把绝对路径注入 Markdown 正文或交付 HTML，不把本机工作区权限随文档传递。

平台 FileAccessAdapter 分别声明 canOpenDirectory、canWriteSource、canChooseExportTarget、canWriteExport。只暴露这些能力的入口；浏览器默认 false，本轮不使用实验性浏览器文件系统访问替代 Tauri 计划。接口提供 importFiles、openWorkspaceDirectory、readBoundDocument、saveSource、chooseExportTarget、writeExport。目录/写盘由 Tauri 平台实现；导出插件仍只返回字节和建议名称，不直接调用原生 API。

保存/写入结果使用 saved/cancelled/failed 三态，saved 必须附带实际成功写入的绑定/目标和修订。慢写入完成时若内存已有新修订，仅确认旧修订已保存，不能清除新修订修改态。源文原子替换、写入冲突和失败恢复按平台验证；导出覆盖现有产物需确认，不覆盖 Markdown 源文件。源保存成功、产物导出成功、浏览器触发下载和系统打印请求分别记录。

本地能力验收留待 Tauri：目录授权/撤销、只读目录、重名、权限不足、取消、磁盘写入失败、外部修改、路径边界和重启恢复；本轮仅验收入口与 Web 导入，不宣称完成上述原生测试。

## 10. 发布方式与依赖边界

### 10.1 默认 Web + PWA

Vite 输出部署至 HTTPS 静态站点。所有核心脚本、Worker、WASM、图标及必要字体随构建发布，不依赖 CDN。运行时插件按需加载，完整离线包通过显式预下载把全部受支持资源加入缓存。

首次联网访问不等于已具备完整离线能力。界面展示“离线资源准备中 / 已就绪 / 不完整”；联网安装完成后断网重启，首次调用之前从未打开的 Graphviz、公式及 DOCX 导出也必须成功。

更新采用版本化资源和原子部署，短期保留旧资源；提示用户保存后更新，避免编辑中强制刷新。清理缓存不得清理文档 IndexedDB。支持旧文档 schema 迁移，旧版本不能读取新格式时明确拒绝修改。

### 10.2 双击运行的离线工具，单独验证

普通 Vite dist ZIP 不是可承诺双击运行的离线应用：file:// 下 ESM、Worker、WASM 加载和 Service Worker 都可能受限。不能让用户解压后再安装 Bun 或 Node 启服务。

如果明确需要不经首次联网、直接双击打开工具，可以提供专门的 standalone.html 构建：脚本内联为兼容形式，WASM 字节内嵌，Worker 使用经验证的 Blob 方式，关闭 Service Worker，并保留文件下载保存。它是独立构建目标，需要完整功能验证；失败时不以普通 dist 包替代。

### 10.3 后续 Tauri 桌面版

根据本轮用户要求，后续桌面路线采用 Tauri 2，当前不实现原生能力。复用 Bun + React 19/Vite 前端，增加 @tauri-apps/api、@tauri-apps/plugin-dialog、@tauri-apps/plugin-fs 与 Rust 端对应插件；CLI、Cargo 和系统前置工具仅在桌面开发阶段准备。[S33][S34]

Tauri 负责已授权目录枚举、文档/资源读取、原文写回、另存为和导出文件写入。文件选择对话框与文件读写权限是不同能力，需同时配置 capability、scope 和受控平台命令。路径校验、工作区边界、符号链接/路径穿越及外部修改冲突在本地适配层处理，不向 Markdown/渲染插件开放任意磁盘权限。

Tauri 使用平台 WebView，不默认附带固定 Chromium，也不沿用 Electron printToPDF。打印路径继续保留；若需要无对话框 PDF 生成，须另行验证平台接口或专用生成适配器，覆盖文本可选、字体、分页、MathML/SVG 和跨系统差异。具备“选择导出路径并写入字节”不代表已具备“自动生成 PDF”。

正式发行需验证目标系统 WebView 准备方式、离线启动、资源加载、签名与权限；用户无需安装 Rust/Bun/Node。Web 首版与原型保持独立可用，原生插件动态加载于 Tauri 适配器，不进入 Web 主入口。

### 10.4 构建与发行命令约定

以下是开发时应实现的项目脚本契约，当前尚无对应工程：

```text
bun install --frozen-lockfile 安装锁定依赖；新建工程先用 bun install 生成并提交锁文件
bun run dev                  启动 Vite；脚本内部使用 bun run --bun vite
bun run check                tsc --noEmit + ESLint；实际检查命令分别执行
bun run format:check         Prettier 只读格式检查
bun run test                 Vitest 单次核心/集成测试；不使用 bun test
bun run test:e2e             Playwright 浏览器交互与导出测试
bun run build                生成 Web/PWA；脚本内部使用 bun run --bun vite build
bun run preview              Vite 本地构建预览，非用户运行前提
bun run verify:offline       检查资源清单并运行断网场景
bun run build:standalone     可选单文件工具构建

```

发布包含版本号、构建提交、依赖锁文件、第三方许可清单、资源清单与校验值。依赖升级通过单独变更验证，不能在发布时自动拉取未锁定的最新依赖。包管理器可统一安装依赖，但浏览器安装包、签名证书等 CI 工具也需显式准备，不把开发机器“碰巧存在”当成项目能力。

test 脚本固定指向 vitest run；bun test 会运行 Bun 自带测试器，不能作为等价替代。[S26] check 脚本通过任务脚本顺序或并行调用检查器并正确传递退出码。CI 先冻结安装，再类型/lint/测试/构建/浏览器/离线验证，保存版本、日志和发行清单。Playwright 浏览器安装、可选 Node 回退和桌面二进制下载必须显式出现在 CI 配置。

## 11. 安全与兼容设计

- 不执行 Markdown 中的 script、事件属性、javascript: URL、嵌入式对象或不可信插件。
- 外部 HTML/SVG 使用允许列表清理；资源协议和外链单独校验，DOMPurify 不能替代 CSS 策略。
- 图表使用受控配置，用户内容不能开放回调、任意链接执行或覆盖安全级别。
- 导入设置文件大小、图片像素、图表复杂度、ZIP 展开数量和总字节限制，防止编辑器卡死或内存耗尽。
- 应用主题、用户正文和导入 HTML 的样式隔离；分页/打印 iframe 只运行应用生成的可信脚本。
- 字体使用系统回退；可选内嵌开源授权字体。中文字体包较大，单独计入离线准备与发行体积；没有嵌入字体时不能承诺跨设备像素一致。
- 主验收浏览器为发布时锁定的桌面 Chrome/Edge；Firefox、Safari 和移动端建立单独兼容表。支持版本同时受 Tailwind、分页引擎等约束，不能只依据 Vite 的最低版本下结论。

### 12.1 规范效力与编码约束

本章是完整产品开发的强制约束，不表示现有原型已符合。P0 建立配置和门禁；规则变更与功能变更同样需要 Review。M1–M4 的 MathJax 优化仍仅在首版发行后实施，工程规范不改变其范围。

- 全部产品源码使用 TypeScript strict；浏览器、Worker、构建脚本分别配置类型环境。禁止新增无说明的 any、@ts-ignore、非空断言及双重类型断言；外部输入先以 unknown 接收并做运行时 schema 校验。必要例外须局部、注明原因和验证依据，不得整目录关闭规则。
- 核心/IR 不依赖 React、DOM 或平台模块；浏览器与 Tauri 能力通过适配器接入。跨模块通过公开入口调用，禁止绕过边界深层导入或循环依赖。共享类型单向依赖，避免建立混杂工具集合。
- 组件和类型使用 PascalCase，函数/变量使用 camelCase；文件及目录统一 kebab-case，React 组件文件采用 PascalCase.tsx。命名体现用途和单位，时间/尺寸使用明确后缀；禁止仅为满足行数阈值拆分模块。
- React Hook 遵守调用及依赖规则；Effect 只同步外部系统，不用它串联本可直接计算的派生状态。编辑器、Observer、事件、Worker 和临时 URL 均有对应清理；挂载/卸载可重复执行。
- 异步任务明确所有者、修订、就绪条件、错误和取消语义；不得吞异常、无上限重试、以固定 sleep 代替完成事件。错误提供可定位诊断，不记录用户正文、凭据或敏感路径到遥测。
- 原始 Markdown、导入样本和用户资源不得被格式化工具改写。HTML 注入经受控清理入口；插件权限、跨线程和跨来源输入在边界校验，不把 TypeScript 类型当安全验证。
- UTF-8、LF 为仓库文本默认，使用 .editorconfig 与 .gitattributes 固化；导入导出仍按既有契约保留或恢复原文换行。注释解释约束与原因，公开契约包含输入、输出、错误及生命周期。
- 依赖新增必须说明用途、替代选择、许可证、运行/开发分类、离线资源与体积影响。精确锁定直接依赖，提交 bun.lock；禁止顺手升级无关依赖。自动生成文件标注生成入口，不手改产物替代源文件修复。

### 12.2 工具与统一检查入口

采用 ESLint flat config、typescript-eslint 类型感知规则、React Hooks 规则、Prettier、markdownlint-cli2；样式使用 Stylelint 并配置 Tailwind v4/现代 CSS 兼容规则。各工具及插件在 P0 验证现有 TS/Bun 组合后锁定精确版本；若不兼容按第 3 节记录局部运行时回退，不通过关闭类型/规则掩盖问题。格式交给 Prettier，语义交给 ESLint/Stylelint，避免重复冲突规则。[S47][S48]

以下为待建立的 package.json 脚本契约，不代表当前目录已有可运行脚本。CI 调用与本地相同入口；不使用 bunx 临时获取未锁定工具。

| 入口 | 必须执行与结果 |
|---|---|
| bun run format:check / format:write | 检查/显式修改受管源码和设计文档格式；排除用户内容、fixtures、第三方及生成产物 |
| bun run lint | ESLint、Stylelint；零错误、零警告；规则例外须在 Review 中说明 |
| bun run docs:check | Markdown 结构、内部链接/锚点、受管样例及 schema、版本/契约引用；外链可达性独立定期检查，不能用网络波动阻塞普通 PR |
| bun run typecheck | 按浏览器、Worker、脚本配置运行 tsc --noEmit；Vite 构建不替代类型检查 |
| bun run test:unit / test:integration | Vitest 单元及集成测试，固定输入与可重现断言；非 watch 模式失败返回非零 |
| bun run build / assets:check | 生产构建；核验资源清单、路径、许可证、隐含远程依赖及产物体积预算 |
| bun run test:e2e | Playwright 针对实际生产构建运行；输出失败 trace/截图及测试报告 |
| bun run check | 聚合格式、Lint、文档、类型、单元/集成、构建及资源检查；任一失败整体非零，不自动修复源文件 |

提交前可用暂存文件快检，但不能替代 PR 全量门禁。CI 缓存键包括系统、Bun 版本及锁文件哈希；缓存缺失时仍能完整运行。安装使用 bun install --frozen-lockfile，禁止 CI 自动更新锁文件。[S50]

### 12.3 文档 Review 与代码 Review

功能开发前维护对应设计条目、接口、样例和验收范围；跨层边界、源载荷、schema、插件 API、依赖和导出语义变化先写 ADR，记录选择、影响、迁移/回退与替代方案。小型缺陷修复可在 PR 中说明，无需为每次修改新建 ADR。文档不得把规划写成实现或把转换成功写成视觉验证。

| Review 类型 | 必查事项 | 留存结果 |
|---|---|---|
| 文档 Review | 范围和阶段一致；术语、接口、示例及引用可用；新增约束可验收；兼容性与降级有依据 | 关联章节/ADR、未解决问题、通过或阻塞结论 |
| 代码 Review | 行为、边界输入、分层、状态/资源生命周期、竞态、错误恢复、权限、依赖及性能风险；测试是否验证行为 | 文件/行号、可复现问题、严重度、修复或接受依据 |
| 输出 Review | HTML/MathML/SVG、A4 和声明支持的阅读器效果；离线资产及内容完整 | 环境、修订、样例、截图/文件、明确未验证项 |

每个 PR 需至少一名未编写该变更的审阅者给出明确结论；Codex 可协助文档/代码 Review，但作者自己的复述不能视为独立 Review。单人开发可由独立 Review 会话检查固定 diff，作者承担最终合并责任；不得宣称获得不存在的人类批准。保护分支强制人类批准时，以实际仓库规则为准。

数据丢失、权限绕过、错误导出、无法构建及其他影响关键契约的问题必须关闭后合并；非阻塞建议记录责任人和后续任务。修复后重跑受影响检查，实质性新提交重新审阅受影响 diff。Review 结论绑定提交 SHA；讨论未解决不以“CI 全绿”代替批准。

PR 模板至少包含：问题与结果、范围/非目标、设计/契约变化、验证命令和证据、兼容/降级影响、已知限制及必要回退。文档-only PR 仍须文档检查与 Review，不无条件跑无关浏览器测试；范围判断不确定时运行完整检查。主分支通过 PR 合并，禁止在未授权情况下推送或发布。

### 12.4 测试策略与验收证据

- 单元：IR/schema、纯转换、资源路径、缓存键及失效、修订选择、降级判断。修复缺陷时优先增加能复现问题的回归测试，不编写仅镜像实现的断言。
- 集成：编辑状态与持久化、插件契约、异步失败/竞态、渲染就绪屏障、源载荷往返、导出快照。非运行阶段的 M1–M4 不提前要求实现或测试其功能。
- E2E：在生产构建验证导入→编辑→保存/恢复→预览→导出→重开；覆盖中文 IME、撤销、错误输入、视口外内容、离线及拒绝/取消操作。核心路径每个相关 PR 在固定 Chromium 环境运行；跨浏览器和 Windows 环境在发布候选运行，新增平台能力才加入相应矩阵。
- 视觉与输出：桌面/手机、长内容、MathJax 与图表、真实 A4 打印预览及格式阅读器检查。截图差异需审阅，禁止批量刷新基线掩盖回归；Playwright PDF 不等于系统打印预览，WebKit 测试不等于 Tauri WebView 实机。
- 非功能：按第 14 节记录性能环境/样例及内存；资源/输入安全负例、权限和恢复；自动可访问性检查加键盘、焦点和必要辅助技术人工检查。第三方依赖扫描报告需结合是否实际可达处置。

覆盖率用于寻找遗漏，不用单一百分比证明质量。P0 建立核心模块基线及变更覆盖要求；关键边界和已修复缺陷必须有可验证证据，不能靠降低阈值过门禁。高风险核心改变必须全量相关回归。

不允许以重试后偶然通过掩盖不稳定测试；记录首次失败。确需隔离的测试须有缺陷编号、责任人、恢复期限及替代验收，关键数据安全/导出完整性测试不得无替代停用。证据记录提交 SHA、工具/浏览器/字体、命令、结果和未验证项，真实用户文档不上传 CI。

### 12.5 CI 门禁与合并策略

默认规划 GitHub Actions；迁移托管平台时保持相同脚本和门禁语义。工作流文件、分支保护和发布环境配置一并纳入 Review，不能只依赖开发者本地 Hook。

| 触发 | 必须检查 | 通过后的权限 |
|---|---|---|
| PR/合并队列（若启用） | 冻结安装；check；相关生产构建 E2E；Review/讨论完成；检测依赖与资源变化 | 允许合并，不获得生产发布权限 |
| 主分支合并 | 对实际合并 SHA 重跑聚合检查及核心 E2E，生成候选产物和哈希 | 可供预览/验收；失败阻止提升为发行版 |
| 定期/依赖 PR | 全回归、跨浏览器、依赖/许可证/外链及体积趋势；按需性能基准 | 产生问题与修复 PR，不自动合并升级 |
| 发布候选/版本标签 | 指向已验收提交；版本、变更记录、许可及离线资源完整；目标矩阵和人工输出验收 | 满足发布授权/环境策略后才可部署 |

每项门禁有稳定检查名称。路径过滤不能令必需检查永久等待或直接被绕过；用汇总门禁明确运行/合理跳过结果。CI 设置超时与并发控制；新预览可取消旧预览任务，不取消正在提升的正式发行。保存报告、失败 trace、候选清单和必要截图，P0 默认保留 30 天；发行清单随版本长期保留，不保留敏感测试数据。

Actions 固定完整提交 SHA；默认 contents: read，写权限限发布任务；不可信 PR 不接触发布密钥，不以 pull_request_target 方式执行其未审阅代码。发布环境凭据单独管理，部署身份优先采用短时授权；日志和产物扫描防止泄密。依赖安装脚本只批准确需执行的包，审查 trustedDependencies 变化。[S49][S50]

### 12.6 CD、发行与回退

CI 负责验证和构建，CD 负责提升已验收产物；默认流程是候选→预览/测试环境→验收→生产。不因 CI 全绿自动公开发布。可预先授权受保护分支/版本标签的自动部署规则；未有此授权时，具体发布由维护者确认，不要求每个普通开发任务重复申请。

生产部署提升与候选一致的不可变产物，校验提交 SHA 和 SHA-256，不在部署时重新安装或重新构建。发行记录包含版本、提交、工具链/锁文件、产物哈希、资产及许可证清单、验收范围、已知限制和回退版本。PWA 验证 Service Worker/缓存更新及旧草稿兼容；破坏性数据迁移必须提供备份、迁移与恢复路径。

发布后运行只读健康/资源加载冒烟和新用户编辑导出样例；失败停止继续推广并恢复已验证版本。回退应用不等于能回退已迁移数据，数据库/草稿迁移需单独恢复方案。Tauri 签名、各系统打包/安装与升级检查在 P6 建立，不冒充 Web 发布已覆盖桌面发行。

### 12.7 阶段落实与完成定义

P0 建立 AGENTS.md、EditorConfig/Git 属性、Lint/格式/类型配置、统一脚本、PR/ADR 模板、基础 CI 和证据目录；按阶段增加真实测试和资产预算，不预建尚未实施的功能。P1–P3 随功能接入回归和输出验收；P4 建立受控发行、离线检查与回退演练；P6 增加平台签名及实机矩阵。

一项开发任务完成必须同时满足：范围内行为实现、文档/契约同步、相关检查通过、Review 阻塞项关闭、证据及限制记录完整。无法运行的必需检查明确标为未验收，不能标成通过；只有维护者记录原因、风险、替代验证和补验期限后才可接受例外。不得无记录跳过或把例外变成永久关闭门禁。

## 14. 验收标准

### 14.1 功能与结构

- 编辑区确有 Markdown 和围栏语言高亮，中文输入不丢字，撤销恢复图片插入及格式操作。
- 编辑区使用 CodeMirror，预览/导出使用 Shiki，预览临时标记使用 CSS Highlights；未引入 highlight.js 或逐键全量 Shiki 扫描。
- 代码 token 范围与 UTF-16 原文一致，覆盖 emoji、制表符、CRLF、跨行字符串和注释；主题切换、未知语言和 Worker 重启不丢代码或错误复用旧颜色。
- 搜索/定位在 DOM 替换、分页、虚拟区块更新及文档切换后仍准确；清理仅作用于本视图注册项，保存/打印/导出无临时标记残留。
- 视口任务优先、非可见区块可延后；全文导出仍包括所有未曾进入视口的内容；清理预览任务不取消独立导出快照。
- 切换视图、变更主题不修改原始 Markdown；普通预览刷新不重置选区或撤销栈。
- 可编辑 HTML 往返后 Markdown 字符内容一致，元数据、主题和所有资源哈希一致；分别测试 LF/CRLF 与 Unicode。
- 单个渲染器报错时其余区块可用；导出列出明确节点和降级结果，无正文静默丢失。
- 导出前等待资源完成；旧渲染结果不覆盖新修订；导出中继续编辑不会混合版本。
- 公式输入固定为 LaTeX，MathJax 为单一主引擎；文档保存/重开后显示模式、宏及扩展配置一致，跨文档不泄漏宏和编号状态。

公式专项样例至少覆盖：行内/独立公式、嵌套分式与根式、积分求和与极限、可伸缩括号、矩阵/分段、多行对齐、编号/交叉引用、数学字体变体、显式自定义宏、中文文本、超长公式及无效命令。领域扩展按启用范围增加样例。分别记录“解析正确”“MathML 显示正确”“SVG 显示正确”“打印正确”，不能把转换成功等同于公式排版通过。

同步与布局专项验收：大纲点击标题居顶；双向滚动在长正文、代码、公式/图表、重复标题、无标题、折叠、文尾和 A4 分片中均能定位正确区块，无反馈振荡、焦点抢夺或旧修订跳转。分别检查全部七种非空组合及最后一个视图不可隐藏、键盘恢复入口、移动端、显隐后编辑状态保留、默认 1024px/自定义/不限宽及调整宽度后的锚点恢复。精度按区块/子锚点验收，不要求不同表示逐像素等高；独立输出不携带工作台显隐偏好。该功能是基本需求，不属于后续 MathJax 优化。

多视图响应式专项验收：在 1280px、684px、390px 及跨断点连续缩放时，开启的视图均保持显示；宽度不足仅工作台内部横向滚动，页面整体无横向溢出。逐项检查七种非空组合、仅单视图时充分使用可用空间、顶栏/配置入口固定可达、隐藏/恢复及偏好重载不受断点改写；横向滚动不触发章节跳转或破坏双向纵向同步。

配置弹窗专项验收：首次打开及重载默认关闭；顶栏入口可达；弹窗开关不改变工作台占用区域；弹窗内配置、校验、应用/重置及最后视图保护正常；键盘焦点进入/约束/返回、Esc/关闭按钮/遮罩关闭在桌面和手机可用；已保存值恢复但不自动弹窗；打印/导出不含配置界面。

### 14.2 格式与视觉

- HTML 正文可选取、可搜索，无未解析公式、空白图表、失效 blob: 引用或隐含远程依赖。
- 桌面与手机实际检查；长链接、宽表格和长代码不导致整页横向溢出，局部滚动需明确。
- A4 检查标题孤页、表格续页、超高图表、页眉页脚、页码和空白页；记录浏览器、字体、纸张、比例和边距。
- 公式分别检查两种文档级模式的行内基线、行距、字体变体、矩阵/多行对齐和编号；MathML 清理前后结构有效，SVG 不依赖编辑器全局字形缓存。打印使用预览冻结模式，切换模式后重新分页。
- DOCX 在选定 Word 版本及至少一种替代阅读器检查，标题/段落/表格为原生对象；公式图片降级有说明。未获得阅读器时仅记录结构检查，不宣称完成视觉验收。
- 浏览器打印预览、实际保存 PDF 检查、实体打印为三个不同验证级别，分别记录。单靠 DOM 截图不能证明 PDF 分页正确。
- A4 页码明确对应完整修订，旧页面更新中有状态提示；阅读模式不连续全篇分页，A4 模式按空闲策略合并更新，最终打印无未就绪高亮、占位或缺失的离屏资源。

HTML/CSS/JS 支持声明须同时标明目标运行环境、阅读效果、打印效果与各输出格式的原生/映射/静态化/不支持状态。第 16.9 节的样例和退出条件按阶段执行，不以“浏览器识别语法”代替布局及导出验收。

### 14.3 离线与发布

- 使用相同 Bun 版本和 bun.lock，在干净开发/CI 环境执行冻结安装，检查/测试/构建不修改锁文件；记录每个工具的实际运行时。React/react-dom 版本对齐且为 19 系列；局部 Node 回退有可复现命令。
- 新浏览器配置加载并完成全部离线资源准备后，断网重启应用，首次启用公式、Mermaid、DOT 和 DOCX 均成功。
- 网络日志中没有必需 CDN 请求；WASM、Worker、字体与动态模块均在资源清单。
- 断网首次打开尚未使用的批准代码语言/主题成功，Shiki Worker 可初始化；关闭视图/切换文档后 Worker 队列、Range 注册项和相关资源按生命周期清理。
- 阅读 HTML 在未安装本工具的机器断网打开可用；可编辑 HTML 导入后能重建文档。
- 浏览器存储配额失败和缓存升级失败不会导致正文丢失或错误的“已保存”状态。
- standalone 和桌面只在各自验证通过后发布，不拿 PWA 安装成功替代首次离线启动验收。

### 14.4 初始性能预算

以下为设计目标，需由 P0/P1 建立 Windows 桌面基准机、锁定浏览器和样例后实测：10 万中文字符、200 个普通区块、20 张图片、20 个图表/公式混合样例；资源字节另行记录。

输入事务主线程耗时 P95 目标小于 50ms；普通正文预览目标在停止输入后 1 秒内更新。复杂图表首渲染与完整分页独立计时，不要求每次按键全量执行。连续编辑、切换和导出 20 次后观察内存与 Blob URL 回收，不要求所有重图表在固定一秒内完成。

公式性能单独记录冷启动资源加载/解析、单公式变更、批量首次转换、缓存命中和浏览器布局时间；覆盖 100 个及 1000 个公式的固定样例。普通文字变更不应触发未受影响公式的重复转换，编号或宏变动应正确重算依赖。MathML 与 SVG 在相同 LaTeX、扩展、字体及设备下比较；不预先宣称某模式一定更快。默认模式决定须同时满足支持度、正确显示与性能目标。

高亮测试至少覆盖 100 个代码块、单个万行代码块及跨行语法样例，记录首次初始化、单块转换、缓存命中、Worker 传输、DOM 创建、搜索 Range 数量、内存与打印分页成本。验证输入延迟与后台吞吐分别统计，不能只报 Worker 内部运行时间。对比相同样例的 Shiki span 默认路径与 CSS Highlights 实验路径，记录整体净收益。

调度测试记录可见/预读/后台队列等待时间、渲染缓存命中率、修订淘汰和 A4 实际运行次数；连续输入应合并分页，长任务不阻塞编辑。800ms A4 空闲时间是初始调度参数，不是完成时限；完整导出耗时单独统计。未完成的预览不能误标为最新已就绪。

初始脚本与完整离线包分别统计压缩体积、WASM、字体及插件占比；依据实测决定预算阈值，不把“依赖统一安装”等同于体积必然很小。

## 15. 关键决策与后续确认点

已明确：产品以 Markdown 编辑器为中心；Bun + React 19 优先开发，统一 TS/npm 生态依赖与构建；用户核心运行不安装 Bun/Node 或外部转换库；HTML 负责展示和视觉输出；保留结构化模型支撑可编辑导出；首版内置插件；Web/PWA 优先。

默认采用：Bun 1.4.x、React/react-dom 19.x（优先验证 19.3.x）、TypeScript 6.0.x 兼容基线、Vite 8.x、CodeMirror 6、Tailwind CSS 4、unified、MathJax 4、Mermaid 12.x 验证基线、Graphviz WASM、docx、Paged.js、Vitest、Playwright。具体包按第 3 节选定并由 P0 精确锁定，设计基线不等于已通过兼容测试。公式仅接收 LaTeX，优先验证 MathML，以大多数公式直接可用及排版稳定为前提；默认显示模式由 P0 确定，不引入 KaTeX/Typst 或逐公式自动切换引擎。默认基础 DOCX 与图表均纳入首版，EPUB/PPTX 后续扩展。

高亮确定采用 CodeMirror / Shiki / CSS Custom Highlight API 分工；Shiki 4.x JavaScript 引擎作为验证基线，替换 highlight.js。Worker、区块缓存、视口优先与独立 A4 空闲调度为首版设计要求。第 7.6 节实验均未承诺实现，不据此替换 Markdown/分页引擎或将全部代码高亮改为运行时 Range。

实施前通过 P0 落实：分页引擎是否满足样例；目标浏览器与 Word 阅读器版本；是否需要从未联网的首次离线启动；是否需要自动下载 PDF。后两项若为必需，则 standalone/桌面路径需提前，不能只靠 PWA 承诺。

后续本地文件能力确定采用 Tauri 平台适配器；工作区导入不等同于目录授权，源文保存不等同于派生产物导出。

## 16. HTML 兼容性与输出适配规划

### 16.1 目标与能力边界

目标是现代浏览器原生 HTML/CSS 阅读与交付，JavaScript 采用显式启用的交互模式；打印和非 HTML 输出分别适配。浏览器/WebView 是实际排版引擎，应用不自建一个只覆盖少量 CSS 的通用渲染器，也不为追求 Word 兼容而统一降低 HTML 阅读能力。

“支持”必须分开记录五层：运行环境能否识别/执行、应用是否允许、阅读布局是否正确、打印是否正确、目标文件是否保留所需语义/视觉/交互。阅读支持不自动推出其他四层支持。

本章所有能力均为实现规划。当前 V0.2.4 UI 原型仍是轻量预览，不据此宣称已完成现代 HTML 兼容。完整原始 HTML 导入/编辑也不是首版功能；普通 HTML 不含本工具源载荷时，仍不承诺恢复 Markdown。

应用界面、文档预览和独立输出 HTML 分别定义样式边界：应用使用 OKLCH，文档默认 HEX/RGB。预览与输出共享语义结构、文档 CSS 及资产清单，独立 HTML 不依赖应用 React、全局主题或外壳容器；按目标内容宽度重新布局，不能只复制 innerHTML。现代特性按内容需要选择，以语义元素、Flex/Grid、媒体查询、尺寸容器查询及流式排版为优先；高级作者语法、任意脚本及高级模板仍按原阶段推进，不因本次修订提前。

### 16.2 内容模式与渲染宿主

| 模式 | 作者入口与内容 | 执行和输出原则 | 阶段 |
|---|---|---|---|
| Markdown 基础模式 | Markdown、批准的原始语义 HTML、公式/图表插件 | 普通正文不执行用户脚本；应用插件输出可为现代 HTML/SVG/MathML | H1 |
| 现代静态内容/模板 | 明确的 HTML/CSS 内容块、结构化主题和模板包 | 广泛使用已验证现代 CSS；不执行作者 JS；拥有独立资源清单和打印样式 | H2 |
| 显式交互内容 | 已注册交互组件，后续按需允许自定义 JS 内容块 | 独立隔离宿主、消息契约、资源/状态声明和静态输出 | H3 |

编辑器外壳、文档样式与交互内容分层。静态文档可以使用独立 iframe 文档根隔离选择器/字体/CSS 变量；具体宿主在 H0/H2 选择并验证，不把 Shadow DOM 当作脚本安全边界。导出器生成完整文档结构，不只抓取可见片段的 innerHTML。

交互宿主使用 iframe sandbox、独立来源或等效隔离方案，并以受控 postMessage 协议通信。来源、消息类型、会话/修订与载荷 schema 均验证；不向用户内容暴露编辑器存储、其他文档或 Tauri 原生桥接。对不可信 srcdoc 不同时开放同源与任意脚本权限。受信任应用插件与作者自定义代码为不同权限类别，不因“是本地文件”而自动授予应用权限。[S40]

CSS 和资源的允许策略独立于 DOMPurify：验证 URL、资源访问、@import 和可影响宿主的规则，同时保留已批准的 @container、@layer 等语法；不能靠简单正则删掉未知 CSS。高级内容在本模式不支持时保留源并提示，不静默破坏。

### 16.3 现代特性目标矩阵

下表“优先”表示计划建立正式契约和测试，不表示全部在首版实现；最终支持以运行环境和验证记录为准。

| 特性组 | 目标能力 | 约束与实现顺序 |
|---|---|---|
| HTML 结构 | 语义元素、表格、图像、figure、SVG、MathML、链接/锚点 | H1 保证正文语义；后续 details 等交互元素增加打印展开策略；外部嵌入不作为离线基线 |
| 布局 | Flex、Grid、Subgrid、逻辑属性、aspect-ratio | H1 常用布局，H2 扩展内容块；浏览器尺寸测量与跨页拆分分别验证 |
| CSS 组织 | 自定义属性、@layer、嵌套、:is()/:where()/:has()、按需 @scope | 按实际引擎与构建输出测试；文档 CSS 隔离，不由正文任意生成应用 Tailwind 类 |
| 响应式 | @media、尺寸容器查询、命名容器 | H1/H2 优先；工具外壳看视口，文档组件看内容容器 |
| 尺寸 | rem/em、ch/ic、lh/rlh、svh/dvh/lvh、容器单位、mm/pt、min/max/clamp/calc | 按第 16.4 节定义参考空间；打印不依赖屏幕高度 |
| 字体 | WOFF2、变量字体、OpenType 特性、中文/西文/数学/代码分配 | H1 本地回退与就绪检测；H2 字体导入、轴设置、内嵌和授权信息 |
| 颜色 | 应用 UI 使用 OKLCH；文档默认 HEX/RGB | H1 文档不要求现代色彩计算；插件原有有效 HEX/RGB 保留，不强制统一到 OKLCH；高级色彩非首版必需 |
| 文本排版 | 行距/字距、断行、连字、数字特性，按需 balance/pretty、纵排 | 常用能力优先；纵排、多栏与复杂跨页作为 H4 专项，不能只凭屏幕截图通过 |
| 原生交互 | details、dialog/popover、CSS Highlights | 应用 UI 与文档交互分开；临时高亮不进入交付，打印展开/隐藏交互控件 |
| 新增增强 | 容器样式/滚动状态查询、Anchor Positioning、View Transitions、滚动驱动动画 | H4 检测后按需启用；不作为普通文档可读或可打印的前置条件 |

容器查询包含多种不同能力，必须逐项声明，不能用一个 containerQueries 布尔值覆盖全部。属性可解析不保证真实排版正确；同样，构建器能处理新 CSS 语法也不保证运行时具备对应能力。[S35][S36][S37]

### 16.4 容器、单位与布局坐标

工具外壳可通过媒体查询调整面板宽度、间距和次要信息，但不得自动隐藏开启视图；空间不足时工作台内部横向滚动；文档内部优先使用尺寸容器查询适应实际右栏宽度。独立导出 HTML、全屏阅读和 A4 正文均建立命名内容容器，使相同组件按所在空间布局，而不是错误地按整台浏览器窗口布局。

容器根使用 container-type: inline-size 等明确设置，查询样式作用于其后代。容器单位 cqi/cqw 等的查询祖先必须确定；不要因导出遗漏容器而改变参考空间。纸张内容宽度依据纸张减去页边距计算，打印适配层重建同等语义容器。H0 以简单两栏→一栏组件验证，H2 扩展到图文/表格组件。[S35][S36]

| 单位/机制 | 默认用途 | 打印与导出处理 |
|---|---|---|
| rem/em | 字号与相对间距 | 保留层级；非 CSS 格式由适配器换算 |
| ch/ic | 西文/代码与中文行长参考 | 字体和字形改变可能影响度量，字体就绪后重排 |
| lh/rlh | 按行高组织间距 | 保留明确的行高上下文，避免循环或不确定计算 |
| svh/dvh/lvh | 应用外壳、交互阅读空间 | 打印样式替换，不能将正文截成一屏 |
| cqi/cqb/cqw 等 | 文档组件随内容容器变化 | 导出保留容器链；纸张按内容区域计算 |
| mm/cm/pt | 纸张、页边距和打印排版 | 屏幕显示不是实体测量证明；实际 PDF/打印验收 |
| fr/%、min/max/clamp/calc | 弹性布局 | 阅读保留；非 HTML 格式依据适配规则重排或静态化 |

容器查询带来的布局变化需在分页前完成；字体、栏宽、资源及容器断点变化后重新测量。分页器若移动/克隆节点改变容器祖先，必须测试或补回容器上下文，不能拿阅读布局的旧高度计算新页码。

### 16.5 字体、色彩与离线资产

字体资产登记来源、许可、格式、哈希、字形覆盖及可用轴。主题设置保存字体族及 wght/wdth/opsz 等轴或对应高级属性；中西文、数学与代码可分别设置。字体加载、可用性检查和实际 glyph 回退分开记录；font-display 的临时回退不等于导出就绪。字体变化使受影响布局与分页缓存失效。[S38]

单文件 HTML 需要字体可内嵌且许可允许；中文字体体积较大，可选经工具验证的子集化，不能随意删去用户动态输入所需字形。未内嵌字体时明确采用系统回退，不承诺跨设备页码相同。变量字体输出 PDF/Word 时是否保留轴和字形效果，按引擎/阅读器单独验证；有需要时显式映射到静态实例。

应用 UI 保留 OKLCH 色彩体系；文档主题及 Markdown 输出 HTML 默认使用 HEX/RGB，阅读/A4 预览与独立文档共享该策略。两种颜色语法可以共存，但不以应用体系强制转换文档或插件配色；Mermaid 等已有 RGB 描述无需增加 OKLCH 中间转换。文档的现代化重点是语义结构、现代布局和响应式排版，不要求全面采用最新 CSS。非 HTML 输出只按目标需要映射颜色/透明度；打印配色另行验收，不承诺屏幕与纸张完全相同。OKLCH 参考仅用于应用或后续显式能力，不作为文档首版基线。[S39]

发布及导出解析 CSS 的 url()、@font-face、图像/SVG 关联资源和批准的 @import，将所需资产本地化或列为未完成依赖。资源收集失败时不能声明完整离线。Bun/Vite/Tailwind 负责应用与受管理模板的构建；用户内容中出现新类名并不会自动获得完整 Tailwind 工具类，需单独编译模板或使用语义 CSS。

### 16.6 JavaScript 与交互导出契约

先支持受控交互组件，再按需开放自定义脚本；无需在首版提供任意 HTML 应用执行平台。交互块声明输入、状态版本、依赖资产、运行环境能力和离线条件。作者代码不依赖编辑器内部 React/store 或全局脚本顺序，不允许将未声明网络加载当成离线能力。

建议契约为 initialize、whenReady、serializeState、pause、renderStatic、dispose。renderStatic 接收目标格式和冻结状态，返回原生内容、可适配结构、SVG/图片或明确不可支持的诊断。接口在 H3 固化；Worker 不替代有 DOM 交互宿主，也不作为运行任意代码的安全边界。

导出协调器冻结 revision 和交互状态 → 等待组件就绪 → 暂停时间相关动画 → 生成目标表示 → 处理字体/资源 → 布局分页 → 写出。无 whenReady/renderStatic 等契约的内容不能仅等固定几秒后认定完成；必须提示选择静态替代或阻断不受支持的格式。

Canvas/WebGL、音视频、动画、自定义元素及 Shadow DOM 按实际组件注册静态化策略，不能默认 innerHTML 序列化可保存其显示状态。静态 HTML 默认无作者运行脚本；交互 HTML 是显式独立配置，包含必要运行代码与状态。交互保留、单文件可打开、完整离线三个条件分别验证，file:// 下 ESM、fetch、Worker 等限制仍按第 10 章处理。

### 16.7 输出内容与格式兼容矩阵

输出能力使用 native（原生语义）、mapped（显式映射）、static（冻结后的视觉表示）、unsupported（不支持）四类；每次还记录文字可选取、对象可编辑、交互保留和视觉一致性的独立结果。图片静态化不能标为“可编辑”，文本存在也不能代替语义正确。

| 内容 | HTML 阅读/交互交付 | A4/PDF | DOCX | PPTX | EPUB |
|---|---|---|---|---|---|
| 标题/段落/列表/简单表格 | 原生 HTML | 正文文字与分页 | 原生对象映射 | 按幻灯片模型映射 | XHTML 语义结构 |
| Grid/Flex/容器布局 | 保留 CSS 与容器链 | 独立打印布局，测试跨页 | 明确重排；必要时静态化 | 模板化重建或视觉模式 | 阅读器子集/回退 |
| 变量字体/OpenType | 保留声明并准备字体资产 | 验证嵌入与字形效果 | 字体/轴映射，按阅读器验证 | 字体/轴映射，按阅读器验证 | 字体许可与阅读器验证 |
| 文档 HEX/RGB 配色 | 保留文档/插件有效颜色 | 独立打印配色及透明度验证 | 映射目标颜色/透明度 | 映射目标颜色/透明度 | 按阅读器支持输出 |
| 数学/图表 | 按既定 MathML/SVG 路线 | 固定模式与完整资源 | 按现有公式图片路径；OMML 后续 | 已支持对象/图像 | MathML/SVG/图像按阅读器 |
| 交互控件/脚本 | 仅显式交互交付保留 | 展开/冻结状态，无运行交互 | 静态语义替代或图像 | 支持的对象/静态表示 | 默认不依赖脚本 |
| Canvas/WebGL/音视频 | 已声明组件及运行资源 | 静态快照/封面/说明 | 静态表示或明确不支持 | 按导出器能力处理 | 阅读器专项能力，否则回退 |

这是一份适配目标，不是已实现矩阵；具体内容若没有相应适配器，当前就是 unsupported。导出前 inspect 按实际文档生成能力报告，列出受影响区块、原因和替代结果。语义重排、图片化或交互移除需展示选择，禁止静默丢失。

打印配置独立使用 @media print、@page、分片/断页规则；多栏、纵排、定位元素、Grid/Flex 与长表格组合需要专门样例。阅读正确不等于 Paged.js 或平台打印正确，不让分页器的局部限制成为全部阅读功能的上限。[S41]

### 16.8 分阶段实现规划

| 阶段 | 对应已有阶段 | 本阶段交付 | 退出条件 |
|---|---|---|---|
| H0 契约与检测 | P0 | 内容/输出能力 schema、测试夹具、命名容器/字体/颜色最小样例、运行环境记录 | 确定首批支持清单和已知缺口；不写“完整 HTML5/CSS3 支持” |
| H1 现代静态基线 | P1–P4 | 文档语义结构、HEX/RGB、Flex/Grid、常用单位/字体、媒体查询及已选尺寸容器查询、静态 HTML 与打印 | 已选基线在预览/独立 HTML 阅读及关键打印样例通过；不依赖应用主题或容器；未实现高级内容明确诊断 |
| H2 模板/高级静态内容 | P4 之后按需 | 独立 HTML/CSS 宿主、尺寸容器组件、变量字体导入、主题包资源收集、阅读/打印双样式 | 拖动预览栏/独立 HTML/A4 容器行为正确；离线资产完整；非 HTML 降级可解释 |
| H3 显式交互 | P5 或独立迭代 | 先做少量注册组件，落实隔离、状态/就绪/静态化接口；再评估自定义 JS | 交互 HTML 可恢复状态，静态输出确定，无法适配时正确提示；无原生权限泄漏 |
| H4 增强与覆盖扩展 | P5/P6 按需求 | 滚动/样式查询、新交互 CSS、复杂文字/跨页布局、多阅读器及 Tauri 环境扩展 | 每项有实际用户需求与同一套样例证据；失败不阻断基础文档 |

H2–H4 的顺序可按真实需求拆分，不要求同一版本全部交付。DOCX、PPTX、EPUB 的能力跟各自导出器阶段推进，不为完成本章清单提前实现这些格式。任何能力从计划升级到正式支持，都更新 manifest、测试、用户说明及已知限制。

### 16.9 运行环境、检测与验收

主目标为现代浏览器/WebView，不提供无限旧版本兼容。Windows Tauri 的 WebView2、macOS WKWebView、Linux WebKitGTK 分别记录实际版本与最低验收环境；不把 Tauri 版本、浏览器品牌或 Bun 版本当作 HTML 能力版本。[S42]

检测分为 CSS.supports/@supports、JS API 存在检查及实际渲染测试三层。能力记录至少包含 featureId、环境/版本、内容模式、输出格式、检测结果、实测状态、验证日期及限制。未测试与不支持分别标记；语法被识别不等于容器查询、字体排版或跨页语义已通过。[S43]

阶段样例包含：

- 同一文档组件在窄右栏、全屏、导出 HTML 和 A4 内容容器下的布局与无意横溢检查。
- 中文/西文混排、变量字体轴、缺失字体与字形回退；字体就绪前后页数变化。
- 应用 OKLCH 与文档 HEX/RGB 隔离；插件配色不作无必要转换；阅读与打印配色、透明度及非 HTML 映射分别检查。
- Grid/Flex、长表格、超高代码/公式、强制分页以及容器祖先变化。
- 交互展开、暂停动画、就绪失败、状态恢复、Canvas 快照；未进入视口的区块也完整导出。
- HTML 离线资源及单文件实际打开；DOCX/PPTX 原生可编辑性与视觉、EPUB 实际阅读器分别验收。

保留静态检查、真实浏览器布局、A4 打印预览、生成 PDF 检查及实体打印五种证据层级，不相互替代。自动化可比较几何边界、文字/资源完整性及快照，关键排版仍需目视；Playwright 引擎测试不代替目标 Tauri WebView 验收。
