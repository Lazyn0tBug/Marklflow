# 概念裁剪（去概念化）

- 日期：2026-11-09
- 状态：**进行中**。本轮的对象是「文件身份」与「文件授权」；裁剪的**方法**在本文，**结论**在《本地文档支持设计》。
- 适用：应用层（`src/application/`）与本文档；原生侧（`src-tauri/`）与 `src/core/platform/` 是事实的拥有者。

---

## 0. 原则

**一个概念留在应用层，当且仅当应用层自己要用它回答一个问题。**

机制归机制，名词归名词。把不属于应用层的判断下沉到事实的拥有者那边；应用层只保留它要问的问题，以及一个不握多余东西的规矩。

代价对照：留在应用层的每个概念都要有定义、有不变量、有失效规则、有验收条目，还要在每次修改时重新论证一遍；下沉或裁掉的那些，一条都不用维护。

---

## 1. 怎么判断一个概念该不该留

三个问题，问的都是"应用层要不要自己回答"：

1. **谁拥有这个事实？** 事实归谁，判断就归谁。操作系统拥有访问权限 ⇒ 访问不是应用层的概念；文件系统拥有规范名 ⇒ 规范名怎么算出来不是应用层的事。
2. **应用层要回答的问题是什么？** 把概念翻译成一句问句。答不上来，或者答案不由应用层给，它就是多余的。
3. **拿掉它，应用层会缺什么吗？** 不缺，就裁。

---

## 2. 两种手法

| 手法 | 做法 | 何时用 |
| --- | --- | --- |
| **下沉** | 概念移到事实的拥有者那边 | 应用层其实不需要这个判断，只是习惯性地自己做了一遍 |
| **改名** | 概念不消失，换成一个不承载额外判断的名字 | 机制确实要用，但不该被当成一个"要论证的实体" |

**改名不等于留着旧概念。** 改名的同时要问：这个名字背后有没有一套本来不必有的规则（不变量、失效语义、跨会话承诺）。有，就一并裁掉。

## 3. 本轮：文件身份与文件授权

### 3.1 应用层要的只剩两条

| 应用层要的 | 问句 | 谁答 |
| --- | --- | --- |
| **文件与内容的一致** | 这份内容是不是这个文件的 | 应用层维护"文件引用 → 文档"的映射 |
| **文件的合法性** | 这个文件现在能不能用 | 原生侧：普通文件、大小上限、UTF-8、目标是否还在、内容变没变 |

应用层自己保留的决定只剩一个：**不再用的时候就把句柄放掉**。这不是权限管理，是别攥着不用的东西。

### 3.2 下沉：授权

- 访问由操作系统在用户选中文件的那一刻授予；原生侧只**遵从**。
- 应用层不再有"权限""角色""可写 / 只读"这些概念。它只说"写到这个文件"，成不成由原生侧按 OS 的授权回答，并给出原因码；应用侧把它当事实，不做策略判断。
- 原来那条"打开用户选中的文件即签发可写授权，因此写回不必再选一次"是一条**原生侧的事实**（用户选中即表达编辑意图），不是应用层的授权模型。

### 3.3 改名：文件身份 → 文件引用

- "身份 = 规范名的会话内别名"这件事是原生侧内部的。应用层只拿到一个不透明串，用来认出"这是同一个文件"。
- 规范名由操作系统给出；**规范名一致就是同一个文件**。本仓不制定跨平台的字符串规范化规则。
- 应用层用它决定归属：这份内容属于哪个文件。
- **归属用的引用必须活过访问的结束。** 关掉标签页会放掉访问，但不能让归属失效——否则再次打开同一个文件就找不到 IndexedDB 里那份内容（"再次打开仍是同一份"这条会破）。
  ⇒ 实现上，引用与访问句柄是**两个**不透明串；但设计里不出现"身份"这个词，也不再为它写"不承诺什么"。

### 3.4 不裁的

| 保留 | 理由 |
| --- | --- |
| 路径不出原生侧；没有"前端给个路径就读写"的命令 | 这是"遵从 OS 授权"的**形状**，不是应用层的权限概念：OS 的一次选择只覆盖一个文件，应用拿到的是它的引用，不是路径 |
| 摘要只存原生侧 | "一个事实一处存放"，与概念裁剪无关 |
| 合法性检查本身（普通文件、大小上限、UTF-8、目标是否存在） | 这就是"文件的合法性" |
| 取消 / 失败 / 拒绝三分 | 用户可见，且已实施（M4a-2） |

### 3.5 词面对照表

| 现在 | 改成 | 它是什么 |
| --- | --- | --- |
| 文件身份 / `fileIdentity` | 文件引用 / `reference` | 应用层认出"这是同一个文件"的不透明串 |
| 授权 key / `key` | 访问句柄 / `handle` | 原生侧代操作系统执行读写的凭据 |
| 授权角色（可写蕴含可读） | 原生侧事实 | 应用层不判断 |
| 授权释放 / 撤销 | 放掉句柄 | 不用了就放 |
| 三类 key 的处置 | 三类句柄的处置 | 绑定采用的保留；去重命中的放掉；失败的放掉 |
| 授权已失效（用户文案） | 文件已经不再可访问 | 用户看得懂的说法 |
