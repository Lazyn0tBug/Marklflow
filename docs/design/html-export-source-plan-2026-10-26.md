# HTML唯一输出源与导出实施规划

轻量路线确认：不封装Chromium、不采用Puppeteer，保留Paged.js；Web使用浏览器原生输出，Tauri优先验证系统WebView。操作一致性不要求实现一致或所有平台均返回PDF字节。

## 1. 不可偏离的约束

Markdown是编辑源；HTML是内容唯一映射，也是各目标格式转换的唯一输出源。共同链路为：冻结文档/配置/资产 → 统一HTML产物 → 目标格式适配 → 文件交付。解析树可用于HTML构建、编辑器语法、大纲及源定位，不得给PDF、DOCX或未来EPUB另开内容输出路线。目标格式建立必要临时结构是转换实现，不是第二内容源，必须能逐项追踪回HTML节点。

PDF是文档产物：正文保留真实文本对象、可搜索/复制/选取，公式与图表优先矢量；原始图片可以保持图片。禁止整页或正文区域截图、canvas栅格化拼页、图片加隐藏OCR文字层冒充文档，包括失败后的后备路径。测试截图可用于视觉比对，不能成为生成输入。不支持时明确诊断或停止，不能偷偷截图、上传服务或改用Markdown重建内容。

所有格式共用选择格式、文件名/必要选项、导出、交付及反馈语义；不增加PDF专属打印预览，A4视图不是前置。生成过程可在独立隐藏宿主内排版；宿主不是用户流程。Web和Tauri都须可用，实现可以不同，内容契约与验收要求一致。

### 源文件保存边界

原样MD及资源包中MD是保存编辑源，必须保持编辑缓冲区文本保真（无编辑且保留原始字节时才承诺原字节保真；不得凭Unicode字符串承诺原编码/BOM不变），不做HTML→MD往返。可编辑HTML可携带源文附件以恢复编辑；附件不参与阅读内容生成。它们不是另一种内容映射：PDF/DOCX/EPUB等转换器不能读源附件重新解释内容。源资源包的链接改写及资产收集也须区分源文件操作与HTML呈现资源，不得破坏未映射的原始语法。如果未来新增“从呈现内容导出MD”，须以HTML为输入单独规划，不能混用原样源保存语义。

## 2. 最小共同契约及所有权

不建设通用输出平台，只在现有ExportService和prepareExportContent边界演进：

- 接受操作时冻结来源ID/修订、名称、选项和资源读取许可；实际资产只读取一次并冻结字节、MIME和SHA-256。切Tab或后续编辑不改本次结果。
- HTML产物包含语义化正文、净化样式、源节点标识/范围、数学MathML、净化SVG、文档元数据与冻结资源引用。生成的数学节点保留MathML语义及按需SVG展示，以同一节点绑定；无OMML时DOCX仍使用既有经确认的图像路径，不把保留MathML视为OMML已实现。用户原始HTML中自带MathML的既有拒绝策略不因此自动放开；源LaTeX仅用于诊断/恢复，不作为转换器解释入口。
- 内容、样式和资源引用组成一个版本化HTML产物包，不要求把所有字节塞进一个字符串；不得仅凭单独的Markdown字段重建内容。配置/HTML契约版本记录在产物中，不引入新的缓存治理平台。
- 目标适配器输入只含HTML产物及有限格式选项；文件型转换返回字节、扩展名、MIME及定位诊断，Web PDF则将完整分页HTML交给浏览器原生输出，不要求返回PDF字节。格式诊断允许分析HTML结构，不以再次解析Markdown决定支持范围。纯封装可以不需要DOM；布局依赖由具体引擎适配并进入现有共享DOM串行入口。
- 交付适配器负责建议名、保存目标、字节写入或浏览器下载、取消及清理。文件路径只在平台边界流转。应用保留单busy和局部finally清理，不建立新的导出队列/任务平台。
- 仅以实际所需能力在组合根选择Web/Tauri适配；禁止在UI散布系统判断。生成能力与保存能力分别判断，保存API不能替代PDF生成能力。

EX-H1已在core/model/exportHtml.ts实现版本化只读契约，prepareExportContent返回独立artifact。旧document/html兼容字段已于EX-H2c1移除，格式适配及HTML诊断已于a/b完成；应用统一准备与UI确认仍属c2；不能由新产物存在推定所有旁路已移除。

### 2.1 同一HTML内容与不同布局宿主

统一HTML是规范化的内容/样式/资源输入，不要求Web与Tauri复用同一份已分页DOM或获得完全相同页码。HTML构建阶段完成Markdown解析、宏/编号解析、图表生成和资产冻结；只允许把产物送到不同宿主布局，不允许目标适配器重解析Markdown/LaTeX、重抓远程资源或执行任意作者脚本。MathML与SVG按同一数学节点关联，不能成为两套独立语义。

每个最终布局宿主对同一操作只调用一次Paged.js。Web在浏览器导出宿主完成分页；Tauri在选定系统WebView内完成分页后调用该宿主PDF API，不能先在应用里分页再向另一宿主自动注入polyfill重复分页。跨宿主可以重新布局同一HTML，不能再次生成内容；记录字体/视口/页尺寸及样式媒体求值的差异。分页结果应消除浏览器默认页眉页脚/边距造成的二次分页风险；Web无法控制的系统选项以验收环境与兼容说明记录，不新增应用设置步骤。

### 2.2 交付结果与资源寿命

只区分必要结果：生成/交接失败、已发起下载、已交由浏览器处理、平台确认已保存，以及可观测取消。浏览器原生PDF输出不返回可确认的保存/取消，不虚构结果；afterprint只可用于生命周期处理。原生保存取消不算错误，不重试、不切换其他保存方案；关闭应用导出弹窗不等于取消已接受操作。

共享DOM入口只覆盖引擎步骤，不在用户操作系统保存框期间占用；busy至本次交付函数完成/交接结束释放，不等待无法观测的文件保存。浏览器阻塞对话框导致页面暂停属于平台限制。输出宿主、字体/图片及URL由交付适配器保留到平台不再读取时释放，不能在print调用前清理；afterprint/pagehide、失败及最终宿主销毁的幂等清理由Web步骤验证。Tauri宿主保留到原生PDF完成及文件提交/失败清理，窗口关闭或超时也不能把仍在生成的宿主提前释放。

### 2.3 诊断与一次降级确认

格式诊断从本次冻结HTML读取，源范围只作定位。需要异步生成HTML时，导出按钮先接受并冻结一次操作，再基于该产物做格式检查；必要时在原导出窗口展示汇总和一次确认，不重复读取当前文档生成另一份。确认等待不占共享DOM入口，但该操作仍占单busy；拒绝则结束，不写文件。PDF没有图片降级选项。DOCX保持O0已确认的图片降级政策，OMML尚未接入；明确允许的单个图形/公式后备不等同于允许PDF正文截图。

## 3. 格式路径与现有差距

| 格式 | 目标路径 | 现状与改造要求 |
| --- | --- | --- |
| 阅读HTML | 统一HTML→样式/资源封装→HTML文件 | 现有prepareExportContent可作为迁移起点；需收敛为共同输入 |
| 可编辑HTML | 同一阅读内容+隔离的源附件→HTML文件 | 源附件只负责恢复编辑，不可变成其他导出器的旁路 |
| DOCX | HTML语义/表格/链接/样式→OOXML；HTML内MathML→OMML | 当前已从prepared.html转换主体，但端口仍接DocumentRecord、诊断再解析MD，公式固定SVG；需收紧边界，O0完成不等于OMML完成 |
| PDF | 统一HTML→Paged.js完整分页→Web浏览器原生输出，或Tauri系统WebView原生PDF能力 | 保留Web原生路径并收紧统一边界；Tauri未验证；系统默认文件名限制如实说明，不要求Web取得PDF字节 |
| 原样MD/资源包 | 源保存分支保留MD；资源冻结/打包与HTML映射资产协调 | 不用HTML反推原MD，防止源语法损坏；禁止被内容转换器调用作旁路 |
| EPUB（后续） | HTML→受支持XHTML/CSS/资源/导航→EPUB | 尚未实施；明确目标格式兼容范围，不提前扩展当前版本 |

HTML唯一来源不等于每种格式支持任意JS/CSS。输出HTML默认HEX/RGB，语义结构与现代响应布局优先；静态导出不执行任意作者JS。动态内容需在HTML构建边界完成静态化或明确拒绝。PDF布局使用固定目标视口和分页配置，容器/媒体查询按此求值；DOCX/EPUB不能表达的布局或交互须提示适配、降级或阻断，不另写Markdown内容解释器补洞。

## 4. 导出实现重新评估

| 路径 | 裁决 | 需要证明 |
| --- | --- | --- |
| Web：Paged.js→浏览器原生PDF输出 | 当前选定路线 | 完整分页、正文文本、公式/SVG、字体和临时宿主清理；系统保存默认名不可保证，不冒充已保存 |
| Tauri：Paged.js→系统WebView原生PDF | 优先验证，尚未证明跨平台可用 | Windows WebView2、macOS WKWebView分别核对A4分页、全文/字体/矢量、保存与清理；其他OS另列支持范围 |
| Puppeteer+随包Chromium/Headless浏览器 | 本次明确不采用 | 不增加完整浏览器体积、更新或受控浏览器进程依赖，也不要求用户安装Chrome来补足此路径 |
| jsPDF/svg2pdf.js或手工HTML→PDF布局 | 本轮不推进 | Web原生输出已是选定实现，不再把客户端PDF字节转换PoC设为前置 |
| 从MD AST/LaTeX另建PDF/DOCX内容 | 排除 | 即便库成熟也违反唯一HTML来源；docx/math可保留封装能力，latexToMath生产候选撤回 |
| HTML截图/正文canvas/整页图片PDF及后备 | 全部排除 | 不进入PoC候选，不以复制隐藏文本或视觉相似规避 |
| 服务端浏览器/远程转换服务 | 非默认，不作当前路线前提 | 当前本地优先、离线、无需上传正文；不能为解决Web缺口偷偷增加服务依赖 |
| Tauri原生能力不足 | 明确记录缺口并讨论目标支持范围 | 不自动引入Puppeteer、随包Chromium、服务端转换或截图后备 |

[window.print](https://developer.mozilla.org/en-US/docs/Web/API/Window/print)无文件名参数。Web保留系统原生对话框，其自带预览不属于应用新增PDF专属预览。应用文件名作为交付HTML标题等建议信息传递；不能保证系统PDF驱动自动采用，Windows默认名问题不宣称已修复。Web仅反馈“已交由浏览器处理”，不能由afterprint推断用户保存或取消。

对于HTML、DOCX、MD等已有字节的格式，Web可按能力使用文件选择器或Blob下载；[showSaveFilePicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)有安全环境/用户激活限制，普通HTTP保留下载路径。该API不用于接收浏览器原生PDF输出。取消可观测时独立返回，不自动切换另一种保存方式；浏览器下载只反馈已发起。

Tauri通过系统WebView能力生成PDF并接原生保存；Windows参考[WebView2 PDF能力](https://learn.microsoft.com/en-us/microsoft-edge/webview2/how-to/print)，macOS参考[WKWebView createPDF](<https://developer.apple.com/documentation/webkit/wkwebview/createpdf(configuration:completionhandler:)>)。接口存在不证明Paged.js分页一致；T阶段须实测。复用系统WebView不等于各OS引擎相同或运行时零依赖，发布时核对目标系统运行时及离线安装条件；不将通用Bun sidecar当作DOM引擎。保存选择后实际文件提交成功才报告已保存。

审查修正及验证范围见[文档审查记录](../reviews/html-export-architecture-doc-review-2026-10-26.md)。EX-H2涉及多格式，执行前可按HTML封装、DOCX/诊断边界、交付组合分成连续的小提交单位；必须先确定各子步验收，不能把跨格式大改一次提交。


## 7. EX-H2小步提交单位（本轮启动）

| 子步 | 前置 | 范围 | 独立验收 |
| --- | --- | --- | --- |
| EX-H2a HTML/PDF输入边界 | EX-H1 | HTML封装器/PDF封装器及分页布局只接HTML产物；预览解析留在预览包装层；源附件在组合入口独立构造 | HTML与MD故意不一致的夹具输出跟随HTML；分页不渲染/抓资源；HTML/PDF及完整现有浏览器回归 |
| EX-H2b DOCX/诊断边界 | EX-H2a | DOCX与能力诊断仅分析HTML节点、可信数学标记和源行；保留一次静态化确认及阻断项 | 解包OOXML核对HTML正文/列表/链接；伪造作者标记不能变成生成数学；图像/原始MathML及未知公式错误保持 |
| EX-H2c1 源保存与产物收口 | EX-H2b | MD/ZIP及编辑附件独立；ZIP仅收集源引用资源，不渲染公式；prepareExportContent直接返回HTML契约，删除document/html兼容字段 | 原样源保真、未知公式不阻止源保存、资产只读取一次、源附件不影响阅读内容；严格类型及资源包/HTML回归 |
| EX-H2c2 统一准备与确认接入 | EX-H2c1 | 应用服务统一准备一次；同一冻结产物诊断/确认/转换；移除临时源诊断入口，增加导入门禁 | 双击busy、确认拒绝/关闭、编辑/切Tab不漂移、准备失败释放、不重复渲染；适配器不导入MD/LaTeX解释器；完整门禁及浏览器回归 |

每行审查验证通过后一次本地提交，不推送。EX-H2a/b期间应用组合允许暂时准备包装及旧UI预检，必须在EX-H2c删除，不作为最终双入口。Web原生PDF路径不变，不推进EX-W/T；不升级MathJax/Paged.js，不引入Chromium/Puppeteer。

EX-H2c在开始前细化为c1/c2，避免源资源包改造与实际弹窗确认一次性耦合。c1保持原服务端口由组合入口准备，c2再原子切换到唯一准备入口；不创建第二套长期导出服务。
