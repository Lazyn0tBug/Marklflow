# 编辑工具设计方案

日期：2026-11-12。状态：仅设计，未实施。基线：当前生产编辑器与 WorkbenchToolbar。协作方案：[操作工具设计](application-tools-design-2026-11-12.md)。

## 1. 最小变更范围

本方案配合用户限定的四项优化，不再设计新的编辑器工具体系。此前工作台原型及菜单化提案废弃，不作为布局、断点或功能迁移依据。保留原来的工具位置、分组、顺序与直接操作，只对显示拥挤做必要适配。

四项为：流式/A4 移到 HTML 上方与同步状态并列；打开/新建位于文档/大纲上方；文字/图标/tips 适配多种分辨率；现代 CSS 改善页面和组件尺寸。前两项的具体设计见操作方案，编辑工具主要涉及后两项，以及并列控件所需的局部布局配合。

不新增“段落/格式/插入”菜单，不把 H1/H2/H3、列表或常用格式命令移入新菜单，不新增编辑器局部主栏或文档切换器。编辑器下方 Tab、自动换行、宽度设置与分隔条继续沿用现状。MathML/SVG、分页指令、设置/About 的入口不迁移或重组。

## 2. 既有编辑能力保持

| 能力 | 本次处理 |
| --- | --- |
| H1–H6、粗体、斜体、删除线、行内代码、引用、列表 | 原按钮/现有下拉与快捷键保留，仅调整必要的文字、间距和组内收缩规则 |
| 链接、表格矩阵及预设、LaTeX、Mermaid、DOT 插入 | 保留现有入口和插入行为，不借适配新增库或更换实现 |
| 撤销/重做 | 保留现有文档历史、禁用条件和位置，不把包含选项的 DocumentRecord 历史缩成文本历史 |
| 输出分页指令与 Markdown 普通分隔线 | 输出准备与编辑语义仍有区别，但本轮不移动或新增插入入口；流式/A4 是查看方式，不等同插入分页符 |
| 同步状态 | 复用现有按钮与状态，配合流式/A4 在 HTML 上方并列；不重写联动或复制同步状态 |
| 输入、选区与底部 Tab | 不改变输入模型、语法高亮、IME、Tab/快捷键、会话切换、未保存提示及各文档位置恢复 |

不切换 CM6、不接 Vim、不改解析器、缓存、任务调度或存储。[CM6+Vim 可行性文档](cm6-vim-feasibility-and-cost-2026-11-01.md)是独立议题，与本次尺寸适配无实施依赖。

## 3. 工具显示优化

- 沿用现有主题、图标和按钮风格；名称、图标、tips 表达同一动作，不用换图标来重新定义熟悉的操作。
- 对按钮组设置不缩断约束，避免中文单字竖排、图标被压扁、菜单触发区域过窄；不强制把所有控件压在一行。
- 按工具容器实际宽度调整间距、辅助说明和必要分行，优先 CSS 容器查询、Flex/Grid 与逻辑尺寸属性。保留现有稳定分组，不能仅因视口较窄而取消直接入口或另建菜单体系。
- 仅在确有需要且图标含义明确时省略辅助文字，完整动作名、当前状态和禁用原因仍可通过可访问名称、键盘可达提示获得；不能仅靠 hover 或颜色理解操作。
- 菜单和 tips 沿用既有浮层边界，避免 overflow、包含块或层叠上下文裁切。局部内容需要滚动时边界明确，不把整页宽度撑开。
- 编辑器内容的最大宽度、自动换行与面板宽度分别遵循现有配置；不借响应式覆盖用户偏好。视图不因断点自动隐藏。

## 4. 编辑状态保护

只调整 DOM 布局与样式时，仍需保留原有选区、输入焦点、IME 组合状态、滚动位置和事件接线；不能因分行或尺寸变化卸载重建编辑器、重置选中文档或创建新的历史项。

编辑操作与查看操作仍有明确副作用边界：格式按钮修改源文，流式/A4 只改查看模式，同步按钮只控制既有联动。无需为了本轮显示优化建立新的编辑适配器、全局命令总线或状态副本。

## 5. 验收与当前状态

本次仅修改设计文档，由 Luna 定向核对与四项要求及当前代码边界的一致性，不运行代码或浏览器测试；未实施，未做真实界面验收。废弃原型的截图和测试不作为本方案证据。

获准实施后，针对真实工作台验证：不同面板宽度、深浅主题、字体放大下按钮/图标不挤压和竖排；鼠标与键盘可获取必要提示；原来的格式/表格/公式等入口仍可达；选区、IME、单步撤销、Tab 状态不因布局变化受损。只跑受影响的定向验证，不因本次文档更新重跑全仓。
