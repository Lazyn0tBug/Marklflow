## 0. 决策摘要

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 文件通道 | 只有 `files.rs` 的受守卫命令，**不引入 JS 插件通道** | 插件命令的授权靠能力清单，而本项目的隔离层是 Rust 来源守卫；加第二道闸会让隔离结论与已验收证据分叉 |
| 打开的文件是否可写 | **可写**。用户选中文件即表达编辑意图；写能力只在用户显式触发保存时使用 | "读写角色分离"改为约束**不同的文件**（只读选择的文件不会被写），而不是同一文件的两种操作 |
| 文件身份 | **原生侧维护的"路径 → 随机 token"映射**，会话内有效；不做路径摘要 | 路径熵低，摘要可被字典枚举还原；字符串规范化在大小写不敏感文件系统上会误折叠两个不同文件 |
| 身份用途 | **只用于去重与聚焦**；同步永远按授权里原生侧保存的实际路径执行 | 前端 token 不参与寻址，避免"用标识推路径"这条错误路径 |
| 绑定归属 | **会话内状态**，不进 `DocumentRecord.meta`，不持久化 | 文档记录会作为载荷外传，本机路径不该跟着走 |
| 未同步的判定 | `lastSyncedRevision` 在打开时置为 `document.revision`；未同步 = `document.revision !== lastSyncedRevision` | 与既有 `DocumentSession.savedRevision`/`dirty` 同形，不新造第二套"脏"语义 |
| 本地图片的解析时机 | **渲染/准备期**，由 `collectAssets` 的本地端口解析并内联 | 预览分页、导出准备、Markdown 打包三条链路共用同一处；文档正文保持相对引用原样，产物自包含 |
| 资产键 | `asset.source` = **文档里的引用原文，逐字不变**；解析只在原生侧做 | 全链路按 `a.source === 引用原文` 精确匹配；键若变成解析后的路径，预览与导出会同时失效，且路径会随产物外传 |
| 绝对路径引用 | **首版不支持** | 净化器会丢弃该属性（`safeUrl` 对 `C:\` 判非法），且绝对路径会随文档与产物外传 |
| 目录授权 | 打开文件时**同时授权其所在目录**（只读），原生侧以授权目录和实际打开的对象校验边界 | 相对路径的基准目录必须有授权来源，否则 M6 的断言无从验收 |
| 资产预算 | 在预览准备和导出准备时执行，打开文档与图片读取分离 | 打开期硬闸会让"含 30 张共 40MiB 图的普通 .md"打不开，报错还与"打开一个 md"毫无关系 |
| 本地资产能力 | **平台条件性**：无法可靠执行"同句柄读取 + 拒绝链接组件"的平台不启用本地资产读取 | 这是能力门，不是降级实现——用不安全的方式读本地文件，比不读更糟 |
| 文档与磁盘的关系 | **一个上下文，三个面**（identity 绑定 / sync 同步 / resources 资源）+ **具名转移** | M4/M5/M6 是三个功能依次叠上去，于是绑定成了字段袋、规则逐条追加。改成三面后，一次转移 = 一组字段的变化，可审、可测 |
| 文档存在哪里 | **草稿（IndexedDB）是唯一的存放处，自动持久化，永远只有一份**。本地文件是这份草稿的一个**同步目标** | 本地文件不是"另一种存储"，而是同一份草稿的镜像。于是"保存"在两端是同一个动作，桌面端只是多一步同步 |
| 界面上的状态 | 只表达**同步状态**（无目标 / 已同步 / 未同步 / 同步失败），**不表达"草稿已保存"** | 草稿自动持久化，没有"已保存"这个状态；界面唯一要报的是**保存文件错误**（同步失败） |
| 另存为 | 写新文件 + **新文档**，与旧文档无关 | 旧文档继续同步它自己的文件；新文档从一开始就是"已同步" |
| 同步 | **只有同步**，两个方向（草稿→文件 正向 / 文件→草稿 反向），**不做行级冲突解决** | 冲突消解是三个选择：**覆盖**（正向，草稿胜出）、**放弃**（反向，文件胜出）、**取消**（两边都不动）。三个选择都是"同步"或"不同步"，于是"期望摘要 + 重试一次 + 条件写原语"整套机制都不需要 |
| 磁盘内容的摘要 | **只存原生侧**（它拥有路径与字节）。应用侧连摘要值都拿不到，只问一句"还是上次同步的那一版吗" | 两份摘要必须同步，同步失败就变成误判；而问一句是非，比拿一个值再比较更不容易出错 |
| 跨运行时原语 | **每个运行时一份实现，一个事实一处存放**：应用侧 `src/core/platform/crypto.ts`；原生侧提升为共享 hash 模块 | 摘要现在有两份实现（TS 的 `sha256Hex`、Rust 里私有的 `file_sha256`），再加一份就是第三份 |

### 1.2 本文覆盖

M4（打开与拖放接会话）、M5（原文件保存）、M6（本地资源）的**产品语义、状态模型、授权模型、UI 规格、验收条目**。不改写既有契约，只在其上补足实现前必须定下的设计。

### 1.3 不变量

1. 应用层不持有路径。路径只在原生侧；前端只拿不透明 key、文件身份 token 与展示用字符串。
2. 绑定是**会话内状态**，不是文档数据。不进 `DocumentRecord.meta`，不落盘。
3. 草稿自动持久化不覆盖同步目标；同步到文件只能是显式动作。
4. 不新增隔离层。文件能力仍只经 `files.rs` 的受守卫命令。
5. 不引入第二个文件通道（JS 插件、Node fs、原生扩展）。
6. 取消不是失败；失败不改上下文、不清未同步提示。
7. Web 端行为不变：桌面端能力在 Web 端缺席时降级为原有导入/下载路径，不报错。
8. 文档正文里的引用串**不因本地解析而被改写**。同步到文件的是源快照，不是渲染结果。

## 2. 语义模型

### 2.1 四个用户动作

| 动作 | 作用对象 | 与磁盘的关系 | 是否改变工作区 |
| --- | --- | --- | --- |
| **打开** | 本地磁盘上的 `.md` / `.markdown` / `.txt` / 可编辑 `.html` | 载入为草稿，并把该文件设为**同步目标** | 新增文档或聚焦已有文档 |
| **保存** | 当前文档 | **落草稿**（所有文档都一样）；有同步目标时再**同步一步** | 否 |
| **另存为** | 当前文档 | 写出到新路径，并**新建一个文档**绑定它；旧文档不受影响 | 新增文档 |
| **导入** | 外部载荷（自包含 HTML） | **不建立**同步目标 | 新增文档 |
| **导出** | 面向受众格式的产物（HTML / DOCX / PDF / MD / ZIP） | 写产物文件，不写源 | 否 |

关键区分：**草稿是唯一的存放处**，自动持久化；文件只是同步目标。没有同步目标的文档（导入的、Web 端的草稿）保存时只有落草稿一步。

**另存为产生的是另一个文档**：新文件绑定新文档，新文档一开始就是"已同步"；旧文档继续同步它自己的文件（或没有同步目标），两边互不影响。本轮只覆盖自包含 HTML 作为导入载荷。

### 2.2 界面上的状态：只有同步

草稿自动持久化、永远只有一份，因此**没有"草稿已保存"这个状态可表达**。界面要表达的是同步状态：

| 状态 | 含义 |
| --- | --- |
| 无同步目标 | 这个文档不与任何文件同步（导入的、Web 端的草稿） |
| 已同步 | 草稿与同步目标一致 |
| 未同步 | 草稿比同步目标新（当前修订 ≠ 上次同步的修订） |
| 同步失败 | 上一次同步没成功（原生侧写入失败等）。冲突里选"取消"不算失败——文档只是仍处于未同步 |

同步失败在界面上叫**保存文件错误**——它是"保存"这件事里唯一会失败的部分。文案要说清：草稿已经在本地工作区，失败的是**文件**。

### 2.3 未同步的判定

上下文记录 `lastSyncedRevision`：上次同步到文件时的文档修订。

- **打开时**置为 `document.revision`（内容本来就来自那个文件，此刻一致）；
- **同步成功后**置为 `document.revision`；
- 判定：`document.revision !== lastSyncedRevision` ⇒ **未同步**。

重新关联后无法证明一致时记 null，按未同步显示。

这与既有 `DocumentSession.dirty = document.revision !== savedRevision` 同形，只是基线从"应用草稿"换成"同步目标"。不另设 dirty 布尔量。

## 3. 授权与身份模型

### 3.1 唯一文件通道

原生文件能力只经 `files.rs` 的受守卫命令：

| 命令 | 作用 | 角色 |
| --- | --- | --- |
| `select_native_open` | 系统文件选择器 + 签发授权 | 读 + 写 |
| `select_native_save` | 系统保存对话框 + 签发授权 | 读 + 写 |
| `read_native_text` | 按 key 读文本（限 50MiB，严格 UTF-8） | 读 |
| `is_native_synced` | 按 key 问一句：**这个文件还是上次同步的那一版吗**。原生侧用它保存的摘要回答，摘要值不出原生侧（§3.4） | 读 |
| `write_native_bytes` | 按 key 写字节（限 100MiB，同目录临时文件 + rename）。**无条件写入** | 写 |
| `release_native_file` | 撤销授权 | — |

**为什么没有"带期望摘要的写入"**：覆盖是用户的明确选择（用草稿覆盖文件），它的语义就是"文件最后应当是草稿的内容"，因此写入不需要复核期望摘要，检测冲突靠 `is_native_synced` 的问答即可。少一个原语，也少一层"检查与替换之间"的窗口讨论（§6.1）。

`print_native_pdf` 同在此文件、同受守卫，但属 PDF 交付路径，约束见导出契约，不在本文范围。

**冲突检测必须在原生侧完成。** §6.1 要问的是"文件还是上次同步的那一版吗"，这条判断若放在应用侧（先把摘要读上来再比）就等于让摘要值跨过原生侧 boundary，与 §3.4 相悖。所以原生侧提供的是一句问答（`is_native_synced`），应用侧既拿不到摘要，也不需要自己比。

**不引入 JS 插件通道。** 插件命令（文件读写、对话框）的授权由应用能力清单承担，而本项目的隔离层是 Rust 来源守卫；引入插件通道等于再加一道闸，且新增的那道正是本仓已判定"不构成隔离"的 ACL 层（探针阶段记录 D0-3）。

### 3.2 授权的形态

- 授权 key 是随机 UUID，与路径无算术关系；前端拿它无法反推路径。
- **角色**：打开用户选中的文件时签发的授权**具备读与写两种能力**。写能力只在用户显式触发保存/另存为时使用；建立授权本身不写任何字节。约束由"同一文件的读写分离"改为"**不同文件**之间的分离"——只读选择的文件不会被写。
  - 原生侧改动：`FileAccess::path(key, writable)` 的角色判定由"必须相等"改为"要写必须可写；要读时可写蕴含可读"（当前实现 `grant.writable != writable` 会把可写授权挡在读路径外）。
- 授权在进程内有效。进程结束即失效，不落盘。
- 撤销走 `release_native_file`，在在途使用结束后调用。

### 3.3 文件身份（会话内）

**定义**：原生侧维护"规范化路径 → 随机 token"的映射；同一文件在本次进程内被多次选中，token 相同。token 是随机的，不是路径的摘要。

**为什么不做路径摘要**：

- 路径熵低（家目录 + 少数文件名），摘要可被字典枚举还原，等于把"路径不出原生侧"削弱成"需要暴力枚举才能反推"；
- 字符串规范化规则在大小写不敏感文件系统上会误折叠（`A.md` 与 `a.md` 在 Linux 是两个文件，在 Windows/macOS 常常是同一个），而跨平台规范化规则又被本设计明确拒绝制定。

**用途**：只用于**去重与聚焦**（§5.2）。同步永远按授权里原生侧保存的实际路径执行，不由前端 token 推导。

**跨会话**：本期不承诺。重启后绑定不恢复（§4.3），身份也随之作废。将来若要跨会话匹配，应使用 OS 级文件身份（Windows: 卷序列号 + 文件索引；POSIX: `st_dev` + `st_ino`），而不是字符串规范化。

**原生侧改动**：`FileAccess` 增加"规范化路径 → token"的映射；`SelectedFile` 增加 `identity` 字段。

> 术语消歧：本文的"文件身份"与来源守卫语境下的"**宿主身份**"（window/webview label 配对）不是同一维度。宿主身份决定"哪个 webview 在说话"，文件身份决定"这是哪个文件"。

### 3.4 跨运行时原语：一处实现、一处事实

摘要、字节比较、预算记账这类跨运行时用到的原语，**每个运行时只留一份实现，同一个事实也只存一处**。

| 原语 | 应用侧 | 原生侧 |
| --- | --- | --- |
| 字节摘要 | `src/core/platform/crypto.ts` 的 `sha256Hex`（SubtleCrypto，回落 hash.js）——资产校验已经在用它 | `sha2` 已是依赖；把 `pdf_print.rs` 里私有的 `file_sha256` 提升为共享模块（如 `src-tauri/src/hash.rs`），供 PDF 留证与文件摘要命令共用 |
| 磁盘内容的摘要 | **不存**，也拿不到值。只问一句"还是上次同步的那一版吗" | 随授权保存（它拥有路径与字节） |
| 字节比较 | 不做 | 提交前的复核与冲突判定都在原生侧 |
| 预算记账 | 只声明上限 | 剩余预算由原生侧算（只有它知道读了多少），应用侧把剩余量作为参数传下去（§7.5） |

规则：**应用侧不留原生侧拥有的事实的副本。** 副本要同步；同步一旦失败，它会以"误判冲突"或"误判未变化"的形式出现在用户眼前——§6.1 的同步判定与 §5.2 的"磁盘已变化"判定都建立在这类事实上。

## 4. 文档绑定模型

### 4.1 文档-文件上下文

一个文档与磁盘的关系，是**一份上下文**，不是一袋字段。上下文分三个面：绑定（identity）、一致性（sync）、资源（resources）。

```ts
interface DocumentFileContext {
  documentId: string;
  identity: {
    fileIdentity: string;      // 会话内文件身份（原生侧随机 token，§3.3）
    key: string;               // 原生授权 key（打开时签发；具备读与写两种能力）
    displayName: string;       // 文件名（原生侧给出）
    displayPath?: string;      // 人类可读的定位串（可选，仅展示）
    sourceFormat: 'markdown' | 'editable-html';
  };
  sync: {
    lastSyncedRevision: number|null;  // 上次同步到文件的修订；无法证明一致时为 null
    conflict: null | {                // 同步时发现文件已被外部改动
      kind: 'diverged';
    };
  };
  resources: {
    snapshot: AssetSnapshot|null;   // 已解析的本地资源快照（§7.1）
  };
}
```

- 存放位置：应用层会话状态，**不持久化**。
- `displayPath` 是展示串，不是标识符，不可用于寻址，也不再回传原生侧。
- **上下文里没有摘要**：磁盘上是什么由原生侧回答（§3.4）。
- **上下文里没有待处理资源计数**：那是 `snapshot` 的派生量，界面直接读快照，不必留一份会过期的副本。
- `sync.conflict` 落在数据上，"文件已被外部改动"才有确定的状态；它的解法只有两个：**覆盖**与**放弃**（§6.1）。

### 4.2 为什么不进文档

`DocumentRecord` 会作为载荷被携带（导入的自包含 HTML 里就有完整文档记录），导出时也会把资产清单整体嵌进产物。把路径或 key 写进去，等于让本机路径随文档离开这台机器，也让"源附件里的路径"看起来像授权。（`documentSchema` 的 `meta` 是 passthrough，额外字段会被保留——所以挡住它的不是 schema，是载荷会外传这件事。）

### 4.3 转移

上下文的每一次变化都是一次**具名转移**。每个转移写明读什么、写什么、哪些不变量保持。

| 转移 | 读 | 写 | 不变量 |
| --- | --- | --- | --- |
| `save` | 当前源快照 | 草稿落 IndexedDB（**所有文档都一样**） | 草稿永远只有一份；不因有无同步目标而分叉 |
| `open` | 选择结果 | 草稿载入；identity 就位；`sync.lastSyncedRevision = document.revision`；`resources.snapshot = null` | 打开不同步（§5.1）；刚打开不显示未同步（§2.3） |
| `sync` | 当前源快照 | 同步到文件；成功后 `sync.lastSyncedRevision` = 写出的冻结修订 | 失败不改草稿，只报**保存文件错误**；同步期间的新编辑仍算未同步 |
| `pull` | 文件的当前内容 | 反向同步：草稿取文件的版本；`sync.lastSyncedRevision` = 该版本 | 只在草稿自上次同步后未改动时发生（§6.1） |
| `resolve-conflict` | `sync.conflict` | 三选一：覆盖（正向，草稿胜出）/ 放弃（反向，文件胜出）/ 取消（两边都不动） | 覆盖后 `lastSyncedRevision` = 写出的冻结修订；放弃后草稿取文件的版本并同步基线；取消后仍是未同步，下次保存还会问 |
| `save-as` | 选择结果、冻结的源快照 | 写出新文件并**新建文档**绑定它 | 旧文档不受影响；新文档初始即已同步（§2.1） |
| `re-associate` | 选择结果 | identity 更新；无法证明与某个文档修订一致时 `sync.lastSyncedRevision = null` | 不读盘覆盖草稿；关联不算同步（§2.3） |
| `refresh-assets` | 资源集合 | `resources.snapshot` 整体替换（失败项不沿用旧字节） | 迟到结果不覆盖新快照（§7.7） |

换文档时上下文的 `documentId` 变了 ⇒ 三个面全部重置（§2.2、§5.2）；侧栏页签切换不换文档，上下文保留。

## 5. M4：打开与拖放接会话

### 5.1 流程

```
用户触发打开
  → select_native_open（系统选择器；多选）
  → 返回 NativeSelection[]：{key, identity, name, size, displayPath?}
  → 交给 SourceImport 批次（read 端口换成 read_native_text）
       逐个文件：读文本 → 扩展名/大小/NUL/UTF-8 校验 → schema 解析
                → 资产校验 → open（新增或聚焦）
  → 逐项处理：该项成功即建立绑定；失败项不建
  → 释放未被采用的授权
```

- 校验与内容去重复用 `SourceImport` 已有的实现，**不在 UI 侧另写一套**。
- 原生读取的字节上限（50MiB）与 Web 端 `SourceImport` 的上限（`50 * 1024 * 1024`）字节一致，两端不会因为来源不同而给出不同的可导入集合。
- 批次内某一项失败不影响其他项。
- 打开**不**自动触发同步，也不改变草稿状态。

**三类 key 的处置**：绑定采用的保留；去重命中（未建新绑定）的立即释放；导入失败的立即释放。

### 5.2 聚焦与"磁盘已变化"

同一 `fileIdentity` 已有绑定时：**聚焦该标签页**，不新建文档，不覆盖磁盘内容，不清未同步提示。

聚焦时向原生侧问一句：**这个文件还是打开时的那份吗**。原生侧用授权里保存的摘要回答，应用侧不留副本（§3.4）。

- 是 ⇒ 直接聚焦；
- 否 ⇒ 提示"磁盘上的文件已变化"，由用户决定是否重新载入；**不静默覆盖**内存中的修改。

"未同步"与"磁盘已变化"是两个独立条件：前者来自修订比较（应用侧），后者来自原生侧的问答（§3.4）。

### 5.3 去重的优先级

现有 `SourceImport` 的去重是"同名 + 内容 SHA-256"（`markdownKey`），HTML 路径完全不去重。这与文件身份是**两个维度**，需要定优先级：

1. **文件身份优先**：同一 `fileIdentity` ⇒ 一律聚焦既有标签页（即使磁盘内容已变，也走 §5.2 的提示分支，不静默新建）。
2. **内容哈希降为二级**：同名同内容 ⇒ 复用同一文档 id（既有行为，保留）。
3. **HTML 路径**：不走去重，按 §5.1 正常新建（可编辑 HTML 的内容键与文件身份不可比）。

实现落点：`SourceImportPorts` 增加一个身份端口（或在 `open` 端口旁增加 `focus` 端口），`ImportItemResult` 增加"磁盘已变化，需确认"这一态。`src/application/workspace/sourceImport.ts` 因此**在改动面内**。

### 5.4 拖放

拖放与文件选择进入**同一个** `SourceImport` 批次，不另开一条路径。拖放同样只拿到授权与身份，不拿路径。

拖放产生的文件身份必须与选择器一致（同一原生来源），否则"拖进来的是刚才打开的那个文件"这种去重会失效。

### 5.5 重新关联

父计划 M4 的验收含"重新关联入口"。定义：

- 入口：桌面端打开文件时，若选中的文件命中一个**已存在的绑定**（同 `fileIdentity`），提示"这是上次编辑的 `<文件名>`，要恢复关联并同步吗 / 重新载入吗"。
- 重新关联**不读盘覆盖草稿**：草稿内容保持不变，只把绑定指回该文件；建立授权本身不算同步。
- 取消 / 失败不改变草稿、修订或编辑状态。
- 匹配依据是 `fileIdentity`（会话内 token）。**重启后不恢复**，所以跨重启的重新关联本期不做（§13）。

## 6. M5：同步

### 6.1 同步是保存的第二步

保存对所有文档都是同一个动作：**落草稿**，然后（有同步目标时）**同步一步**。草稿自动持久化、永远只有一份；同步失败不影响草稿。

**一次保存 = 一个源快照**：草稿与文件写的是同一份字节，两者不会差一个按键。

**顺序：先草稿，后同步。** 草稿落盘成功才做同步；同步失败 ⇒ 草稿已在，工作不丢，只是文件没跟上。

同步的完整流程：

1. 冻结文档 ID、修订、待写源字节与当前上下文的 identity（§4.3）。对同一目标串行处理。每次同步记录绑定实例标识，回填结果前核对文档 ID 和绑定实例；失效结果只报告原目标的实际结果，不能更新当前上下文。
2. 落草稿（IndexedDB）。**这一步对所有文档都一样**，没有同步目标的文档到此结束。
3. 有同步目标时，向原生侧问一句：**这个文件还是上次同步的那一版吗**（`is_native_synced`，摘要不出原生侧，§3.4）。
   - **是** ⇒ 正向同步：把冻结的源字节写进文件（同目录临时文件 + rename）。成功后 `sync.lastSyncedRevision` = 写出的冻结修订。
   - **否**，文件被外部改过 ⇒ 分两种：
     - **草稿自上次同步后没有改动**（`document.revision === lastSyncedRevision`）⇒ 这不是冲突，是一次更新：**反向同步**——把文件的当前内容读回草稿，`lastSyncedRevision` 随之更新。
     - **草稿也改过** ⇒ 冲突，建立 `sync.conflict` 并提示。**三个选择**：
       - **覆盖**（正向同步，草稿胜出）：用草稿无条件写进文件，文件的外部改动被丢弃；`lastSyncedRevision` = 写出的冻结修订；
       - **放弃**（反向同步，文件胜出）：草稿的本地改动被丢弃，草稿取文件的版本；`lastSyncedRevision` 随之更新；
       - **取消**：两边都不动。草稿保留本地改动，文件保留外部改动，文档仍是"未同步"，下次保存还会再问。
4. 写入失败（原生侧报错、授权失效、目标消失）⇒ 报**保存文件错误**，草稿不动，绑定不变。

**不做行级冲突解决，也不做三方合并。** 覆盖与放弃是同一件事的两个方向（§0），取消是不做；除此之外没有别的出口。覆盖的语义是"这个文件最后应当是草稿的内容"，因此写入是无条件的：不需要"带期望摘要的条件写"，也不需要"重试一次"的机制——覆盖之后文件就是草稿的样子，若此后又被外部改动，那是下一次同步要面对的事。

**搁置**：冲突里"把草稿另存到第三个文件、两边都留下"这个出口本期不做（§13）；本期只有上面三个选择。

写入内容随源格式而异：Markdown 文档写原始 Markdown 字节，不写渲染结果；可编辑 HTML 文档写其源载荷，不写 Markdown 覆盖。

**字节保真（已知限制）**：原生读取会剥掉 UTF-8 BOM，编辑器的值把 CRLF 规范化为 LF，因此同步出去的文件是**无 BOM 的 LF**。对原本是 CRLF 的 Windows 文件，这是一次全文件差异。本期不保真换行风格，也不弹提示——但这条要写进设计，别在验收时当缺陷。

### 6.2 另存为

另存为**产生另一个文档**：

1. `select_native_save`（带建议文件名，文件名规则复用导出契约的完整名与扩展名）。
2. 用户取消 ⇒ 无新授权，无任何状态变化。
3. 写出成功后**新建一个文档**绑定该文件，初始 `lastSyncedRevision` = 写出的修订（即已同步），并切换过去。**旧文档不受影响**：它继续同步它自己的文件（或没有同步目标），两边互不相关。

**跨目录的相对引用（已知限制）**：正文里的相对图片引用（如 `![](images/a.png)`）在源快照语义下**不被改写**。另存到另一个目录后，这些引用在新位置会失效。写入的 .md 仍然只含相对引用，路径语义由新目录决定。

因此另存为必须提示这一点，并提供两个可选项（本期只提示，不自动处理）：

- 接受：新目录下的相对引用按新位置解释（可能裂图）；
- 或先在原目录另存，再手动搬运资源。

把资源一并写出（定义资源目录布局）或把引用改写为绝对/内联，属于后续能力，本期不做（§13）。

### 6.3 显式动作与快捷键

快捷键（`Ctrl/Cmd+S` 保存、`Ctrl/Cmd+Shift+S` 另存为、`Ctrl/Cmd+O` 打开）**只触发与按钮完全相同的动作**，不构成第二条路径，也不允许绕过"没有同步目标时保存只落草稿"的判定。

### 6.4 "保存"只有一个意思

顶栏的"保存"按钮在两端是**同一个动作**：落草稿，有同步目标时再同步一步。桌面端不再有另一个"保存"（写回文件）的意思——**同步是保存的一部分，不是另一件事**。

- 有同步目标 ⇒ 保存 = 草稿 + 同步；
- 无同步目标（导入的、Web 端的草稿）⇒ 保存 = 草稿。

状态区只显示**同步状态**（§2.2），两端同一套文案；没有"草稿已保存"这一行，因为草稿自动持久化，没有这种状态可表达。

## 7. M6：本地资源

### 7.1 解析与内联的落点

本地图片在**渲染/准备期**解析并内联，落点是 `collectAssets` 的一个**本地读取端口**：

```
collectAssets(html, existing, allowRemote, local?)
  …遇到既不是 data:、也不是 http(s)/blob: 的 src…
  现在：直接抛错「无法读取本地相对图片，请先导入资产」
  改后：有 local 端口 ⇒ 解析并读取字节；没有 ⇒ 照旧抛错（Web 端行为不变）
```

现有 A4 预览、导出准备和 Markdown 打包使用 collectAssets。流式预览当前只应用已提供的资产，M6 须补上资产准备入口。四条路径共用读取、校验和快照规则。

资产快照是上下文 **resources 面的一部分**（§4.1），随当前文档会话保存在内存，包含引用原文、已验证字节、摘要及逐项失败状态。首次准备与引用集合变化时构建快照，未变引用可复用当前授权下的既有结果。流式和 A4 预览使用同一快照。接受导出操作时冻结文档修订和不可变的资产快照。若准备仍在进行，则固定该次准备任务及其结果，刷新不得替换此引用。HTML 系列由 prepare 消费冻结输入，Markdown 打包直接由 generateMarkdownBundle 消费相同输入。纯 Markdown 源输出只消费源快照。需要资产的路径在快照尚未完成时等待该次准备，后续编辑或刷新不改变已冻结的导出输入，也不为导出另行重读磁盘。无法取得对应快照时明确失败。

快照的失败项计数是它的**派生量**，不另存副本（§4.1）；界面直接读快照。

### 7.2 资产键

**`asset.source` = 文档里的引用原文，逐字节不变。** 路径解析只在原生侧进行，解析结果不进入 `source`。

全链路都按 `a.source === 引用原文` 精确匹配（`collectAssets` 查既有资产、`applyDocumentAssets` 回填预览、`markdownBundle` 写 manifest），键若变成解析后的绝对路径，预览会全裂、导出会报错，且本机路径会随产物外传。

`assetSchema` 要求 `source` 在非 `data:` 时长度 ≤ 4096 —— 相对引用天然满足。

### 7.3 绝对路径引用：首版不支持

`![图](C:\pics\a.png)` 这样的引用**首版不支持**，理由有二：

- 净化器会丢弃该属性：`safeUrl` 对 `^[a-z][\w+.-]*:` 判非法（`src/core/policy/htmlRules.ts:17`），`C:` 命中，属性被整条移除，图片连"不可用"的提示都到不了资产层；
- 绝对路径会随文档与产物外传，与 §10 第 5 条冲突。

支持它需要一套"先解析、后净化"的顺序，属于额外能力，本期不做（§13）。首版支持的是**相对引用**（`./`、`../`、同级目录）。

### 7.4 路径解析与目录授权

```
外链或内联（http/https/data:/blob:） → 原样保留
其余引用（相对路径）
  ├─ 有绑定 ⇒ 以绑定所指文件的所在目录为基准解析
  │            解析结果必须落在已授权目录范围内
  └─ 无绑定 ⇒ 不解析，记为待处理
```

- 基准目录来自绑定所指的原生侧位置，**不作为路径回传前端**。
- **目录授权**：打开文件时为所在目录签发会话内只读授权，覆盖普通子目录中的文件。拒绝绝对路径、越界路径及路径组件中的符号链接和 Windows 重解析点，目录内指向目录内的链接也拒绝。原生侧从授权目录解析和打开，读取前确认实际打开对象符合授权，读取使用同一对象句柄。仅比较 realpath 或先检查路径再按字符串重新打开均不足。无法可靠执行上述约束的平台暂不启用本地资产读取。
  - **基线目录取打开文件的 realpath 目录**，符号链接与重解析点的检查只针对**该目录以下**的路径组件。基线目录自身可能经由系统符号链接（macOS 的 `/tmp` → `/private/tmp`、`/var` → `/private/var`），那是文件系统布局，不是被授权对象的逃逸；若把检查扩到基线之上，macOS 上从这些目录打开的文档会读不到任何本地图片。
- 解析不出或越权的引用按"资源不可用"处理：给出可理解的提示，不静默裂图，也不把失败伪装成空图。这类引用的数量由资产快照派生（§4.1 的 resources 面），状态区显示"有 N 处本地图片未能解析"。

### 7.5 预算与外链

- **预算**：打开 Markdown 时不读取图片。流式和 A4 预览准备以及导出准备沿用 128 项、单项 10 MiB、累计 25 MiB 的限制和既有 MIME、签名、SHA-256 校验。原生侧在分配或完整读取前检查可用预算，并按剩余预算限量读取，防止文件在读取期间增大。预览保留成功资源，对超限资源显示占位和原因，A4 仍可排版。需要这些资源的导出明确失败，不产出缺图文件。仅保存源文本的操作沿用源快照规则。
  - 因此本地读取端口的调用要**携带剩余预算**（`maxBytes`）：原生侧无从自行知道"还剩多少可用"，没有这个参数就只能整份读回再判断，限量读取也就无从谈起。
- **外链仍按导出期策略**：`allowRemote` 为假时外链图片在导出时报错，与今天一致。"渲染只读文档内数据"只对**本地**资源成立。

### 7.6 资源类型边界

现有 `documentSchema` 的资产 MIME 白名单是 `png / jpeg / gif / webp / avif`。**不扩张**（含 SVG）。内联 SVG 里引用的位图（`svg image`）是既有支持，不受影响。

本地 SVG 引用按"资源不可用"处理并提示。SVG 的导入路径需要单独的设计与安全评估，不在本轮。

### 7.7 重新读取资源

磁盘变动由显式“重新读取资源”触发。刷新期间可显示旧预览并标注刷新中，新结果按整份快照替换，失败项不沿用旧图片。重新关联、授权失效或关闭文档时使旧上下文失效，废弃迟到结果，不再从旧授权读取。快照的内容摘要和失败状态进入预览身份，并按会话资产上下文隔离缓存。导出复用已冻结的字节。若所需读取尚未完成且授权失效，明确失败。

不做后台磁盘监视。

## 8. UI 规格

### 8.1 入口

文档相关的入口**留在侧栏**（现状位置：`Sidebar.tsx` 的"新建/导入"操作条），不另在顶栏开一套：

| 环境 | 操作条 | 下拉项 |
| --- | --- | --- |
| 桌面端 | **打开**（系统选择器）/ 导入 | 打开本地文件… / 导入自包含 HTML… |
| Web 端 | **导入**（浏览器选择器） | 导入本地文件… / 导入自包含 HTML… |

Web 端现有的单一文件输入 + 按扩展名分流（`sourceImport.ts`）保持不变；桌面端的"打开"走原生选择器（过滤器含 `md` / `markdown` / `txt` / `html` / `htm`）。

> 注意：文件对话框会展示 `.html`，但只有**含自包含载荷**的 `.html` 能被解码；普通手写 HTML 会在导入时报"HTML 没有有效源载荷"。这个差异要在选择器附近有一句说明，或在失败提示里讲清楚。

### 8.2 顶栏

- 桌面端：`保存` = 落草稿 + 同步（有同步目标时），旁边一个 `另存为`。
- Web 端：`保存` 不变（保存草稿）。

### 8.3 文档标题区

- 已关联：显示文件名；`displayPath` 存在时以次要样式显示定位串。
- 未关联：显示标题，不显示路径占位。
- 未同步：标题旁显示标记，悬浮提示"本地文件有未同步的修改（Ctrl/Cmd+S）"。
- 不在标题上显示"已保存至磁盘"这类含混措辞：草稿与原文件两个维度分别表达。

### 8.4 状态区

按 §2.2 的两个维度分别给一行，桌面端显示，Web 端只显示草稿维度。

### 8.5 提示文案

| 情形 | 文案要点 |
| --- | --- |
| 用户取消选择 / 另存为 | 中性陈述，不出现"失败" |
| 写盘失败 | 说明原文件未被改动 |
| 同步时发现文件已被外部改动 | 说明应用外有改动，请选择**覆盖**（用草稿覆盖文件）、**放弃**（用文件覆盖草稿）或**取消**（两边都不动，下次再问） |
| 保存文件错误 | 说明草稿已在本地工作区，失败的是文件；给出重试入口 |
| 另存为跨目录 | 提醒相对图片引用会按新位置解释 |
| 关联已失效（读/写失败且原因是目标不存在） | 说明关联失效，可重新关联或另存为 |
| 来源守卫拒绝 | 友好提示，不暴露内部标识 |
| 资源不可用 | 指出是哪一处引用、为什么不可用 |

### 8.6 视图模型：界面读上下文的哪些字段

界面不自己判断，只读由上下文派生出来的视图模型。每一处显示都写明它读什么，避免各处各判一遍。

| 界面位置 | 读什么 |
| --- | --- |
| 顶栏"保存" | 同一个动作：落草稿；有同步目标时再同步一步。按钮的可用性由是否有待决定的冲突决定 |
| 标题区 | `identity.displayName` / `identity.displayPath`；未同步标记 = 当前修订 ≠ `sync.lastSyncedRevision` |
| 状态区 | **只有同步状态**（无同步目标 / 已同步 / 未同步 / 同步失败，§2.2）。没有"草稿已保存"这一行 |
| 冲突提示 | `sync.conflict` 存在时才出现；三个按钮：**覆盖**、**放弃**、**取消** |
| 待处理资源 | `resources.snapshot` 的失败项计数（派生量，不另存副本） |

界面不读摘要，也不读路径以外的事实：那些由原生侧回答（§3.4）。

## 9. 回执与错误

原生命令的返回在应用层分三类，不混用：

| 类别 | 判定 | 对状态的影响 |
| --- | --- | --- |
| 取消 | 用户在系统对话框取消（原生侧返回"未选"） | 无 |
| 失败 | 操作未完成且原因不是取消 | 上下文与未同步状态不变 |
| 拒绝 | 来源守卫拒绝 | 与失败同样处理，文案区分（内部条件，不是用户操作问题） |

**取消在原生侧是可区分的**：`blocking_pick_files` / `blocking_save_file` 返回"未选"，与错误是两条路径。但要在应用层保住这个区分，需要两处改动：

1. **稳定码枚举化**。现在原生侧把所有 IO 失败塌缩成一个码（`files.rs` 的 `error()` → `native-io-failed`），前端只能靠**子串匹配**识别拒绝（`files.ts:15` 的 `String(error).includes(SOURCE_DENIED)`）。应改为：前端拿到结构化的机器码 + 友好文案两层，拒绝不再靠子串；原生侧细分失败原因（目标不存在 / 权限 / IO / 超限 / 目标不是普通文件），否则 UI 无法区分"文件被移走"与"磁盘写不进去"。
**稳定机器码清单**（原生侧给出，前端按码映射文案；两边必须同步改）：

| 机器码 | 含义 | 前端文案 |
| --- | --- | --- |
| `native-source-denied` | 来源守卫拒绝 | 当前窗口无权使用原生文件能力 |
| `native-target-missing` | 目标不存在 | 文件已被移走或重命名 |
| `native-permission-denied` | 权限不足 | 没有权限访问这个文件 |
| `native-io-failed` | 其余 IO 失败 | 文件读写失败 |
| `native-dialog-failed` | 系统对话框自身故障（**与取消不同**） | 系统文件对话框打不开 |
| `native-internal-failed` | 内部状态不可用 | 文件能力暂时不可用 |
| `file-too-large` | 超过大小上限 | 文件超过可处理的大小上限 |
| `invalid-utf8` | 不是合法 UTF-8 文本 | 文件不是合法的 UTF-8 文本 |
| `not-a-file` / `not-a-regular-target` | 目标不是普通文件 | 目标不是一个普通文件 |
| `unknown-file-key` | 授权不存在或已释放 | 这个文件的授权已经失效 |
| `file-capability-mismatch` | 能力不符 | 这个文件不允许这样操作 |
| `invalid-file-name` / `invalid-target` | 名字或路径不可用 | 文件名无法读取 / 目标路径无效 |

取消仍然**不是错误**：选择器返回"未选"（`Ok(None)`），没有机器码 ✓（§12.5 把 macOS / Linux 的对话框语义留给 M10 验证 ✓）。

2. **跨平台语义需验证**。Linux（xdg portal）与 macOS 的对话框实现有可能把"对话框失败"也折叠成"未选"。§12.5 把 macOS/Linux 推给 M10，但"取消必须是取消"这条语义不能默认成立——需在对应平台各验一次。

"关联已失效"只在读/写失败且原因为"目标不存在"时标记；不做后台监视（§13）。

## 10. 隔离与安全边界

1. 文件能力只有 `files.rs` 一个来源，受 `source_guard` 单闸保护。
2. 不新增能力清单文件；新增受保护命令不改变允许范围（仍是 main/main），只扩大命令集合。
3. 不引入全盘读取范围：读取范围是"用户本次选择的文件，以及打开时同时授权的其所在目录"。
4. 授权 key 与文件身份 token 都不落盘、不进文档、不进日志（除必要的命令名与字节数）。
5. 路径不出原生侧；日志不记路径。
6. 应用不引入任意路径读写命令（"前端给个路径就读写"是禁止的形态）。
7. 目录授权及同一对象句柄读取按 §7.4 执行。

## 11. 可观测性

- **同步与读取的结果已经有日志**：`write_native_bytes` / `read_native_text` 等命令在命令 span 内记 `source_decision` 与 `operation_result`（含字节数与原因码）。这部分不需要新做。
- **绑定的建立与释放是应用层状态**，原生侧的页面可回传事件是封闭枚举（`page_ready` / `call_started` / `call_finished` / `page_error`），没有承载位；原生侧也不知道绑定（绑定是应用层概念）。
  ⇒ **本期不把绑定生命周期记进原生日志。** 若要可观测性，先扩日志契约（`log-base-plan` §5.1 / §5.2 的 span 词汇与事件集），那是独立一步，不在本设计内。

## 13. 明确不做

- 不引入本地路径协议（`asset:` 之类）与相应协议白名单。
- 不引入全盘读取范围（能力清单的通配 scope）。
- 不引入 JS 插件文件通道。
- 不扩张资产 MIME 白名单（含 SVG）。
- 不支持绝对路径引用（首版）。
- 不做跨重启的绑定恢复，也不做跨会话的文件身份匹配。
- 不做后台磁盘监视；资源变化靠显式重读。
- 不做"应用给个路径就读写"的命令形态。
- 不在路径上做跨平台规范化规则的通用库；规范化由原生侧完成。
- 不把资源一并写出到另存为的目标目录（§6.2）。
- 冲突里"把草稿另存到第三个文件、两边都留下"的出口本期不做（§6.1）；本期只有覆盖、放弃、取消三个选择。
- 不在无法可靠执行同句柄读取与链接拒绝约束的平台上启用本地资产读取（§7.4）；这类平台是**能力缺席**，不是降级实现，M10 的支持表须按平台分别声明。

2026-11-06 同步模型重构后修订。主要改动：
