### 1.2 本文覆盖

M4（打开与拖放接会话）、M5（原文件保存）、M6（本地资源）的**产品语义、状态模型、授权模型、UI 规格、验收条目**。不改写既有契约，只在其上补足实现前必须定下的设计。

### 1.3 不变量

1. 应用层不持有路径。路径只在原生侧；前端只拿不透明 key 与展示用字符串。
2. 绑定是**会话内状态**，不是文档数据。不进 `DocumentRecord.meta`，不进 `documentSchema`。
3. 草稿自动持久化不覆盖磁盘原文件；原文件写回只能是显式动作。
4. 不新增隔离层。文件能力仍只经 `files.rs` 的受守卫命令。
5. 不引入第二个文件通道（JS 插件、Node fs、原生扩展）。
6. 取消不是失败；失败不改绑定、不清未写回提示。
7. Web 端行为不变：桌面端能力在 Web 端缺席时降级为原有导入/下载路径，不报错。

## 2. 语义模型

### 2.1 四个用户动作

| 动作 | 作用对象 | 与磁盘的关系 | 是否改变工作区 |
| --- | --- | --- | --- |
| **打开** | 本地磁盘上的 `.md` / `.markdown` / `.txt` / 可编辑 `.html` | 建立只读授权 + 会话绑定；记录"这个文档来自哪个文件" | 新增文档或聚焦已有文档 |
| **另存为** | 当前文档 | 写出到新路径；成功后把绑定改指新路径 | 否 |
| **导入** | 外部载荷（自包含 HTML、剪贴板文本） | **不建立**文件关联 | 新增文档 |
| **导出** | 面向受众格式的产物（HTML / DOCX / PDF / MD / ZIP） | 写产物文件，不写源 | 否 |

关键区分：**导入与打开都会把内容载入工作区，但只有打开与磁盘建立了关联**。导入的内容没有"原文件"，因此没有"原位保存"，只有"另存为"。

### 2.2 两个正交的状态维度

草稿状态与原文件状态是**两件事**，UI 必须分开表达，不能用一个"已保存/未保存"覆盖：

| 维度 | 取值 | 含义 |
| --- | --- | --- |
| 草稿 | 已持久化 / 待持久化 | 应用内草稿是否已写入应用存储（现有自动持久化） |
| 原文件 | 未关联 / 已关联未写回 / 已关联已写回 / 关联已失效 | 与磁盘原文件的关系（本文新增） |

"已关联已写回"只在**本次会话**内可能成立。重启后一律回到"未关联"，UI 显示"草稿已恢复，未关联本地文件"。

### 2.3 未写回的判定

绑定记录 `writtenRevision`（最近一次成功写回的文档 revision）。当 `document.revision !== writtenRevision` 时为"已关联未写回"。判定只看 revision，不另设 dirty 布尔量——避免与草稿状态混用。

## 3. 授权与身份模型

### 3.1 唯一文件通道

原生文件能力只经 `files.rs` 的受保护命令：

| 命令 | 作用 | 角色 |
| --- | --- | --- |
| `select_native_open` | 系统文件选择器 + 签发只读授权 | 读 |
| `select_native_save` | 系统保存对话框 + 签发写授权 | 写 |
| `read_native_text` | 按 key 读文本（限 50MiB，严格 UTF-8） | 读 |
| `write_native_bytes` | 按 key 写字节（限 100MiB，同目录临时文件 + rename） | 写 |
| `release_native_file` | 撤销授权 | — |

（PDF 交付路径由导出契约约束，不在本文范围。）

**不引入 JS 插件通道。** 插件命令（文件读写、对话框）的授权由应用能力清单承担，而本项目的隔离层是 Rust 来源守卫；引入插件通道等于再加一道闸，且新增的那道正是本仓已判定"不构成隔离"的 ACL 层（探针阶段记录 D0-3）。加第二道闸会让隔离结论与已验收证据分叉，收益不抵成本。

### 3.2 授权的形态

- 授权 key 是随机 UUID，与路径无算术关系；前端拿它无法反推路径。
- 读写角色分开：只读授权不能被写，写授权不能被当作读授权使用（原生侧按角色校验，不匹配时返回 `file-capability-mismatch`）。
- 授权在进程内有效。进程结束即失效，不落盘。
- 撤销走 `release_native_file`，在在途使用结束后调用。

### 3.3 稳定文件身份（**M4 的前置缺口**）

现有原语每次选择都签发新的 UUID key，因此**无法判断两个选择是否指向同一个文件**。而"重复打开同一文件应聚焦已有标签页，而不是新开一个"是本地文档支持的基本预期。

设计：在原生侧引入**稳定文件身份**——对规范化后的绝对路径做一次不可逆摘要（平台侧计算，不回传路径），随选择结果一起返回。

- 前端用该身份做去重键，与 `SourceImport` 现有的"内容哈希去重"并列：内容哈希识别"同一份内容"，稳定身份识别"同一个文件"。前者用于避免重复建文档，后者用于把既有绑定指回同一文件。
- 该摘要**不是授权**，不能用于读写；读写仍需每次选择的 key。
- 稳定身份同样只在进程内有效，不落盘、不进文档载荷。

## 4. 文档绑定模型

### 4.1 绑定记录

```ts
interface LocalBinding {
  documentId: string;
  fileIdentity: string;      // 稳定身份摘要（§3.3）
  readKey: string;           // 只读授权
  writeKey?: string;         // 写授权（另存为成功后才有）
  displayName: string;       // 文件名（原生侧给出）
  displayPath?: string;      // 人类可读的定位串（可选，仅展示）
  sourceFormat: 'markdown' | 'editable-html';
  writtenRevision: number | null;  // 最近一次成功写回的 revision
}
```

- 存放位置：应用层会话状态（与 `DocumentSessions` 同层），**不持久化**。
- `displayPath` 是展示串，不是标识符，不可用于寻址，也不再回传原生侧。

### 4.2 为什么不进文档

`DocumentRecord` 会作为载荷被携带（导入的自包含 HTML 里就有完整文档记录）。把路径或 key 写进去，等于让本机路径随文档离开这台机器，也让"源附件里的路径"看起来像授权。`documentSchema` 的 `meta` 有固定字段集，`passthrough` 只是为了不丢别处写的记录，不是给本机路径开的口子。

### 4.3 生命周期

| 事件 | 绑定变化 |
| --- | --- |
| 打开成功 | 建立只读绑定，`writtenRevision = null` |
| 写回成功 | `writtenRevision = document.revision` |
| 另存为成功 | 绑定改指新文件：`writeKey` 更新，`displayName` / `displayPath` 更新，源格式按用户选择，`writtenRevision = document.revision` |
| 另存为取消 / 失败 | 绑定不变 |
| 标签页关闭 / 窗口关闭 | 在途使用结束后释放授权 |
| 应用重启 | 全部绑定失效；草稿恢复为"未关联" |

## 5. M4：打开与拖放接会话

### 5.1 流程

```
用户触发打开
  → select_native_open（原生选择器；多选）
  → 返回 NativeSelection[]：{key, fileIdentity, name, size, displayPath?}
  → 交给 SourceImport 批次（read 端口换成 read_native_text）
       逐个文件：读文本 → 扩展名/大小/NUL/UTF-8 校验 → schema 解析
                → 资产校验 → open（新增或聚焦）
  → 全部成功后，为每个已打开文档建立只读绑定
  → 释放未使用的选择授权
```

- 校验与去重全部复用 `SourceImport` 已有的实现，**不在 UI 侧另写一套**。
- 原生读取的字节上限（50MiB）与 Web 端 `SourceImport` 的 50MB 上限一致，两端不会因为来源不同而给出不同的可导入集合。
- 批次内某一项失败不影响其他项；失败项不建立绑定。
- 打开**不**自动触发写回，也不改变草稿状态。

### 5.2 聚焦已打开的文件

同一 `fileIdentity` 已有绑定时：聚焦该标签页，**不**新建文档，**不**覆盖磁盘内容，**不**把未写回状态清掉。若该标签页有未写回修改，UI 明示"磁盘上的文件已变化，是否重新载入"，由用户决定；不静默覆盖内存中的修改。

### 5.3 拖放

拖放与文件选择进入**同一个** `SourceImport` 批次，不另开一条路径。拖放同样只拿到授权与身份，不拿路径。

拖放产生的文件身份必须与选择器一致（同一原生来源），否则"拖进来的是刚才打开的那个文件"这种去重会失效。

## 6. M5：原文件保存与另存为

### 6.1 写回原文件

显式动作，绑到现有会话的源保存路径，不新增写盘通道：

1. 取当前文档的源快照（`document.revision` 对应的 markdown 或可编辑 HTML 源载荷）。
2. 通过绑定的 `writeKey` 调 `write_native_bytes`。
3. 成功提交后：`writtenRevision = document.revision`。
4. 失败：原文件保持不变（`commit_bytes` 用同目录临时文件 + rename，目标失败不会留下半个文件），绑定不变，未写回提示保留。

写入内容随源格式而异：Markdown 文档写原始 Markdown 字节，不写渲染结果；可编辑 HTML 文档写其源载荷，不写 Markdown 覆盖。

### 6.2 另存为

1. `select_native_save`（带建议文件名，文件名规则复用导出契约的完整名与扩展名）。
2. 用户取消 → 无写授权，无任何状态变化。
3. 写出成功后更新绑定（§4.3）；失败或取消保留旧绑定、标题与状态。

### 6.3 显式动作与快捷键

快捷键（`Ctrl/Cmd+S` 保存、`Ctrl/Cmd+Shift+S` 另存为、`Ctrl/Cmd+O` 打开）**只触发与按钮完全相同的动作**，不构成第二条路径，也不允许绕过"未绑定即另存为"的判定。

### 6.4 关闭标签页

标签页存在未写回修改时，关闭必须提示，与草稿自动持久化的完成与否无关。

## 7. M6：本地资源

### 7.1 读取时机：导入期冻结，不在渲染期读盘

工作台显示的文档是一份已冻结的文档：资源在**打开/导入时**被读入、校验、内联为 `DocumentAsset`（data URL），此后渲染只读文档内的数据。

因此：

- 预览不需要任何本地路径协议，不需要在渲染时访问磁盘。
- 导出的产物自带资源，不依赖交付机器上有原图。
- 磁盘上的图片被修改后，已打开文档**不会**自动变化；需要显式的"重新读取资源"动作，重读后更新资源与配置版本。

这条选择同时避免了两个代价：一是把本地路径协议引入内容安全策略（需要放开协议白名单与全盘读取范围），二是让渲染结果依赖运行期磁盘状态（预览不可复现）。

### 7.2 路径解析

对 Markdown 中的图片引用：

```
外链或内联（http/https/data:/blob:） → 原样保留
其余引用
  ├─ 绝对路径 → 以授权目录为界解析，越界则拒绝
  └─ 相对路径 → 以当前文档所在目录为基准解析
                 无绑定（未关联本地文件）→ 不解析，记待处理
```

- 基准目录来自绑定所指的原生侧位置，**不作为路径回传前端**。
- 解析结果必须落在用户本次授权的目录范围内。
- 解析不出、或越权的引用，按"资源不可用"处理：给出可理解的提示，不静默裂图，也不把失败伪装成空图。

### 7.3 授权

M6 需要**目录级**授权，现有原语只覆盖单文件。设计上扩展原生侧：目录选择 + 只读授权签发；读取仍走受保护命令。

新增受保护命令必须同步：

- 进入 `logging::WebCommand` 枚举（漏了编译不过，命令名与页面回传的名字必然一致）。
- 补与既有五个命令**同等**的来源守卫证据。新命令不在 D1b 已验的集合内，属"未验"，须按同一口径取证后才算通过。

### 7.4 资源类型边界

现有 `documentSchema` 的资产 MIME 白名单是 `png / jpeg / gif / webp / avif`。**不扩张**（含 SVG）。本地 SVG 引用按"资源不可用"处理并提示；SVG 的导入路径需要单独的设计与安全评估，不在本轮。

## 8. UI 规格

### 8.1 顶栏

| 环境 | 主按钮 | 下拉项 |
| --- | --- | --- |
| 桌面端 | **打开** | 打开本地文件… / 导入自包含 HTML… |
| Web 端 | **导入** | 导入本地文件… / 导入自包含 HTML… |

下拉项在两端一致，差别只在第一项走系统选择器还是浏览器选择器。按钮文案随环境变，不并列两个含义重叠的主按钮。（从剪贴板导入等其它载荷入口不在本轮范围。）

### 8.2 文档标题区

- 已关联：显示文件名；`displayPath` 存在时以次要样式显示定位串。
- 未关联：显示标题，不显示路径占位。
- 未写回：标题旁显示未写回标记，悬浮提示"本地文件有未写回的修改（Ctrl/Cmd+S）"。
- 不在标题上显示"已保存至磁盘"这类含混措辞：草稿与原文件两个维度分别表达。

### 8.3 状态区

状态区按 §2.2 的两个维度分别给一行，桌面端显示，Web 端只显示草稿维度。

### 8.4 提示文案

| 情形 | 文案要点 |
| --- | --- |
| 用户取消选择 / 另存为 | 中性陈述，不出现"失败" |
| 写盘失败 | 说明原文件未被改动 |
| 绑定已失效（文件被移动/删除） | 说明关联失效，可重新关联或另存为 |
| 来源守卫拒绝 | 友好提示，不暴露内部标识 |
| 资源不可用 | 指出是哪一处引用、为什么不可用 |

## 9. 回执与错误

原生命令的返回码在应用层分三类，不混用：

| 类别 | 判定 | 对状态的影响 |
| --- | --- | --- |
| 取消 | 用户在系统对话框取消 | 无 |
| 失败 | 操作未完成且原因不是取消 | 绑定与未写回状态不变 |
| 拒绝 | 来源守卫拒绝 | 与失败同样处理，但文案区分（属内部条件，不是用户操作问题） |

关键：**"取消"与"失败"在 UI 上必须可区分**，否则用户会以为文件被改了。

---

## 10. 隔离与安全边界

1. 文件能力只有 `files.rs` 一个来源，受 `source_guard` 单闸保护。
2. 不新增能力清单文件；新增受保护命令不改变允许范围（仍是 main/main），只扩大命令集合。
3. 不引入全盘读取范围：读取范围是"用户本次选择的文件/目录"。
4. 授权 key 不落盘、不进文档、不进日志（除必要的命令名与字节数）。
5. 路径不出原生侧；日志不记路径。
6. 应用不引入任意路径读写命令（"前端给个路径就读写"是禁止的形态）。

---

## 11. 可观测性

新事件沿用既有命令 span 形态（`in_command_span`），不另造 span 模型：

- `source_decision`（allow / deny）与 `operation_result`（ok / error / denied）由守卫与命令体记录，**绑定生命周期事件另记**：`binding_created`、`binding_released`、`write_back_committed`、`write_back_failed`。
- 事件字段只记：文档 ID（应用层标识）、源格式、字节数、结果码。**不记路径、不记授权 key**。
- 事件命名沿用契约的最小原生事件集；新增事件名要同步进日志契约文档。

## 12. 验收

沿用 arch 的证据纪律：每阶段保存基线 SHA、实际变更、验证命令与输出、计数、真实文件路径与 SHA-256、未验项；自动替身、真实系统保存、干净机器开箱分别记录。

### 12.1 M4（打开与拖放接会话）

| 编号 | 断言 |
| --- | --- |
| M4-1 | 打开本地 `.md` 成功载入工作区，标题与内容一致 |
| M4-2 | 打开可编辑 `.html` 走 HTML 载荷路径，不按 Markdown 导入 |
| M4-3 | 非法 UTF-8 / 含 NUL / 超限文件被拒，且不建立绑定 |
| M4-4 | 同一文件重复打开聚焦既有标签页，不新建、不覆盖、未写回提示保留 |
| M4-5 | 多选批次中一项失败，其余项仍完成 |
| M4-6 | 拖放与选择器进入同一批次，去重行为一致 |
| M4-7 | 打开后不发生任何写回 |
| M4-8 | 关闭标签页后授权被释放 |

### 12.2 M5（原文件保存）

## 13. 明确不做

- 不引入本地路径协议（`asset:` 之类）与相应协议白名单。
- 不引入全盘读取范围（能力清单的通配 scope）。
- 不引入 JS 插件文件通道。
- 不扩张资产 MIME 白名单（含 SVG）。
- 不做跨重启的绑定恢复（延期；重启后一律"未关联"）。
- 不做后台磁盘监视；资源变化靠显式重读。
- 不做"应用给个路径就读写"的命令形态。
- 不在路径上做跨平台规范化规则的通用库；规范化由原生侧完成。
