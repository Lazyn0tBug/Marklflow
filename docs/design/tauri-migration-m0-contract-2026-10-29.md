### 3.1 静默PDF平台适配约定（2026-11-02）

- 同一冻结分页HTML与资源加载为专用WebView顶层文档，不以工作台/预览iframe可见DOM为源，不重复prepare、MathJax或Paged.js，不新增应用PDF预览。新宿主只布局现成产物，隐藏状态就绪与打印可靠性必须验证。
- Windows候选：隐藏WebView2 + PrintToPdf；原生端持有目标路径授权，ExportFile提供默认名。选择目标可显示，打印面板/输出宿主不显示；PrintToPdf完成成功只证明临时PDF输出，受控提交目标后才能saved。失败保护已有目标，清理临时文件。
- deliverPdf端口内部负责目标选择/取消、原生宿主、回调、临时文件与授权释放；不走ByteSaveTarget.save(Blob)伪装已有PDF字节，不改变字节格式端口。授权finally释放不掩盖主错误；源绑定授权不被误释放。
- 运行串行，沿用导出busy。超时/关闭不能让迟到回调提交目标或改变回执；终止/排空原生任务再安全清理的可行方式须PoC核实，不宣称原生计算可协作取消。等待字体、图片、布局而非固定睡眠；输出宿主不向用户内容开放一般IPC或本地路径权限。
- 前置D1在D0产物契约核对后做Windows小夹具，无需D2、完整EX-W3/M4—M7，不接生产UI，不要求全量历史回归先闭合。D7/M8在完整EX-W3/M7后验收命名/取消、同目录临时提交、覆盖失败保护、资源/超时/迟到回调与完整PDF；通过后D8/M9生产接入。此例外仅独立探索，不放行全部EX-T。
- 当前pdfExporter输出固化分页HTML，无Paged.js运行脚本；htmlPaginator在paged.preview完成后取页面与样式。waitForLayout等待图片/字体及双rAF，隐藏宿主不能直接照用后者；D1验证就绪，不等待不存在的第二次分页。
- PDF端口平台内部选择目标并交付，字节selectSave不参与，不拆两种签名；端口cancelled映射ExportResult.cancelled，handed-off/saved映射completed+成功回执，不返回completed+cancelled。保留端口显式取消信号，不承诺中断原生计算。
- PDF默认目标同目录临时输出/同卷提交，失败保留旧文件；参考M3 new_in(parent)/sync/persist原则，但commit_bytes只接收bytes，不等于原生PDF文件已适配。默认不从系统临时卷rename，确需跨卷则另规划复制到目标目录临时文件再替换。D1可顺带核对临时输出，完整覆盖/权限/清理在D7。

- macOS WKWebView createPDF/printOperation、Linux WebKitPrintOperation文件输出属于最后Future（D9/M11当前范围收口之后）；分别验证多页/打印CSS和系统后端，未验统一标待验证。将来各平台仍需自己的生产接入和发布验收，不以Windows通过替代。

## 4. 源文件操作与状态冻结

| 操作 | 接受时/完成时规则 |
| --- | --- |
| 打开/拖放 | 用户选出的文件标识建立本次授权；已绑定文件聚焦已有Tab，不能以磁盘内容覆盖草稿；失败保留原文、现有Tab与绑定 |
| 草稿自动保存 | 继续保存应用仓储，确认草稿修订；不影响磁盘已写回修订，不访问原文件 |
| 保存原文件 | 接受时冻结文档ID、revision、源格式与绑定目标；成功写出后记录该绑定的已写回修订。切Tab不重定向；较新修订仍提示未写回 |
| 另存为 | 接受时冻结快照，成功提交后更新对应文档绑定；失败/取消不改旧绑定、标题或写回状态。同一原生目标被其他打开文档绑定时不静默把两个Tab合并或覆盖其草稿，M5明确冲突反馈 |
| 保存源格式 | .md/.markdown/.txt沿用精确Markdown源字节策略；可编辑HTML沿用同HTML正文+源附件路径，不能将MD字节写回.html；源保存外层负责确认写回，格式生成不自行markSaved |
| 导出 | 独立目标，不更新原文件绑定或markSaved；single prepare、DOCX一次确认和平台写入清理保持 |
| 关闭Tab/窗口 | 同时考虑草稿dirty与本地绑定已写回修订，不能把草稿持久化当原文件保存完成。用户选择取消/保存失败则保留；写入完成只确认接受修订 |

本地绑定最小内容：平台内部文件标识/规范路径、文档ID、显示名、源格式和已写回修订；应用仅持有不透明绑定键和可显示状态。绑定默认本次会话有效，不恢复旧路径为可写权限；跨重启原位保存/最近文件需后续明确授权与验证，不在M0扩展。

### 4.1 绑定失效与授权释放（2026-11-01）

- M3实际授权为Rust进程内Map；重启后旧key无效。M4/M5恢复草稿时不恢复写权限，UI显示“草稿已恢复，未关联本地文件”，新建显示“未关联本地文件”；有来源证据才显示关联失效。
- 草稿已持久化与本次会话内已写回修订分列；未关联时原文件状态为未知，不展示有效已写回标记。原位保存引导重新关联或另存为，不静默写旧目标。
- 重新关联不覆盖当前草稿、选区、undo或修订，取消/失败保持状态。关联成功不是写回成功，覆盖确认后实际提交才确认接受修订；较新修订仍未写回。
- ByteSaveTarget.release幂等且只释放本次导出授权；服务finally负责调用。释放错误保留诊断，不掩盖写入主错误，也不把已完成提交谎报成写入失败。源绑定授权由绑定生命周期在使用结束后释放，不能被导出清理误撤销。
- 跨重启恢复延期，可由Rust持久locator/不透明ID并在明确授权后重建grant；不要求前端持有路径，不修改源附件/DocumentRecord来携带权限。
