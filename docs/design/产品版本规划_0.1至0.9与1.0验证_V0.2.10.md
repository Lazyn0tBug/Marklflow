# 产品版本规划：0.1–0.9 开发与 1.0 基础可用验证

日期：2026-10-23。配套设计基线：总体设计方案 V0.2.10。

## 1. 目标与版本口径

1.0 的目标是功能基本完整、满足既定需求且经过真实使用和输出验证的基础可用版，不是最小演示或仅跑通 happy path 的 MVP。开发功能规划结束于产品 0.9；0.9 到 1.0 仅审查、验证、修复及发行准备，不继续补计划中的功能。

本文件的 0.1–0.9 是产品里程碑；总体方案 V0.2.10 是设计文档修订号，二者不对应。当前 UI 原型也不自动等于产品 0.2 或任何已完成里程碑。以下均为待实施规划，不包含工期承诺；前一版通过退出条件后进入下一版，必要时用补丁版本完成修复，不为赶版本跳过门禁。

产品 0.9 是功能完整的验证候选，不作为已经通过正式发行验收的 1.0。内部候选构建可使用相应预发布标记；1.0.0 仅在审查验证关闭后发布。

## 2. 1.0 范围冻结

| 必须具备的领域 | 基础完整要求 |
|---|---|
| 编辑与工作台 | 配置默认隐藏、顶栏“视图”打开布局弹窗；开启的视图同时显示、不按断点自动隐藏、空间不足时工作台内部横向滚动、用户控制三视图显隐、编辑/HTML 内容区分别默认最大 1024px 可配置、大纲居顶导航与中心章节强调、双向同步滚动、文件/大纲、CodeMirror Markdown 和围栏语法高亮；中文输入、撤销重做、查找替换、主题、响应式布局与明确状态 |
| 文件与恢复 | 浏览器导入 Markdown/约定资源、切换文档、保存下载、草稿恢复、覆盖/取消/错误处理；关联资源和重开流程有明确规则 |
| 解析与文档模型 | CommonMark/GFM 及已定义扩展、稳定 IR/sourceRange、资产与配置 schema、版本识别、异常诊断；原始 Markdown 权威来源 |
| 内容呈现 | 阅读预览、Shiki、MathJax LaTeX、Mermaid、Graphviz WASM、图片、语义化结构、现代布局与响应式静态 HTML/CSS 基线；文档默认 HEX/RGB；错误可定位且不丢正文 |
| 排版与输出 | A4 分页预览、版式设置、单文件阅读 HTML、含源载荷的可编辑 HTML 往返、浏览器打印/保存 PDF、基础 DOCX |
| 发行与质量 | 静态 Web/PWA、全部批准运行资源随包发布、准备完成后的离线使用、无账号/后端核心闭环；Review、Lint、类型、测试、CI、受控发行与回退 |

基础 DOCX 必须覆盖方案已约定的标题、段落、列表、表格、链接、代码及图片/图表映射；公式按现有图片路径并明确不可原生编辑。不能以“基础”为由把核心内容静默丢弃。PDF 默认是浏览器打印路径，不承诺自动无对话框生成。公式默认模式由真实样例决定，复杂 MathML 适配不作为补齐初版的手段。

离线验收区分应用资源和用户文档资源：PWA 首次成功安装并准备全部批准资源后断网可用，不宣称从未访问过的设备可以无网络安装。远程用户图片缺失必须提示；正式单文件输出收集必要资产，不保留失效 blob 引用或未说明的联网依赖。

不纳入本路线：PPTX、EPUB、独立 SVG/PNG 图片导出、Tauri 本地目录访问/写回/导出路径及文件关联、自动 PDF、OMML 原生公式、任意作者 JS、高级 HTML 宿主/复杂 MathML 适配、插件市场、协同、AI 服务及反向转换。保留接口和明确未开放状态，不建立假可用按钮；这些事项不排入 0.9→1.0。

“无优化”指不安排性能专项或实验方案，不实施 MathJax M1–M4、公式专用 Worker、精细增量依赖、持久公式缓存、自研增量分页等。既定区块级复用、修订校验、基础队列、Shiki/Graphviz Worker 和 A4 调度仍是现有实现基线，不能退回逐键全量重渲染；具体实现以正确、可维护为先。性能基线和阻塞使用的卡顿仍需验证和修复，不能以“不优化”为由接受基本不可用。

应用界面保留 OKLCH；Markdown 文档预览和独立 HTML 默认采用 HEX/RGB，保留插件已有有效配色，不强制将 Mermaid 等转换到 OKLCH。文档优先语义结构、现代布局和响应式排版，阅读/打印分别验收；高级模板、交互及复杂适配仍按原范围后置。此区分适用于 0.4 内容集成、0.5 文档输出及 0.9→1.0 复验，不改变版本顺序或新增功能。

## 3. 开发里程碑：止于 0.9

| 0.6 PDF 与基础 DOCX | 打印设置、冻结修订/就绪屏障、DOCX 原生结构及图像映射、能力/降级提示 | 实际 A4 打印预览；PDF 内容完整；DOCX 在目标 Word 及一种替代阅读器验收；继续编辑不污染导出快照 | P3 输出；P4 DOCX |
| 0.7 离线与发行闭环 | Web/PWA 全部批准资源准备、离线重启、安装/更新、候选构建清单及回退 | 断网首次启用已批准但此前未用的公式/语言/图表/导出模块成功；用户无需开发工具；更新不丢草稿；产物无隐藏 CDN 依赖 | P4 交付/H1 完成 |
| 0.8 功能整合与需求闭合 | 打通前述全部能力；补齐需求内遗漏、边界错误、权限/输入安全、可访问性与恢复 | 功能需求逐项有实现和初步证据；核心回归通过；无待实现的 1.0 功能；目标环境/样例/输出清单冻结 | P0–P4 汇总 |
| 0.9 功能冻结验证候选 | 完整候选、安装/使用文档、兼容矩阵、需求追踪、测试/审阅记录、已知问题和发行候选清单 | 无需求内功能空缺；开发阶段检查和作者自验完成；关键使用路径无已知阻塞；候选 SHA/资产/哈希可追踪，可交独立审查 | P4 候选完成，正式发行待审查 |

每版执行总体方案第 12 章相关门禁；新增行为有相应测试与 Review，已有关键路径持续回归。表内退出条件不是允许其他约束暂时失效。0.8 负责功能补齐，0.9 负责冻结；不得把未实现需求留给“1.0 验证阶段”。

响应式显隐规则：0.2 实现开启视图同时并排显示，显隐只由用户控制；不得按断点自动收起或改为单视图。空间不足时在工作台内部横向滚动，页面整体不溢出，顶栏配置入口保持可达。0.8/0.9 和 0.9→1.0 复验 1280px/684px/390px、跨断点缩放、七种显隐组合、偏好恢复及同步滚动。

配置交互固定为默认隐藏、顶栏入口打开弹窗；窗口关闭不撤销已应用值，重载恢复配置而不自动打开。0.2 实现，0.8/0.9 及 0.9→1.0 复验桌面/手机、焦点、关闭/恢复与布局不被挤占；不改变导出面板或其他设置范围。

新增同步/布局为 1.0 基本功能：0.2 建立导航与布局，0.4 完成阅读联动，0.5 完成 A4 映射，0.8/0.9 整合复验，不延后到审查阶段开发。显隐按用户确认独立逐步隐藏，支持七种非空组合，最后一个视图不可隐藏；1024px 是工作台内容区最大宽度，不改变 A4 或独立导出主题。

## 4. 0.9 到 1.0：审查验证，不排新功能

| 验证工作 | 内容及产物 |
|---|---|
| 文档与需求审查 | 对照总体方案、需求追踪表和实际行为；核对首版/后续边界、说明书、能力/降级及许可证，纠正文档与实现差异 |
| 代码与工程审查 | 审查架构、契约、生命周期、竞态、数据完整性、权限、依赖和 CI/CD；检查规则例外与未解决 Review 项 |
| 全流程复验 | 干净用户环境重新导入/编辑/恢复/预览/导出/重开；在线、断网、刷新、取消、失败/重试及长文档场景 |
| 真实输出审查 | 桌面/手机阅读、A4 打印预览、PDF、DOCX 阅读器、源载荷 HTML 往返；记录浏览器/字体/阅读器及文件证据 |
| 发行验证 | 检查不可变候选产物、哈希、版本、完整离线资源、更新兼容、冒烟与回退演练；发布授权按既定规则执行 |

发现缺陷可发布 0.9.x 候选修复；文档纠错、必要测试、既有行为修复与发行配置修正属于此过程。每次变更重新执行受影响 Review/测试；最终候选重新跑完整发行门禁。未改变的审查证据可复用，但须记录其适用提交/范围，不能把旧候选全绿直接当新候选验收。

若发现原定功能缺失或需要新增设计才能满足需求，应退回开发状态补齐并重新生成 0.9 候选；不能把新功能混在“验证修复”中。若发现后续需求，登记到 1.0 之后，不阻塞已冻结范围。不得在验证期间顺手升级依赖、重构架构或实施专项优化；为修复缺陷必须调整时记录理由、影响及回归范围。

1.0 放行必须同时满足：

- 每条范围内需求能定位实现、测试/人工证据及审查结论，无未实现或证据不明的必需项。
- 数据丢失、越权、错误或缺失输出、无法安装/离线、关键编辑故障等阻塞问题为零；其他问题逐项记录影响、责任人与维护者接受结论，不无限制留缺陷。
- 必需 Lint、类型、单元/集成、生产构建、E2E、资源及发行检查通过；真实阅读器/打印验收完成，不能用结构检查代替。
- 固定最终候选的提交、锁文件、产物哈希及验证环境；文档如实列明支持范围、降级和限制；发布及回退流程可执行。

未完成必需环境或输出验证则保持 0.9.x，不因计划日期自动升为 1.0。版本放行不等于未经授权自动公开发布。

## 5. 需求追踪与每版交付记录

P0 建立需求追踪表，每项记录：需求 ID、来源章节、必须/后续分类、目标产品版本、实现位置、测试或人工步骤、样例、环境、证据、状态、审阅者及阻塞问题。状态使用“计划/开发/已实现待验/验证通过/失败/后续”，不得用“完成”合并实现与验收。

每版记录范围变化、提交 SHA、工具链/锁文件、产物、已执行检查、未验项和遗留问题。0.9 提交完整审查包，1.0 只对同一范围形成最终通过结论；不安排 PPTX、桌面版或优化阶段。
