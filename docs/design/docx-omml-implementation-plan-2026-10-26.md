# DOCX 原生公式（OMML）改造规划

日期：2026-10-26；状态：规划，未切换生产公式输出；基线architecture-refactor / fea23dd。用户反馈公式较多时逐行提示过量，要求开始规划Word原生公式。此规划独立于已完成的架构重构，不回写历史V阶段为已实施。

## 1. 目标与现状

OOXML是DOCX的整体文档格式，原生数学对象使用OMML（Office Math Markup Language）。目标为常见LaTeX公式导出后在Word中可编辑，而非仅能选中一张公式图片；不把MathML字符串原样嵌入DOCX就宣称实现原生公式。微软的[数学格式说明](https://learn.microsoft.com/en-us/office/math/)确认Office文档以OMML存储数学。

当前docxExporter固定prepareExportContent的公式模式为SVG，图片映射带PNG兼容回退；inspectDocx按每个math/inlineMath节点生成static提示。未接受静态化时生成器把逐项信息拼成异常，因此多公式文档会出现大量相同内容。这是既有降级能力提示，不等同于MathJax公式解析失败；无有效公式也不能静默忽略。

本轮规划不实现OMML、不删除真实降级告知、不升级MathJax 3.2.2或更换Paged.js 0.4.3。主编辑器继续使用LaTeX语法及现有MathJax输出；不因Word适配器支持子集就缩小整个应用的语法范围。统一导出入口、单busy、来源快照、源保存/预览缓存独立及Web反馈沿用。

## 2. 路径评估

| 路径 | 用途与优势 | 必须验证的不足 | 建议 |
| --- | --- | --- | --- |
| 已安装docx 9.14.0的docx/math及latexToMath | 无新增依赖，提供原生OMML组件；含矩阵、分段、对齐、括号、重音等 | 另一个LaTeX解释器；自定义宏、文档上下文、标签引用及样式可能与MathJax不同，解析成功不等于保真 | O1优先对照，证据满足后才决定生产接入 |
| MathJax Presentation MathML → 严格OMML适配 | 沿用MathJax语法解析、宏/编号隔离，避免再解释完整LaTeX | MathML到OMML并非一一对应，结构、样式和特殊元素需明确映射；不能只用textContent把公式打平 | O1并行对照少量代表语料；内置转换不足时作为补充或主路径 |
| Office安装目录MML2OMML.XSL/Word自动化 | 可作开发侧参考对照 | 依赖本机Office/OS及再分发许可，违背用户发布即可用目标 | 不作运行时依赖；未经许可不随包复制Office文件 |
| 外部转换服务/新通用文档引擎 | 或有成熟覆盖 | 内容上传、离线、体积及迁移成本需另评估 | 本轮不引入，不作为实现前提 |

当前[docx数学API](https://docx.js.org/api/modules/math.html)提供Math、矩阵/分段/对齐等组件及latexToMath。本地9.14.0类型定义证实已有这些入口；没有为了使用它升级依赖。

[初始解析探针](../acceptance/docx-omml-parser-probe-2026-10-26.json)仅调用现有latexToMath：10个小样例中8个返回组件，newcommand和未知命令拒绝。包含分式、上下标、根式、求和、矩阵、分段及aligned；color也返回组件，但本地API说明明确颜色/字号/部分间距不保留，故不能把它判为保真通过。探针未生成或打开Word文件，不是OMML结构、排版、可编辑性或完整覆盖率证明。

## 3. 模块边界与结果

- application/exports继续负责接受操作、冻结来源与选项、单busy和结果反馈，不引入公式任务平台。
- DOCX适配器按既有Markdown公式节点提取sourceRange/源偏移、行号、display/inline和LaTeX；用出现位置关联产物，不仅以公式字符串匹配，以容纳同式不同宏上下文。
- 仅在DOCX边界增加原生公式转换器；输入输出使用严格类型，第三方/XML返回值先校验。纯应用层不导入docx组件；不得用any或双重断言绕过ParagraphChild/Math类型。
- 每个公式结果为native、fallback或unsupported，并保留位置和理由。native必须是有效OMML树；fallback必须在用户同意后输出经过既有校验的SVG/PNG；unsupported阻止丢内容式成功。
- 行内公式映射m:oMath；独立公式核对m:oMathPara/段落结构、对齐和间距。嵌套分式、矩阵等保留结构，不能以整式字符串MathRun冒充结构化转换。
- 若选MathJax路线，完整文档公式按同一隔离上下文顺序准备；不能只拿失败公式重算而丢失前面宏定义/计数状态。不在预览DOM中反向截取公式，不污染MathJax主页面状态。
- 保留图表SVG/PNG及现有原始HTML重排；原始MathML当前拒绝策略不随LaTeX原生公式接入而自动开放。MathML路线要限定可处理元素/属性、拒绝外部实体与不受支持结构。
- 原生全部成功时，不再生成所有公式的SVG后备；混合文档按实际必要降级生成。宏上下文需要完整准备时如实记录成本，不另建持久化公式缓存或Worker平台。

## 4. 提示与降级策略

正常用户只看一份汇总：例如“共42个公式：40个原生可编辑，2个需转为图片”。仅列出实际降级/不支持项；完整逐节点位置可在详情中展开，不让每个正常公式都成为警告。

在尚未实施原生公式前，可先将重复提示合并为“本次N个公式将以图片输出”，保留一次明确同意；原有按节点的诊断仍用于详情和测试。阻断错误与一般兼容说明分开，不能删除未知命令、图片读取失败或不支持内容的错误。

提供“原生优先，需同意时使用图片”及“仅原生，不能转换则停止”的有限策略；最终UI选项在O0定稿，不预建未可用开关。默认不得静默把不支持的公式转成普通文字，也不得自动上传外部服务。图片后备保留源LaTeX作为可核对信息/替代说明；不把后备图片标为原生可编辑。

## 5. 小步实施与验收

每步独立review、相关验证后一次本地提交；后续实施须另行明确启动。以下均未实施，不并入0.9→1.0只审查流程。

| 步骤 | 范围 | 验收门槛 |
| --- | --- | --- |
| O0 诊断汇总及语料冻结 | 合并重复公式提示，保留详情/一次降级接受；冻结真实文档与代表公式、预期结构和失败项 | 多公式文档无逐条告警洪水；实际阻断项仍可定位；未授权不静态降级，原生产DOCX回归通过 |
| O1 双路径小型PoC | 对照已安装latexToMath与MathJax MathML适配的代表结构；仅测试夹具，决定路线与支持表 | 生成DOCX解包检查OMML结构；记录宏/样式/编号不一致；至少在Windows Word、macOS Word目标版本手工编辑/保存/重开；WPS单列，不用解析通过替代实际验收 |
| O2 基础原生公式适配 | 行内/独立、文本/数字/符号、分式、上下标、根式、定界符及常见大运算符；有限转换结果类型与降级 | m:oMath/必要m:oMathPara、分子分母/脚标嵌套正确；原生公式无图片替代；未知节点明确拒绝/需同意，源偏移不串式 |
| O3 常用复杂结构与上下文 | 矩阵/分段/对齐、重音、函数、数学字体、中文混排；明确宏、标签/引用与多式上下文 | 同文档定义顺序、跨文档隔离、重复公式、编号与行内标点；不支持特性不静默丢失，结构及目标Word编辑验证通过 |
| O4 生产统一导出接入 | 以冻结源为权威，DOCX生成复用原表格/图像/关系及必要MathJax入口，按实际结果汇总诊断 | 编辑/切Tab不改变本次结果；失败释放busy；图表/图片、列表/链接/表格无回退；原生/混合/全拒绝三种文档通过 |
| O5 回归与覆盖声明 | 全部门禁、单元、Chromium、OOXML结构及外部Word/WPS证据；同步能力矩阵 | 说明实际支持项、降级项、Word/WPS版本与未验范围；Word无修复警告；可编辑性与视觉分别留证，之后才考虑默认启用 |

O1不能仅因组件API丰富就跳过选择过程。若现有转换器已满足常用语料且上下文可控，不再为“统一”自建全量MathML转换器；若宏/语义差距明显，则保留MathJax解析权威并仅实现必要OMML适配。持续保持发布后用户无须安装TeX、Office转换工具或其他本地库。

## 6. 验证语料

覆盖行内/独立、空公式、嵌套分式、上下标组合、根式、多重积分/求和、伸缩括号、矩阵/分段/多行对齐、重音向量、函数、黑板粗体、中文与数学混排、超长公式、颜色/间距、宏定义与跨式引用、重复公式、转义、未知命令及损坏输入。每式记录源位置、预期native/fallback/unsupported和具体理由；不编造“完整支持全部LaTeX”的覆盖承诺。

结构验收检查word/document.xml和相关关系/命名空间；图片后备检查SVG/PNG与源式位置；人工验收在Word进入公式编辑、修改一个结构元素、保存重开，并检查无文件修复提示。WPS及阅读器另列，未安装时保持未验状态，不自动安装Office或用普通文本提取充当可编辑验收。
