# 工作台界面设计方案

日期：2026-11-13。状态：仅设计，未实施。基线：当前生产界面与生产编辑器。

本文合并 2026-11-12 的两份方案（操作工具设计、编辑工具设计，提交 `baaa3ab`）。两者的结论、边界与验收条目整体保留，只把重复的范围声明合并、去掉互链，其余不改。两份原文件随本次合并移除；需要原样文本时取 `baaa3ab`。

## 1. 范围与基线

本方案按用户最新要求收敛为四项最小变更，取代此前工具栏重组提案。此前创建的工作台 HTML 原型全部废弃为设计依据；文件和检查记录仅保留历史，不再继续修改或据此验收。当前生产界面是唯一界面基线。

1. 将“流式 / A4 分页”移到 HTML 视图自己的控件条，与现有同步状态按钮并列（详见 §2）。
2. 将“打开”“新建”放在左栏“文档 / 大纲”页签上方。
3. 优化文字、图标和 tips，使现有操作适应多种分辨率。
4. 用现代 CSS 改善现有布局与组件尺寸自适应，解决挤压、断字、遮挡和越界。

不再实施文件操作统一菜单、编辑工具菜单化、MathML/SVG 迁移、分页符迁移、额外文档切换入口或设置/About 重组。三视图、主题、保存和导出沿用现有入口和样式，只做必要显示适配。原有导入、删除、Tab、宽度设置、自动换行及其他功能不因本方案改变归属或语义。

编辑侧配合同一组四项：不再设计新的编辑器工具体系，此前工作台原型及菜单化提案废弃，不作为布局、断点或功能迁移依据。保留原来的工具位置、分组、顺序与直接操作，只对显示拥挤做必要适配。前两项的具体设计见 §2 与 §3，编辑工具主要涉及后两项，以及并列控件所需的局部布局配合。

不新增“段落/格式/插入”菜单，不把 H1/H2/H3、列表或常用格式命令移入新菜单，不新增编辑器局部主栏或文档切换器。编辑器下方 Tab、自动换行、宽度设置与分隔条继续沿用现状。MathML/SVG、分页符、设置/About 的入口不迁移或重组。

## 2. 流式 / A4 与同步状态并列

只迁移现有“流式 / A4 分页”控件，复用已有模式状态与回调；不创建新的查看模式或新的渲染入口。目的位置是 HTML 视图自己的控件条——位于 HTML 视图区域的顶部，与现有同步状态按钮横向并列，保持明显分组和独立选中态。

控件归各自控制的视图，随该视图显隐，不随今天恰好承载它的容器显隐：

- 流式 / A4 分页是 HTML 视图的查看方式，放在 HTML 视图自己的控件条上，随 HTML 视图显隐；编辑器隐藏时它仍然可用。
- 同步滚动按钮与同步状态一并进入这条控件条（同 §5 表中“同步状态”一行）：它控制编辑器与预览的联动，随编辑器显隐——只有 HTML 视图时没有可跟随的对象，此时不保留一个按不动的按钮。
- 撤销 / 重做是编辑器动作，留在工具栏右组原位，不随控件条移动。

当前模式开关在 TopBar；同步按钮与同步状态位于 WorkbenchToolbar 右侧。实现只做上述迁移所需的局部布局调整，不借机重构整条工具栏，也不设置两套同步控制。

- 宽度充足时，“同步状态”与“流式 / A4 分页”同排显示；空间不足时允许整组换行，不能把“A4 分页”拆成竖排。
- HTML 隐藏时，控件条随视图隐藏；恢复后保留现有模式。
- 切换只改变查看模式，不修改 Markdown、不插入分页符，也不自动导出。A4 视图仍不是导出的必经步骤。
- 同步状态保持原有操作与联动，不由流式/A4 切换隐式改变。

## 3. 打开 / 新建位于文档 / 大纲上方

在左侧栏顶部、“文档 / 大纲”页签上方放置现有“打开”“新建”入口。切换文档/大纲页签时，这一操作行保持位置稳定，下面仍为原来的页签及内容区域。

- 不改成新的文件菜单，不重排保存、导出、导入或文档管理流程，不复制同一操作的常驻按钮。
- 复用现有新建和打开处理逻辑、平台能力判定及忙碌/禁用条件。当前 Sidebar 的打开入口由可选 onOpen 注入，Web 没有该能力时不凭布局新增原生打开入口；既有导入保留。
- 打开/导入失败不覆盖现有文档，重复打开聚焦已有会话，未保存保护和绑定规则不变。
- 左栏隐藏时操作行随其隐藏；三视图显隐继续由用户控制，不因窗口变窄自动展开或关闭左栏。
- **窄屏另有一条**（见 §6 的窄屏规则）：左栏自动收起，主区一次只显示一个内容视图，跟随焦点所在的那一侧，顶栏的视图开关在该状态下是切换而不是叠加；这些都由宽度**算出**，不写回显隐偏好。

## 4. 文字、图标与 tips

保留现有 neutral/teal 主题、图标体系与操作风格，不换一套视觉语言。先消除同义冗长文案和重复说明，再减少留白或调整分行，不靠缩小整页或字号硬塞按钮。

- 操作名简短一致，“流式”“A4 分页”“打开”“新建”保持可辨认。已选中、已关闭、忙碌和不可用状态不能只靠颜色区分。
- 按钮与图标组作为整体，文字不按单字符换行，图标不被压扁。紧凑时可省略非必要辅助说明；只有图标语义足够明确时才省略按钮文字，并保留可访问名称。
- tips 说明动作、当前状态、禁用原因及已有快捷键，不编造新快捷键，也不成为理解按钮的唯一途径。
- 键盘聚焦也能获取必要提示，触屏不能依赖悬停才发现核心操作；提示不得被容器裁切或持续遮住相邻主按钮。复用已有提示实现，确有缺口时局部补齐，不引入通用提示平台。

编辑侧的工具显示遵循同一组要求：

- 沿用现有主题、图标和按钮风格；名称、图标、tips 表达同一动作，不用换图标来重新定义熟悉的操作。
- 对按钮组设置不缩断约束，避免中文单字竖排、图标被压扁、菜单触发区域过窄；不强制把所有控件压在一行。
- 按工具容器实际宽度调整间距、辅助说明和必要分行，优先 CSS 容器查询、Flex/Grid 与逻辑尺寸属性。保留现有稳定分组，不能仅因视口较窄而取消直接入口或另建菜单体系。
- 仅在确有需要且图标含义明确时省略辅助文字，完整动作名、当前状态和禁用原因仍可通过可访问名称、键盘可达提示获得；不能仅靠 hover 或颜色理解操作。
- 菜单和 tips 沿用既有浮层边界，避免 overflow、包含块或层叠上下文裁切。局部内容需要滚动时边界明确，不把整页宽度撑开。
- 编辑器内容的最大宽度、自动换行与面板宽度分别遵循现有配置；不借响应式覆盖用户偏好。视图不因断点被取消（窄屏按 §6 的规则不并排，不是取消）。
- 分页符按钮现用剪刀图标，读者只会理解为“裁剪”。换用语义为“一页被横线分开”的图标（lucide-react 0.546.0 无 PageBreak / FileBreak，取 Rows2），名称统一为“分页符”：图标提示、可访问名称与本文档用同一个词；tips 写明“在此处插入分页符（A4 硬分页）”，syntax 仍显示 `---pagebreak---`。按钮保持纯图标，不新增文字标签。该按钮位于横向可滚动工具组的末尾，窄窗下可能被滚出视野，实施时确认其可发现性。

## 6. 现代 CSS 与组件尺寸适配

仅调整现有布局、尺寸约束和显示规则，不按断点替用户**取消**任何开启的视图；至少一个视图可见的约定不变。沿用现有面板最小宽度、内容最大宽度及分隔条偏好，不采用废弃原型的 24rem、68rem、96rem 等数值作为生产约束。

窄屏规则：**整个工作台连两个面板的最小宽度都放不下时**（两个面板各 360px 加分隔条 8px ⇒ 728px，取自 `src/core/model/paneSplit.ts` 的既有下限，不另拍一个数），改为一次显示一个内容视图：

- 显示哪一个**跟随焦点**：焦点在编辑器就显示编辑器，焦点在预览就显示预览；没有焦点记录时默认编辑器。
- 视图**不被取消**，只是不并排；用户显式关掉的那一个仍然关着，不会被布局改回来。
- 顶栏的「编辑器 / HTML 预览」在窄屏下是**切换**而不是叠加：点哪一个就显示哪一个。
- 左栏自动收起，顶栏的侧栏开关保持可达；展开后仍按既有宽度规则显示。
- 这些都由宽度**算出** ⇒ ⇒ 不写回显隐偏好 ⇒ ⇒ 窗口变宽回到并排。

| 区域             | 最小必要的适配策略                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 应用栏和工具行   | Flex/Grid 排版，允许必要分行；按钮组不缩断，文档名和辅助文字可收缩、省略并可查全称                                        |
| HTML 局部工具    | 按所在容器宽度适配，优先容器查询；同步与模式组可整体换行，保持各自顺序和完整名称                                          |
| 左栏操作行       | 随左栏宽度分配空间；页签下方列表/大纲独立滚动，操作行不被长内容挤走                                                       |
| 工作台           | 使用 min-inline-size: 0、min-block-size: 0 正确释放可收缩空间；低于既有面板总下限时，仅工作台内部横向滚动，视图不自动隐藏 |
| 导出及设置弹层   | 宽度受视口约束，高度使用动态视口单位配合上限；标题/操作区可达，中间内容滚动，窄时现有选项可转单列                         |
| 右下消息与导出窗 | 保留既有 body Portal、层级及焦点/点击隔离；调整尺寸和间距，窄/矮窗为消息与主要按钮留出必要空间，不让两者互相遮挡          |

使用逻辑属性、CSS 变量、min()/max()/clamp() 约束宽高与间距，保持稳定可读字号、可达命中区和可见焦点。容器查询服务于组件空间；媒体查询处理视口高度、输入方式、减少动态效果等环境差异。已有实现足够时直接沿用，不为使用新技术而重写。

弹层与消息的具体避让方式在真实工作台上确定，不采纳废弃原型的固定阈值或另建碰撞调度器。保持统一右下消息区、导出窗口不自动关闭，不改消息队列、生命周期或计时。设置继续默认收起并以弹窗打开，入口不重组。

## 7. 验收边界与当前状态

文档部分已定稿；实施按 §8 分步进行。四步均已实现并在 Web 真实工作台核对过（宽窗、半屏、窄窗、矮窗四档逐项量过），真实 Tauri 的视觉、输入与文件操作验收待补；废弃原型的通过记录不能证明本方案已通过视觉验收。本方案的文档未做 Luna 定向复核——当前环境没有 `gpt-6-luna` 子代理配置，不自行更换模型。

后续获准实施时，在真实工作台验证宽窗、半屏、窄窗、矮窗及浏览器缩放/字体放大；1600/1280、800、390 和 800×600 可作为检查样本，不作为硬编码断点。确认：

- 流式/A4 位于 HTML 上方并与同步状态并列；切换不改源文、不触发导出，隐藏恢复保留模式。
- 打开/新建位于文档/大纲之上，平台能力、会话和失败保护不变。
- 文字不竖排、图标不变形、提示与键盘焦点可达，核心按钮不被挤出可视范围。
- 三视图显隐由用户决定，横滚限于工作台；导出操作和右下消息不互遮，弹层不越界。
- 窄屏（工作台 < 728px）：左栏收起，主区只显示一个视图且跟着焦点走，顶栏视图开关是切换；窗口变宽恢复并排，显隐偏好不被改写。

编辑侧同期验证：不同面板宽度、深浅主题、字体放大下按钮/图标不挤压和竖排；鼠标与键盘可获取必要提示；原来的格式/表格/公式等入口仍可达；选区、IME、单步撤销、Tab 状态不因布局变化受损。只跑受影响的定向验证，不因本次文档更新重跑全仓。

Web 浏览器与真实 Tauri 的视觉、输入和文件操作验收分别记录；不以静态文档审查代替运行结果。HTML 唯一内容投影与视觉输出源、平台导出路径及既有保存语义均不在本次变更范围。
