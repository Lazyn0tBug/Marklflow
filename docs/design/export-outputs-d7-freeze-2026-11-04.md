# D7-0 导出路径差异冻结（2026-11-04）

D7（Windows 产品化验收，映射迁移计划 M8 ✓）的**验收依据**。对应迁移计划 M7「EX-T0 差异冻结」✓：映射当前端口与已完成准备工作，列出各 OS 导出能力与占位清理范围 ✓。

**边界**：D7 **不接生产 UI** ✓（M8 明写 ✓ —— 那是 M9「EX-T2a Windows 统一导出接入」✓ 的活 ✓）；**不重建 PoC** ✓（复用 D1 的隐藏宿主 + COM + 就绪探测 + 输出 ✓）；**不新增用户端依赖** ✓（不装 poppler ✓，不引 PDF 库 ✓）。

## 1. 两条导出路径

### 1.1 Web 路径（今天唯一的用户可见路径）

```
ExportService.run（src/application/exports/exportService.ts）
  → ports.prepare → ports.generatePdfHtml → ports.deliverPdf(html)
  → deliverPdfHtml（src/core/platform/web/pdfDelivery.ts）
      隐藏 iframe（794×1123，opacity:0，不在视口内）
      → view.focus() → view.print()
      → **浏览器的打印对话框** → 用户选"另存为 PDF"
```

- **目标选择**：**浏览器的打印对话框** ✓（不是原生选择器 ✓）。
- **命名**：浏览器取自 HTML 的 `<title>` ✓ —— 而该 title 由 `ports.generatePdfHtml(artifact,{title:file.baseName})` 给出 ✓（`file` 来自 `exportFile(input.fileName, format)` ✓）。**Web 路径的命名是提示，不是保证** ✓（系统/浏览器可能忽略 ✓，见总方案"Web PDF 的 HTML title/建议名只是提示，系统驱动可能忽略" ✓）。
- **取消**：用户关掉打印对话框 → 浏览器不产生文件 ✓；但**应用侧无从区分"取消"与"打印失败"** ✓（`deliverPdf` 返回 void ✓，无回执 ✓）——这是 Web 路径的固有短板 ✓。
- **覆盖保护**：**没有** ✓ —— 浏览器直接写它要写的地方 ✓（同名文件由浏览器/系统决定 ✓）。

字节类格式（md／zip／docx／html）走另一条 ✓：`ports.selectSave(file)` → Web 侧 `selectWebSave` ✓ → 浏览器下载 ✓，回执四态 ✓（`saved`／`download-started`／`recovered-download`／`activation-expired` ✓）。**这条路径没有原生选择器** ✓。

### 1.2 Windows 原生静默路径（D1 的 PoC，今日只有探针在用）

```
探针（src-tauri/src/probe.rs，仅 pdf-probe 特性）
  → 隐藏宿主（visible(false)）载 file:// 的受控样本
  → 原生 eval 读就绪（文档完成 + 字体 loaded + 图片解码 + 页面盒数量/尺寸）
  → COM: ICoreWebView2_7::PrintToPdf（打印设置钉死 A4 + 零边距 + 背景开 + 页眉页脚关）
  → 目标同目录的临时文件 → rename 提交
```

- **目标选择**：**没有** ✓ —— 目标是固定的（默认 `<仓库>/docs/acceptance/pdf-probe/probe-pdf-output.pdf` ✓，可用 `MARKFLOW_PROBE_PDF` 改 ✓）。
- **命名**：**没有** ✓（文件名固定 ✓）。
- **取消**：**没有** ✓（没有用户参与 ✓）。
- **覆盖保护**：**有** ✓ —— 同目录临时文件 + rename ✓，失败时原文件保持不变 ✓。
- **回执**：**有** ✓ —— `probe_pdf` 记 `ok`／`bytes`／`elapsed_ms`／`committed`／`sha256` ✓。

### 1.3 两者差在哪（这就是 D7 要补的）

| 项 | Web 路径 | 原生静默路径（今日） | D7 要达到 |
| --- | --- | --- | --- |
| 目标选择 | 浏览器打印对话框 | 无 | **原生选择器**（复用 `select_native_save` ✓） |
| 命名 | HTML title 提示，系统可忽略 | 无 | **由 `ExportFile` 给默认名** ✓，写进目标路径 ✓ |
| 取消 | 应用侧区分不了 | 无 | **取消 → 不写任何文件** ✓，回执区分取消与失败 ✓ |
| 覆盖失败保护 | 无 | 有 | 保持 ✓（失败保留旧文件 ✓） |
| 静默性 | **不静默**（有打印对话框 ✓） | 静默 ✓ | 保持 ✓（只有保存对话框 ✓，无打印面板 ✓） |
| 回执 | `SaveReceipt` 四态 ✓ | `probe_pdf` ✓ | 统一到"目标提交成功才 saved" ✓ |

## 2. 各 OS 的导出能力

| OS | 导出 PDF | 依据 |
| --- | --- | --- |
| **Windows** | **原生静默** ✓（隐藏宿主 + COM `PrintToPdf` ✓） | D1 通过 ✓（2026-11-04） |
| macOS / Linux | **只有 Web 路径** ✓（浏览器打印对话框 ✓） | WebView2 的 COM 路径是 Windows 专属 ✓；本仓库没有其他平台的原生静默实现 ✓ |

**因此"Windows 静默 PDF"这个能力声明只对 Windows 成立** ✓；其余 OS 的能力声明仍是"经浏览器打印对话框" ✓（与今天的路线图文案一致 ✓）。

## 3. 命名与目标选择的规格

- **默认名**：`exportFile(input.fileName, format)` ✓ → `ExportFile{name, baseName, extension, mime}` ✓。**`baseName` 是文件名的主干** ✓（`generatePdfHtml` 用它做 title ✓；原生路径用它做目标文件名 ✓）。
- **扩展名与 MIME**：由 `exportFile` 的格式表给出 ✓（`print-pdf` → `.pdf` / `application/pdf` ✓）。
- **目标选择**：原生 `select_native_save` ✓（M3 的薄适配 ✓）——它给的是**授权**（路径 + 可写 + key ✓），**路径只在原生侧可见** ✓（前端只拿到 key 与文件名 ✓）。
- **取消**：`select_native_save` 返回 `None` ✓ → **不写任何文件** ✓。
- **命名规则**：沿用 `exportFile` 的清洗规则 ✓（后缀剥离 ✓、非法字符替换 ✓、grapheme 边界 ✓）✓ —— 原生路径**不得另起一套命名规则** ✓。

---

## 4. 同目录临时提交与覆盖失败保护

- 临时文件与目标**同目录** ✓ → 同卷 ✓ → rename 是原子的 ✓。
- 目标**只在最后那一步被触及** ✓ → 打印失败、取消、超时、迟到回调**都不改原文件** ✓。
- **不得**默认走系统临时卷再 rename ✓（跨卷 ≠ 原子 ✓）—— 确需跨卷再单独设计 ✓（Q5 ✓）。
- 打印的产出是**原生直接写文件** ✓，不经 bytes ✓ → M3 `commit_bytes` 的保护原则**不能直接套用** ✓（它接 bytes ✓），只能借用其"临时 + 替换"的形状 ✓。

## 5. 资源、超时与迟到清理

| 项 | 规格 |
| --- | --- |
| 隐藏宿主 | 打印结束即显式关闭 ✓（**丢句柄不等于关窗** ✓ —— 窗口仍在应用的窗口表里 ✓） |
| 临时文件 | 成功 → rename ✓；失败 → 删除 ✓；超时 → 删除 ✓ |
| 完成回调迟到 | **超时即失败** ✓；迟到回调**不得改写回执** ✓（通道一断即无人收 ✓） |
| 打印等待上限 | 有界 ✓（超时即失败 ✓） |
| 日志 | 每运行一份 ✓；轮转与保留按基座契约 ✓（D8 的监控看板另议 ✓） |

## 8. 未决与风险

1. **原生路径没有用户可见的入口** ✓ —— D7 的机制由夹具/探针驱动 ✓（**不接生产 UI** ✓），M9 才接 ✓。
2. **Web 路径与原生路径的语义不等价** ✓ —— Web 路径"取消"与"失败"分不开 ✓、命名只是提示 ✓、没有覆盖保护 ✓。**D7 不改 Web 路径** ✓（那是既有行为 ✓）；两条路径的差异由 M9 统一 ✓。
3. **代表阅读器的清单尚未定** ✓ —— "声明支持哪些阅读器"是对外说法 ✓，须先定清单再核 ✓（否则核的是谁的阅读器并不清楚 ✓）。
4. **跨机阅读不由 D7 保证** ✓ —— 字体嵌入只是一层证据 ✓；D1/D7 的 PDF 与生成机器相同 ✓，跨机复现不承诺 ✓（Q7 的说明 ✓）。
5. **更完整样本的字体环境** ✓ —— 必须在**与交付宿主相同**的环境生成 ✓（否则分页度量不匹配 ✓，D0 已立过这条 ✓）。
