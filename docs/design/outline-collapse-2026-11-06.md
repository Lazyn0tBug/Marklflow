# 大纲折叠设计：侧栏大纲树的展开与收起

日期：2026-11-06；状态：**折叠功能与结构重构均已实施**（分支 `outline-collapse`；折叠功能提交 `5a0c7df`，结构重构 R1–R4 见 §11 与 §12）。

## 0. 决策摘要

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 折叠单位 | **有子标题的标题**（树节点）。叶子标题没有折叠按钮 | 折叠是"收起一段"，没有子项就没有可收起的内容；不给叶子加一个永远无效的按钮 |
| 树的定义 | 某标题的父节点 = **它前面最近的、level 更小的**标题；没有则它是根。跳级不报错（H1 后的 H3 直接挂在 H1 下） | 与 Markdown 标题层级语义一致；跳级不产生空洞层级 |
| 默认状态 | 按**树深度**判定（根 = 0）：**深度 ≥ 3 默认收起**，深度 ≤ 2 默认展开 | 对 H1 起的文档，等价于"H1–H3 展开、H4 及更深收起"；但用深度而不是 level，层级整体偏移两级的文档（Word/Confluence 导出常见）不会整篇塌成空骨架 |
| 显式操作的键 | **稳定键** = 标题文本 + 该文本在文档中按出现顺序的序号；**不用** `createHeadingId` | 标题 id 内嵌行号（`src/core/parse/markdown.ts:25-28`），在任意位置插入一行会让其后所有标题的 id 全变 ⇒ 用 id 记显式值等于"编辑一次清空全表"，与显式值存在的目的直接相反 |
| 状态归属 | 仅当前激活文档的视图状态，切换 Tab 时清空 | 与《本地文档支持设计》§4.2 的"绑定不入文档"同理：这是临时视图状态 |
| 搜索时的折叠 | **忽略折叠状态**，命中的标题全部可见；此时不渲染折叠按钮 | 搜索的语义是"找出全部命中"。若折叠仍生效，用户会看到"搜到了却看不见"；搜索结果本身已是筛选后的子集，折叠无对象可收 |
| 跳转与展开 | **用户主动点击标题跳转时，展开其全部祖先**；滚动引起的高亮变化**不展开** | 高亮随编辑器滚动持续变化（每次滚动都更新）。若高亮变化就展开祖先，用户向下滚动时大纲会一路自动展开，折叠就白做了。而"点搜索命中跳过去"是明确意图，展开路径是用户要的 |
| 高亮标题与折叠 | 滚动使高亮落在收起分支内时，**不展开**；改为在"其子树包含当前高亮"的折叠按钮上做强调标记 | 同上。高亮行不在 DOM 里时，`[aria-current=location]` 的计数会变成 0（§1 约束表已列） |
| 全部展开/折叠 | 工具区一个按钮，在"全部展开"与"全部折叠"之间切换 | 长文档需要整体收起的场合；一个按钮两态比两个按钮省位置 |
| 行结构 | 一行 = `div` + **两个兄弟 button**（折叠按钮、跳转按钮），不嵌套 | HTML 不允许 button 嵌套；折叠按钮必须是独立可聚焦元素才有正确的键盘与读屏语义 |
| 缩进 | 仍按 **level**（`(level-1)*10px`），不改成树深度 | 树深度与 level 在跳级标题处不同；沿用 level 保持既有观感与既有断言 |
| 快捷键 | **不做** | 折叠是次要操作；键盘用户可用 Tab 到折叠按钮 |
| 代码结构 | **数据 + 视图 + 响应**：状态机在纯模块里，组件只渲染 | 规则原先散在父组件、子组件与一个 ref 之间；组件里散着分支，与迁移计划 §3.1「组件调用应用服务，不散布分支」相悖 |
| 上一修订的同名组 | 是**状态的一部分**，不是 effect 维护的 ref | 规则与它的输入放在一起，"什么时候清理"不再隐式 |

## 1. 现场事实

侧栏"大纲"标签页当前把 `extractOutline` 给出的**扁平**标题列表按 `level` 缩进平铺渲染：

- 每一行是一个 `<button>`，`title` 为 `标题文本 (第 N 行)`，点击即跳转到该标题；
- 没有父子概念，也没有折叠位 ⇒ **大纲永远完全展开**；
- `activeHeadingId` 由编辑器滚动位置持续更新（`App.tsx` 的 `highlightLine` 每次滚动都调用），当前高亮行带 `aria-current="location"`；
- 标签页上的计数 `大纲 (N)` 是**文档标题总数**（`outline.length`），与折叠无关。

现有断言依赖这些形状，改动不得破坏：

| 断言 | 位置 | 前提 |
| --- | --- | --- |
| `button[title^="章节5 (第"]` 可点击并跳转 | `tests/e2e/review-workbench.spec.ts` | 该 title 属于**跳转按钮**；折叠按钮的 title 不得以标题原文开头（见 §4.1） |
| `[aria-current=location]` 计数 | `tests/e2e/review-workbench.spec.ts` | **当高亮标题可见时为 1**；高亮落在收起分支内时为 0（此时高亮行不在 DOM 里）。现有夹具是 12 个 H1（不会触发收起），计数仍为 1 |
| `button[title^=...]` 命中唯一 | `tests/e2e/workbench-source-scroll.spec.ts`、`workbench-tabs.spec.ts` | 同上：不得有第二个按钮以标题原文开头 |

## 2. 折叠语义

### 2.1 树

扁平列表按 §0 的规则叠成树。**子树的定义统一以此为准**：一个节点的子树 = 它自己 + 它的全部后代（经由 §0 的父节点关系传递）。不再另给"其后连续的更深层标题"这一定义——两者在跳级序列上会得出不同结论。

### 2.2 折叠与可见性

- 一个节点**可折叠** ⟺ 它有子节点。
- 节点处于**收起**状态时，保留该节点的标题行和展开按钮，仅隐藏后代。后代仍可被搜索命中。若祖先也已收起，则该节点随祖先隐藏。
- 叶子节点没有折叠按钮，也永远不是收起状态。

### 2.3 默认状态与显式覆盖

对每个可折叠节点，取值顺序：

1. 用户对该节点有过显式操作 ⇒ 用显式值；
2. 否则 ⇒ **树深度 ≥ 3 为收起**，否则展开。

**稳定键**（§0）：`标题文本 + 该文本在文档中按出现顺序的序号`（同名第 n 次）。它与行号无关，因此：

- 唯一标题在上方增删普通行后保留覆盖。标题改名或消失时删除旧覆盖。
- 同名序号只区分当前修订中的节点。Markdown 修订变化时，清除上一修订或当前修订中出现同名的组的覆盖，其余唯一标题沿用现有键。首版接受同名组较早恢复默认，避免把覆盖转移到另一节。


## 3. 数据 + 视图 + 响应

大纲的状态机不再散在组件里。分成三层：**数据**（一份状态）、**动作**（外部世界与用户意图的入口）、**视图**（纯函数，把状态变成要渲染的东西）；**响应**由 React 的 `useReducer` + `useMemo` 承担。

### 3.1 分层与落点

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 树运算 | `src/core/parse/outlineTree.ts`（既有） | 叠树、稳定键、可见行、生效收起集合、收起祖先、祖先键、可折叠集合——都是纯函数，不含规则 |
| 数据与规则 | `src/application/workspace/outlineState.ts`（新） | reducer（动作 → 新状态）与 `outlineView`（状态 → 视图模型） |
| 渲染 | `src/components/workspace/Sidebar.tsx` | 只做渲染与事件映射：不持有规则，不算派生值 |

组件里不再出现"用 effect + ref 维护上一修订"这类写法：它变成状态的一部分。

### 3.2 数据

```ts
interface OutlineState {
  docId: string;                           // 状态属于哪个文档
  items: readonly HeadingItem[];           // 标题提取的结果
  filter: string;                          // 搜索词
  overrides: ReadonlyMap<string, boolean>;  // 显式覆盖（稳定键 → 是否收起）
  duplicates: ReadonlySet<string>;          // 当前修订里出现至少两次的标题文本
  previousDuplicates: ReadonlySet<string>;  // 上一修订的同名文本
}
```

### 3.3 动作

```ts
type OutlineAction =
  | {type:'sync'; docId:string; items:readonly HeadingItem[]}
  | {type:'filter'; value:string}
  | {type:'toggle'; key:string}
  | {type:'toggle-all'}
  | {type:'jump'; itemId:string};
```

外部世界对组件只有"我变了"这一件事，所以只有一条 `sync`：换文档与内容变化都由它进入，reducer 内部判断是哪一种。

### 3.4 reducer 的规则

| 动作 | 规则 |
| --- | --- |
| `sync` | `docId` 变了 ⇒ 覆盖清零；重算同名组；用（当前 ∪ 上一修订）的同名文本清理覆盖；`previousDuplicates` ← 旧的同名组，`duplicates` ← 新的 |
| `filter` | 只改搜索词 |
| `toggle` | 该键的覆盖取"当前生效值的反面"（生效值 = 深度默认 + 覆盖，reducer 自己算得出） |
| `toggle-all` | 全部可折叠节点的覆盖取同一个值（全部收起 / 全部展开） |
| `jump` | 该标题的祖先键的覆盖置为 false（展开路径） |

这五条就是原先散在组件里的规则。收进 reducer 之后，"上一修订"是数据的一部分，不需要 effect 去维护它。

### 3.5 视图模型

```ts
interface OutlineRow {
  item: HeadingItem;
  key: string;          // 稳定键
  hasChildren: boolean; // 有子标题
  foldable: boolean;    // 是否渲染折叠按钮（叶子或搜索态为 false）
  collapsed: boolean;   // 收起中
  marked: boolean;      // 收起的、且其子树包含当前高亮
}
interface OutlineView {
  rows: OutlineRow[];
  allExpanded: boolean;
  empty: 'none' | 'no-match' | null;
}
outlineView(state, currentDocId, activeHeadingId): OutlineView
```

视图是纯函数：建**一次**树，算生效收起集合，算可见行，套搜索筛选，把标记打进行里。

- 状态里的 `docId` 与当前文档不符时，覆盖视为空 ⇒ 换文档的第一帧就不会显示旧文档的折叠（零陈旧帧）；reducer 随后把覆盖清零，于是切回旧文档也是默认状态。
- 搜索时忽略折叠、不渲染折叠按钮（`foldable` 为 false）。
- 侧栏自己的"文档/大纲"页签切换不换文档，折叠状态保留。

### 3.6 响应层

组件里只有三件事：`useReducer` 持有状态、`useMemo` 算视图、把事件映射成动作。视图与状态都是纯的 ⇒ 规则可以直接单测，不必起浏览器。

### 3.7 迁移必须保持的行为（不变量）

重构只改结构，不改行为。以下八条由 §9 的验收条目钉住：

1. 深度 ≥ 3 的分支默认收起，叶子没有折叠按钮；
2. 收起只隐藏后代，标题行与折叠按钮保留；
3. 唯一标题的覆盖跨"上方插入内容"保留；同名组在修订变化时清理且不转移；
4. 搜索时忽略折叠、命中项全可见、不渲染折叠按钮；清空搜索后折叠原样恢复；
5. 主动跳转展开祖先；滚动引起的高亮变化不展开；
6. 换文档清零（切回旧文档也是默认状态）；侧栏页签切换保留；
7. 折叠按钮的 `title`/`aria-label` 不以标题原文开头；
8. 高亮落在收起分支内时，高亮行不在 DOM 里，收起祖先的按钮带标记。

## 4. 交互规格

### 4.1 一行的结构

```
┌────────────────────────────────────────────┐
│ [▸] │   三级标题                       ●     │   ← 折叠按钮 │ 跳转按钮
└────────────────────────────────────────────┘
```

- 两个按钮是**兄弟**，不是嵌套。
- 折叠按钮：`aria-expanded`（展开为 `true`）、`aria-label`（`展开 三级标题（第 12 行）` / `折叠 三级标题（第 12 行）`）、`title`（同义文案）。
  - **折叠按钮的 `title` 与 `aria-label` 都不得以标题原文开头**（否则会撞上 §1 表里 `button[title^="章节5 (第"]` 这类选择器，Playwright 的 strict 模式会因多命中直接失败）。
  - 文案里带行号，使同名标题的按钮可区分。
- 跳转按钮：保留现有 `title`（`标题文本 (第 N 行)`）、保留 `aria-current="location"`（且**仅**它带）、保留高亮圆点、保留点击跳转。
- 高亮行与悬停态的背景从跳转按钮移到外层 `div`，使两段行共享同一底色。
- **行上不显示级别徽标**（H1 / H2 / H3 这样的小标签）：缩进已经表达了层级，再挂一个级别标签是多余的，也不是通行的大纲样式。级别是 Markdown 源的信息，在大纲的行上没有位置。

### 4.2 图标

折叠按钮用 `ChevronRight`（收起）/ `ChevronDown`（展开），工具区按钮用 `ChevronsUpDown`；均为仓库既有的 `lucide-react` 图标，不引入新图标集。

### 4.3 布局与类名约束

```
行 div：display:flex; align-items:center; gap:0        ← gap 固定为 0，保证位移可确定
  折叠按钮 / 占位：统一槽宽，图标 14px           ← 无子节点时放同宽的空占位
  跳转按钮：flex:1 1 0; min-width:0; padding-left:(level-1)*10 + 8px
```

- 缩进挂在**跳转按钮**的 `padding-left`（与今天的写法一致），不在行 div 上；
- 跳转按钮需要 `min-width:0` 与 `flex:1 1 0`，内层文本保留 `truncate`，否则长标题不会省略而是撑破行宽；
- 折叠槽统一为 24px，图标宽 14px。按钮命中区占满槽宽和行高，行高至少 24px。叶子及搜索结果使用同宽占位。
- 标题文本随槽宽右移 24px。折叠按钮须提供可见的键盘焦点样式。


### 4.4 跳转时展开祖先

用户点击某标题跳转时，展开该标题的**全部祖先**（写入显式值）。这条规则同时覆盖两种入口：

- 在大纲里直接点某个可见标题；
- 在搜索结果里点一个命中项时保留搜索词，立即跳转并记录祖先展开。搜索结果仍只显示命中项，清空搜索后显示展开路径。

滚动引起的高亮变化**不**触发展开（§0）。

## 5. 搜索与折叠

- 搜索词非空时：可见行 = 命中的标题（沿用现有的扁平筛选语义，不改成"命中项及其祖先"）；**不施加**折叠，命中项全部可见；**不渲染**折叠按钮（此时没有可折叠的对象）。
- 行结构在搜索态保持一致：折叠槽仍占 24px，避免清空搜索后文字横向跳动。
- 搜索词清空后：按最新覆盖恢复折叠显示，包括搜索期间点击命中项展开的祖先及批量操作。
- 现有筛选语义（只显示命中的标题）保持不变，不在本次改动范围。

## 6. 高亮与折叠

- 高亮标题被收起祖先挡住时，**不展开**它。此时该标题在渲染结果里不存在，`activeItemRef` 为空，大纲列表的"滚动到高亮项"逻辑自然不动作；`[aria-current=location]` 的计数为 0（§1 约束表已列这一前提）。
- 替代反馈：其子树包含当前高亮的**收起节点**，其折叠按钮用强调色（teal）标出，提示用户"当前章节在这个收起分支里"。
- 该强调色**不承担** `aria-current` 的语义；高亮可见时计数仍为 1。
- 实现上不要用选择器兜底去找"当前高亮行"：它此刻本就不在 DOM 里，查不到是正确状态，不是缺陷。

### 6.1 高亮在收起分支里时：够得到它

颜色标记只回答"那边有个东西"，不回答"我在哪儿"。补一条：

- **够得到**：大纲能滚到那个收起分支。高亮落在收起分支内时，"滚动到高亮项"改为"滚动到收起它的那个祖先"，于是用户看见的是分支的入口，点一下就展开。

**仍然不自动展开。** 展开是用户自己的决定；滚动到祖先并把它的按钮标出来，是**指路**，不是替他决定。

**不另加位置提示行。** 曾经设计过在大纲顶部加一行「当前章节位于〈祖先标题〉」，实施后判定为多余：入口行本来就在屏上、还带强调标记，把它的标题再写一遍没有新增信息，却占了一行位置、多了一处会闪烁的界面元素。位置由入口行本身承担。

#### 6.1.1 "够得到"的具体规则

- 高亮**可见**时：滚动到高亮行（现状不变）。
- 高亮**被挡住**时：滚动到**最外层那个收起祖先**的那一行。那一行一定可见——更深的收起祖先被外层挡住，不在屏上；最外层那个的祖先都没有收起，它留在列表里，天然是一个可点的入口。
  - 取最外层而不是最近的那个：收起只隐藏后代，所以更深的收起祖先**连同它自己的行**一起被外层挡住，指不到。
- 该祖先行的折叠按钮带 §6 的强调标记，指路与可见性互相印证。

#### 6.1.2 与 §4.4 的分工

| 动作 | 展开祖先 | 定位 |
| --- | --- | --- |
| 点击大纲标题（§4.4） | 是 | 定位到该标题 |
| 高亮变化后的自动滚动（§6.1.1） | **否** | 定位到高亮行，或到挡住它的那个收起祖先 |

展开是用户的决定：点击标题是用户明确要求"到那里去"，顺带展开祖先是达成它的必要手段；高亮自动滚动只是"指路"，替用户展开就越界了。

#### 6.1.3 实现约束

- 入口行是**派生量**：由（折叠状态 + 当前高亮 ID）算出，**不进状态机**，因此**不新增 reducer 动作**。（§11 曾写"以新动作的形式加进 reducer"，此处更正：这条不改变任何折叠状态。）
- "滚动到高亮项"那个 DOM 效果的依赖要**加上折叠状态**：否则用户手动收起或展开之后，滚动定位不会重新计算，入口与实际收起情况会脱节。
- 落在收起分支内时高亮行**不在 DOM 里**（§6 已述），所以定位只能指向祖先行；两者互斥，不存在"既滚到高亮又滚到祖先"的情形。

## 7. 全部展开 / 折叠

工具区（搜索框旁）一个按钮，图标 `ChevronsUpDown`：

- 当前**全部展开**时 → 动作是"全部折叠"；
- 否则 → 动作是"全部展开"。

作用范围是当前大纲里**所有可折叠节点**（含被收起的），并以显式值写入（覆盖默认）。判定用的是全部可折叠节点，不是当前可见行。按钮的 `title` 与 `aria-label` 随当前动作变化。

搜索期间该按钮仍在，行为不变（作用于全部节点）。

## 13. Future：搜索大纲（暂不实施）

**是什么**：一个**跨文档**的标题导航器。输入一段文字，在所有打开文档的标题里匹配，结果按文档分组，每条给出标题与它的**大纲路径**（祖先链），回车跳到那个文档的那个标题。

**为什么值得做**：现在的搜索框是**当前文档内**的筛选，而且只给命中的标题——命中项在文档里的位置看不出来（它可能在收起的分支深处）。工作区级搜索把"在哪个文档、哪条路径下"一起回答了；侧栏的搜索框继续做"当前文档内筛选"，两者并存。

**可行**：要的零件都已经在——

- 每个文档的大纲树与稳定键（§2.1、§0）⇒ 路径与去重都是现成的；
- `jump` 动作会展开祖先再跳转（§4.4）⇒ 从搜索结果跳过去，落点一定是一条展开着的路径；
- 状态 + 视图的形状（§3）⇒ 工作区级搜索是同一形状的**上一层**：状态挂在工作区，视图出结果行。

**要加的**：

1. **工作区级索引**：文档 ID → 该文档的大纲树，随文档修订更新。这是当前设计之外的一层状态——现在只有文档级状态。
2. **匹配器**：匹配标题文本，可选是否连祖先标题一起匹配（即"按路径匹配"）。精确/模糊/拼音是独立的一步，不进本设计。
3. **结果视图**：分组的结果行 + 路径；复用现有的行模型（键、标题、路径），不另造行形状。
4. **入口与键盘**：一个快捷键唤起；结果列表支持上下键与回车。

**不做**：不做正文搜索（那是全文检索，不是大纲搜索）；不持久化搜索历史；不改现有搜索框的语义。
