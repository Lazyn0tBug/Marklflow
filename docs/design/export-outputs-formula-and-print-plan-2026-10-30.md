# 统一输出与桌面交付完整实施方案

更新：2026-11-02。三平台原生静默PDF为目标，Windows先验证，macOS/Linux列Future最后实施；尚未修改代码。代码核对基线：`architecture-refactor / 00a8ce2fb778c192a780928f259063c71895c667`。本文替代原 A/B/C 草案及互相冲突的执行叙述，作为当前输出工作的完整方案；历史实测仍以原始记录为准。本次仅更新文档，未执行代码测试或系统验收。

## 1. 目标、范围与约束

Markdown 经唯一映射形成冻结 `ExportHtmlArtifact`，阅读 HTML、可编辑 HTML、DOCX、PDF 从该产物生成。原始 Markdown 和 Markdown 资源包沿用既定源保存例外，不为这些例外再渲染正文。可编辑 HTML 的源附件服务恢复，不成为第二套正文生成入口。

Web/Tauri 使用同一个 `ExportService` 类与格式生成器，各自组合交付端口。用户统一选择格式、名称、确认适配、执行导出；PDF 不增加专属打印预览，A4 工作台视图不是必经步骤。平台实现可以不同，但反馈必须对应实际可观察结果。

保留 MathJax 3.2.2、Paged.js 0.4.3 及当前依赖锁；不封装 Chromium、不采用 Puppeteer、不采用截图 PDF、不重跑源解析生成另一份公式。现有 DOCX 图片降级不等于截图 PDF，继续受一次确认约束。后续格式仍从冻结 HTML 提取所需结构，不另建绕过 HTML 的内容模型；EPUB/PPT 等不在本轮实施范围。

关联：[迁移路线](tauri-migration-plan-2026-10-29.md)、[接口契约](tauri-migration-m0-contract-2026-10-29.md)、[HTML 输出约束](html-export-source-plan-2026-10-26.md)、[OMML 历史规划](docx-omml-implementation-plan-2026-10-26.md)。迁移阶段依赖由迁移路线管理；本文细分输出工作，不建立第二套 EX-T 阶段。

## 3. 单一业务服务与双平台组合根

目标调用链：`ExportModal → 统一应用服务入口 → ExportService → 共用生成器 + 平台交付端口`。

- 启动组合处按 `isTauri()` 选择 Web 或 Tauri 组合根；SDK 检测封装在平台边界内。UI 只依赖统一服务，不分散环境判断；一次运行只使用选中的单例，关闭/重开导出窗口不重建 busy。
- 保留 `platform/web/exportService.ts`；新增 `platform/tauri/exportService.ts`，镜像注入 `selectSave/deliverPdf`，不复制 ExportService.run、公式转换或冻结生成器。公共生成器装配如有重复只做小型工厂，不建平台注册器。
- Tauri 端口未完成或平台未验时明确不可用，不假借 Web 组合完成桌面验收，也不在原生失败后自动下载。
- 当前顺序继续为冻结快照→正文 prepare/检查→需要时一次确认→生成完整字节→selectSave→save→释放目标。被拒绝输出不选择位置；取消选择不写入。异步生成后不能保证 Web 用户激活仍有效，也不能宣称 picker/write 必然仍在原手势内。
- 格式生成失败或交付失败保持错误；busy 在操作 finally 结束。PDF 请求交接后不把 busy 当成系统保存锁，打印宿主另按生命周期清理。

## 4. 交付接口及回执

下列是拟议契约，不表示生产类型已改动。

| 端口 | 目标约定 |
| --- | --- |
| selectSave(ExportFile) | 返回 ByteSaveTarget 或 undefined；undefined 仅表示选择未产生目标，不能推断所有原生弹窗故障均可辨识；可辨识错误抛出 |
| ByteSaveTarget.save(Blob) | 保留字节保存专用 SaveReceipt，准确区分真实提交与浏览器接管，不加入打印状态 |
| ByteSaveTarget.release?(): Promise<void> | 可选、幂等；Web 无授权可省略，Tauri 必须实现。应用服务取得目标后在 finally 调用，包括成功/失败；选择途中已取得授权但构造失败，由适配器清理 |
| deliverPdf(html, ExportFile) | Promise<PdfDeliveryReceipt>；平台内部承担目标选择与交付，字节selectSave不参与PDF路径；输入仅为同一次冻结分页HTML，ExportFile提供名称，不授予路径权限 |
| PdfDeliveryReceipt | 拟议联合类型为 `{status:'handed-off'}` / `{status:'saved'}` / `{status:'cancelled'}`；Web仅返回handed-off；桌面仅在原生输出及目标提交成功后saved，用户选择目标取消时cancelled。运行中的不可取消计算不伪报cancelled，失败抛错 |

PDF 不可用、准备失败、原生调用/完成回调失败或目标提交失败时抛出错误，不能返回handed-off或saved。Web原生输出不能判断系统面板内保存/取消，afterprint仅用于清理，文案为“已提交 PDF 输出请求，请在系统对话框中完成保存。”桌面静默路径只有目标文件成功提交才提示“已保存文件”；取消选择目标则提示取消。端口handed-off/saved映射ExportResult.completed并带成功回执；端口cancelled映射现有ExportResult.cancelled，不返回completed+cancelled，UI只处理应用层取消。端口必须显式回传取消信号，失败按错误处理。

### 4.1 三平台原生静默PDF目标

| 平台 | 候选原生接口 | 实施顺序与状态 |
| --- | --- | --- |
| Windows | 隐藏专用WebView2加载冻结分页HTML，PrintToPdf输出受控临时PDF | 前置D1先独立技术验证；D7/M8产品化验收后才D8/M9生产接入，当前均待验证 |
| macOS | 隐藏WKWebView；评估createPDF与printOperation/系统PDF输出的分页适配 | Future F-PDF-Mac，排在当前Windows/Web路线收口之后；待验证，不承诺createPDF天然产生正确多页A4 |
| Linux | 隐藏WebKitGTK；评估WebKitPrintOperation配置PDF文件输出 | Future F-PDF-Linux，与macOS同属路线最后；待验证，核对发行版/GTK打印后端/打包环境 |

目标都是统一导出入口、可选择保存位置、无应用专属PDF预览且不显示打印面板。静默不等于跳过用户授权或保存选择器；只有已明确授权的目标才可省略选择。三平台共用生成器与冻结HTML，原生交付按OS适配，不要求底层相同。未实现或未验证的平台标“待验证”，不得自动回退Web打印、截图或新浏览器。

Windows宿主必须把冻结分页HTML作为顶层文档；PrintToPdf不能直接指定现有预览iframe。复用现有完整分页HTML生成路径和冻结资源，不抓取可见DOM、不重新解析Markdown/LaTeX，不要求先显示A4，不重复prepare或分页。已核实pdfExporter调用paginatePreparedContent，后者在paged.preview完成后提取页面outerHTML和样式；交付HTML无Paged.js运行脚本。隐藏宿主的就绪判据统一见第4.2节，尚待D1验证；保持资源有效至完成，不在本节重复维护另一套判据。

Rust持有路径/授权，专用宿主不授予一般业务IPC或任意本地文件访问。受控一次性内容装载与就绪通知应限任务范围；保持静态HTML/CSP及资源策略，不执行作者脚本，不为就绪检测开放广泛权限。用户建议名仍由ExportFile产生；先选择/授权目标，再由原生端在目标目录输出受控临时PDF，完成成功回调后检查输出并同卷受控提交替换目标，最后返回saved。原生回调仅证明临时输出完成，不等于目标已提交；失败保留原文件。选择目标在完整PDF交付HTML生成后进行，与字节格式“完整字节生成后选择”的路径分开描述，不改字节端口。

输出宿主一次只执行一个打印任务，沿用导出busy，不新增任务平台。纸张、缩放、页边距、背景、页眉页脚与既有分页HTML匹配，避免二次缩放/空白页。成功、失败、超时、关闭均释放宿主及临时资源；超时后须先使原生任务不能再提交/写入目标再清理临时文件，迟到回调不得报成功。原生调用返回或销毁宿主能否可靠终止写入也属于PoC验证项，不伪称系统提供可中断取消。授权release失败不掩盖输出主错误。


授权释放失败应单独保留诊断，不掩盖主要写入失败；若文件已提交，不因 release 失败引导用户重复保存或谎称写入失败。释放只针对本次导出目标，不能撤销仍供原文件绑定使用的授权。源绑定与导出目标是不同资源；关闭文档/重新关联/应用退出分别按归属释放，先等本次使用完成再释放，不建通用资源平台。


### 4.2 D0/D1样本、宿主与验证边界（Q6—Q44，2026-11-02）

D0先在受控样本源中加入唯一首尾标记，经当前生成路径分页冻结，记录标记与预期页码，再计算HTML的SHA-256并交接固定样本，记录data-export-pages预期值、唯一首尾标记/代表性内容、生成提交、OS/WebView与样本指定及实际可用字体。样本含CJK、公式、图片和表格即可，不先建设大型样本库。D1直接加载该文件，不自行重新驱动前端生成；哈希只锁定输入，不证明内容正确或跨机器输出一致。

D0同时确认Tauri原生入口及依赖版本：当前2.12.4有with_webview，Windows PlatformWebview有controller()/environment()；Cargo.lock含传递的webview2-com/windows。应用直接使用时仍需核对直接依赖与版本一致性，不能因Cargo.toml未直接列出就推断无COM依赖。这里只读核对入口，不等于PrintToPdf已封装或运行通过。

D1复用Tauri创建的隐藏宿主及控制器，范围包含Windows原生接口访问/转换、PrintToPdf异步完成、回调和COM引用生命周期、加载与基本清理。“小夹具”仅指产品范围有限，不承诺只调用一次API，也不预建另一套原生窗口/COM环境管理层。

D1退出条件：PDF物理页数等于固定HTML的data-export-pages；核对关键首尾正文、可选文字、CJK、代表公式图表，无额外空白页/截断及宿主闪现/打印面板，保留文件/hash/环境。页数相等是必要而非充分条件；Windows完整产品化保真证据归D7，D6仍是Web系统证据，不互相替代。

候选就绪判据（由D1验证，尚不承诺可靠）：目标顶层导航成功且文档加载完成，document.fonts.ready及图片资源成功加载/解码，再读取页面盒数量与尺寸核对预期。HTML img与SVG image按实际API分流，不能都直接调用decode；检测在目标WebView文档环境内进行。不用固定睡眠或rAF作为必需就绪条件，不新增作者脚本权限；仍须证明受控检测与CSP兼容。静态分页结构在新宿主仍重新计算样式/布局，不能称为没有回流，也不执行第二次Paged.js分页。

字体边界：当前验证本机生成分页HTML并交付本机输出宿主，仍需确认实际字体环境一致；冻结分页HTML跨环境重新输出的版式一致性尚未验证。PDF成品跨机器阅读另验字体嵌入/显示/可选文字，不因此被声明为仅支持本机阅读。正文及带文本图表可能有系统字体依赖；MathJax SVG字形内部图形引用与MathML字体依赖不能一概而论。本轮不追加字体打包工程。

D0选定D1首选形态为Tauri创建、独立label、visible(false)的专用WebviewWindow，从不主动显示输出窗口；D1复用其WebView2控制器，不先实现三种宿主或另建独立原生COM窗口平台。附着已有窗口的独立WebView不等于现有预览iframe，不能仅因附着关系判定其不符合隔离；但它不是本轮首选，是否改试需根据失败证据另行决定。

D1允许三种结论：通过（满足既定条件）、当前形态不可行（明确可复现的机制限制）、未能确认（环境/依赖/实现问题未排除）。后两者均可结束本轮探索，保存输入/环境/错误/实际输出证据并完成安全清理，Windows静默PDF不标已支持，D7/D8暂停，Web路径不受影响。单次错误不等于路线证伪，不自动换其他宿主或扩大功能。无法安全清理时须记录阻塞并停止后续接入，不能称基本清理通过。

IPC隔离是D0/D1的显式检查：D0记录输出window/webview label与所有capability匹配、core/插件权限及应用自定义命令暴露；D0只读定位需要的最小限制；若需收紧，作为D1首个最小小步落实，再验证隔离，不留到D8、不新增主阶段。D1用有限探针验证输出宿主不能调用敏感文件选择/读取/写入命令。独立label或不匹配capability不等于无IPC，invoke_handler注册的应用命令默认行为必须单独约束。采用适当命令权限/来源限制，不在本轮预建通用权限框架。就绪检测走原生WebView2受控脚本执行，不通过Tauri IPC，不为此授权一般业务命令或作者脚本。

API层次以Tauri 2.12.4 PlatformWebview为准：controller()/environment()是包装层方法；内部wry结构的字段形式不能用来否定它们。D0核对锁定版本与接口覆盖，D1仍须验证实际运行，不以旧版缓存推断新API不存在或承诺无需直接依赖声明。

Q23身份约定：注入owned tauri::Webview明确代表发起命令的WebView，从其取得真实WebView label及所属窗口label，二者分别记录，不接受前端身份参数。D0固定当前main与独立输出宿主的身份映射、允许范围及签名解析预期；D1a编译和定向验证。Tauri 2.12.4的WebviewWindow::label()返回内部WebView label，不能因类型名当作窗口label；owned Webview注入也不要求调用方必须是WebviewWindow组合形态。

当前单WebView主窗口与独立输出窗口可按真实窗口身份划分主窗口允许、输出拒绝，同时记录WebView身份；这不是对未来同窗所有WebView的授权。一窗口多WebView须重新核对粒度，不自动继承窗口级权限。Capability既支持windows也支持webviews，窗口匹配会覆盖同窗WebView；不能称ACL只按窗口label。Rust检查和ACL可以有意采用不同粒度，但允许/拒绝结果及差异必须说明、通过同命令对照验证，不机械要求字段一致。

Q24编译边界：D1a生产来源检查、敏感命令拒绝、正常授权及释放逻辑始终编译，不受pdf-probe控制。只有测试夹具创建/签发/受控交付、测试专用回收及探针页/专用启动逻辑放在feature后；正常release_native_file等业务清理不能一并消失。D1b记录实际构建命令与有效feature集合：feature关闭时生产来源限制和主窗口允许路径仍有效、测试入口不进入正常构建；默认feature列表和命令未显式传参只是证据一部分，需检查配置/依赖启用的实际结果。正常发行不得使用会启用探针的--all-features，专用探针release与正常发行明确区分。不为此预建复杂CI系统，后续生产接入仍核对同一边界。

Q25精确映射：owned Webview是身份来源，不等于仅按WebView label授权。D0只读明确主界面及输出宿主预期的(window label, webview label)对应关系与允许范围；D1a用纯守卫单测验证预期身份匹配并检查入口接线，主界面真实允许调用归D1b；输出宿主实际身份与调用证据由D1b取得。不能假设两种label相等，也不能把枚举到的全部WebView自动允许。当前可采用窗口/WebView组合匹配，不因某对象属于main窗口就无条件允许；未来同窗多WebView须重新判断权限。

Q26拒绝记录：D1b至少记命令、真实调用方身份、拒绝原因、实际拒绝层及对应代码/配置版本；层可为ACL、Rust来源检查或未确认。须正向确认权限拒绝；若仅具体层归因未确认，按Q32记录并限定复用；通道/阳性无效或拒绝性质未知时仍不能通过。ACL先拒绝只证明该层拦截，不证明Rust检查已被实际调用；Rust生产限制由D1a独立针对性检查，不为验证它放宽生产权限。证据复用仍核代码/配置/依赖、身份映射和调用路径等前提，不能简化成“Rust代码还在即可复用”，也不要求一轮探针对未到达的所有层都给运行通过。

Q27范围：D0不新增附着式宿主创建或实际调用；首选独立隐藏窗口保持不变。将来确实改试附着式时，才核对窗口/WebView身份、capability继承、来源限制并补实际证据；当前记录机制与未验边界，不提前实现备选，不把现有结果外推，D0不改产品代码，受控样本生成按Q30例外执行。

Q28发行核验：并入既有Q24，不新建工具或阶段。正常发行使用已确认feature集合；检查实际脚本/包装命令及最终有效feature，D1b验证当前feature关闭构建，实际发行仍核当次环境，不由一次检查永久担保。Cargo --all-features会启用所选包全部feature，没有通用的“all-features后排除pdf-probe”选项；--exclude排除包而非feature，不能混用。正常发行不走会启用探针的all-features入口，专用探针构建单独记录；默认列表/命令无显式--features并非充分证据。

Q29创建归属：生产侧单点定义具名输出宿主身份与创建函数，身份用于识别拒绝对象而非自动加入允许清单。D1a定义/引用身份并验证守卫允许/拒绝逻辑及入口接线；D1b首次实现并创建输出宿主以承载权限探针，D1c和后续D8复用同一函数/身份定义/形态，每次运行创建独立实例，不共用运行实例或另建替身形态。生产创建路径与身份定义不受pdf-probe控制，仅测试页面/初始化等专用行为受feature控制。源码定向检查单点引用及无无意副本，运行断言实际窗口/WebView身份与预期一致；不把普通编译器能证明“无第二份字面量”作为条件。共用函数不自动证明页面内容/来源/安全配置相同，隔离证据复用仍需原有前提匹配。

Q30样本归属采用(a)：D0执行者可通过现有前端生成入口完成一次受控固定样本生成并落盘，先标记样本源再冻结；不改被核对的产品代码，不增加阶段。交接仍含HTML/hash/页数/标记页码/生成提交与环境，Luna核验交接及必要证据。D0可启动既有应用取证，但不实现IPC探针、权限修改或新原生输出，不承担身份注入编译验证。既有路径不能生成有效样本时记录具体缺陷与受阻范围，另定修复归属，不在D0静默扩大代码工作。

Q32权限效果与归因：D1b须有正向权限拒绝证据（稳定拒绝代码、可识别平台权限结果或其他充分证据），有效通道及同命令阳性，并确认无副作用/内容泄露；不是“排除四个业务错误或其他已知错误后其余皆权限错误”。拒绝性质未知仍未能确认。权限拒绝已确认但ACL/Rust先后无法区分时，可记录“拒绝层归因未确认”而不阻塞D1b；不要与总阶段“未能确认”混为同一字段。自有Rust检查可提供稳定错误代码，但上游拦截不证明Rust已运行。D7/D8复用时，层已知可帮助限定复验；层未知不能缩窄，按相关代码/配置/依赖、身份和调用路径整体补验，不以必须补出层名作永久门槛，不由探针自行弱化正向证据要求。

Q33默认拒绝仅指受保护的敏感命令：未列入相应允许范围的窗口/WebView保持受限，不推导所有无敏感性API皆不可用。D1a建立规则，D8核对当时所有实际宿主：确需允许且路径可用，或有意受限且限制有效。不能将新增宿主自动加入允许清单，输出宿主应留在受限侧；清单核对不是扩大授权。

Q35来源与冲突：D0按Cargo.lock选择精确registry源码/对应版本文档，或已确认对应的上游提交，记录来源URL/版本或提交、锁文件标识及必要工具链信息，不用latest或近似tag替代。缺缓存时后续可在相应授权下以cargo fetch --locked取得锁定内容，不因取资料升级依赖。webview2-com与windows不是天然互斥，要核对实际互操作类型/版本组合；锁定版本下的实际结论是只有webview2-com可用（windows 0.62.2不含WebView2绑定），见本节末D0核对已确立段。文档与实测冲突时，先确认代码/依赖/feature/平台相同且探针有效，以可复现结果修正当前预期，在新证据中注明修正的D0项与适用范围，历史归档不覆盖；单次运行现象不无条件推翻接口文档。

Q36正向证据路径：D0读源码/配置只提出预期，D1b确认实际拦截路径。自有来源守卫执行时，以共享稳定拒绝码证明权限拒绝，不匹配Tauri错误文案；ACL先行时以可靠、绑定实际Tauri版本的权限结果识别方式取证，识别失效则拒绝性质未确认、不能通过。正向识别平台权限结果不等同于黑名单排除，也不承诺完全无调用路径依赖。实际层可归因未确认时继续适用Q32，但权限性质必须有充分正向证据；不得根据D0预期直接声称哪个层已运行。

Q37拒绝码与验证边界：来源拒绝使用一处共享稳定常量，保证与既有业务错误不混淆，不必新建错误命名空间/框架，具体名称在实施时确定。D1a针对守卫和命令入口做可判定检查，拒绝返回该码且后续文件/对话框操作未执行，并用纯守卫单测验证主窗口身份允许分支；真实允许调用归D1b，不要求尚未创建的真实输出宿主调用，该实际证据在D1b取得。用户可见错误沿现有UI处理映射友好提示，不显示裸码或调用方/允许名单细节；探针读机器码不读中文提示。内部受控验收记录可保留必要身份用于复现，不与用户提示混用，不扩大成新UI工程。

Q38受保护集合：当前为select_native_open、select_native_save、read_native_text、write_native_bytes、release_native_file五个files.rs的IPC命令。身份范围与命令集合分开表达，由这些入口调用同一守卫，不建注册平台。get_platform_info不加这组文件来源守卫，但不保证任意宿主可调用，通道/其他权限仍以实际验证为准。release_native_file受保护以防越权撤销授权，Rust内部按资源归属清理仍须可用，不把IPC来源检查放进通用清理逻辑而妨碍正常释放。

Q39—Q41验证分层：D1a以纯守卫函数单测断言允许身份放行、范围外身份返回共享稳定拒绝码；另对五个受保护命令定向检查入口接线、原生身份提取、拒绝码传递及检查先于文件/对话框副作用。入口证据采用定向源码审查，或可行的入口级测试，明确各自证明范围；纯函数单测不替代入口证据，二者都不称真实IPC隔离已通过。默认feature构建与单测只证明相应编译边界和判定逻辑，不冒充运行期拒绝证据。D1b通过受控测试调用方取得主窗口允许与输出宿主拒绝的真实IPC证据，不要求提前实现M4/M5生产文件交互。当前没有现成生产文件调用链，且本阶段选择不为D1a临时接入M4/M5的生产调用方，因此真实调用验证安排在D1b；这是范围与步骤划分，不是技术上无法构造测试调用方。

Q42—Q44身份与证据：D1a在既有原生主窗口创建/初始化路径或受控验收入口读取运行中的完整(window label, webview label)，与允许范围预期比较并记录来源。D0配置/创建路径可作为初始依据，运行值用于校验，避免仅用同一常量自证；不新增身份IPC命令，不提前接M4/M5生产文件交互。不一致先核实际取值路径与配置版本，再修正身份映射或允许范围；运行身份匹配不代表真实IPC隔离已验。五个受保护入口各记录四项证据：调用共享守卫、身份取自原生注入、拒绝返回路径正确传播、检查位于文件/对话框/授权撤销等副作用之前。每项标源码位置或相关测试位置，写入既定共用阶段记录；优先定向源码审查，按需补可行入口测试，不为此强制构造五套运行时。源码审查证明返回值路径，不冒充框架实际IPC响应证据，后者由D1b验证。失败按同一请求的实际观察排查：守卫对本应拒绝的实际输出身份返回允许，检查允许范围和身份提取；共享拒绝码已可靠对应到该请求且无业务效果，来源守卫拒绝有效，有可信运行对应证据时拒绝层已知；已有拒绝记录却另有操作成功，先核请求、命令入口、实例、版本及结果传播，再查漏接或副作用先于拒绝；请求未到守卫只能记原因待查，ACL、路由、通道均为候选，不能直接认定ACL。到达handler不等于业务成功。继续遵守正向权限证据要求，权限性质未知不通过；只有拒绝性质已证而具体层未知时才按Q32限定结论。

## 5. 格式输出路径

| 用户选择 | 内容源与生成路径 | Web 交付 | Tauri 交付 |
| --- | --- | --- | --- |
| Markdown | 接受快照中的原文 | 字节保存/下载 | 原生选择并写入 |
| Markdown 资源包 | 快照源文与既有冻结资产打包 | 同上 | 同上 |
| 阅读 HTML | ExportHtmlArtifact→generateExportHtml | 同上 | 同上 |
| 可编辑 HTML | 同一产物正文 + encodeEditableSource 附件 | 同上 | 同上 |
| DOCX | 同一产物→共用公式判定→exportDocumentToDocx | 同上 | 同上 |
| PDF | 同一产物→generatePdfHtml/Paged.js→完整分页 HTML | 浏览器原生输出请求 | 所声明 OS 已验证的静默原生 PDF 端口（Windows先行） |

两平台沿用 ExportFile 的 MIME、完整扩展名、255 UTF-8 字节及完整 grapheme 规则。Web PDF 的 HTML title/建议名只是提示，系统驱动可能忽略；桌面静默保存由ExportFile提供默认名并由用户选择目标，不依赖打印机驱动命名。桌面当前尚无已接生产的PDF端口，D1先验证技术能力，D7/M8再做产品化验收，不能把“系统 WebView 必然支持”写成事实。

Web 现有降级分支 download-started/recovered-download/activation-expired 必须在 UI 如实区分，硬写入失败不静默改投。生成耗时导致激活过期时，优先沿用明确下载反馈；若实际需求要求始终选择位置，后续再设计一次用户确认动作，不重新生成或重复确认 DOCX。保存选择器取消与异常分开测试。

## 6. 会话绑定失效与工作台状态

此节落实 M4/M5 所需语义，不把源文件保存混入导出服务。

| 状态 | UI 与允许操作 |
| --- | --- |
| 新建/未关联草稿 | “未关联本地文件”；草稿仓储状态独立显示；显式保存引导另存为 |
| 当前会话有效绑定 | 显示授权的文件显示名；分别显示草稿持久化与“本次会话内已写回修订/尚未写回”；较新修订仍未写回 |
| 重启恢复或授权失效 | “草稿已恢复，未关联本地文件”或“本地文件关联已失效”；原位保存不可直接执行，提供重新关联/另存为，不显示仍有效的已写回标记 |
| 重新关联取消/失败 | 保留草稿、选区、undo、修订及原状态；不得读取磁盘正文覆盖草稿或把较新修订标为已写回 |

只有确有来源状态证据时才称“原关联失效”；当前恢复模型无法区分来源时统一显示“未关联”，不凭空恢复来源。关联选择仅重新建立目标授权，覆盖需明确确认；成功关联本身不是写回成功。初版不持久化可用 grant，不自动用旧 key 申请写入；恢复的原文件写回状态为未知，而非“本次会话已写回”。只含当前草稿持久化与绑定所需最小 UI 状态，不强加新文档 schema。

后续可由 Rust 持久化 locator 与不透明 ID，经明确授权后重建会话 grant；路径仍不进 DocumentRecord、前端业务、Worker、缓存或导出附件。该能力独立规划，不在 M4/M5 首版实现，也不要求为此破坏当前接口。

## 7. DOCX 原生公式与产物边界

现有转换器已读取冻结 HTML 中 MathML，不再读取 Markdown 或解析源 LaTeX。data-mf-tex 仅用于降级详情和图片 altText；不改用 MathML annotation 承载源式，避免净化后源文本混入正文。native 不产告警，fallback 汇总数量并保留逐项理由，一次确认后导出图片，unsupported 阻断且不产假成功文件。

| 当前处理 | 能力及后续核对 |
| --- | --- |
| 叶子、分式、上下标、根式、部分 mfenced | 已有 OMML；需结构与复杂嵌套语料回归，不能仅凭简单公式断言全支持 |
| munder/mover/munderover、矩阵/表格、未知元素 | 当前降级图片；不拍平未知结构或伪造空 n-ary 被积式 |
| mstyle/mpadded/mphantom、mspace | 当前有展开/空格处理；这不证明视觉等价，尤其 phantom 可见性、间距、颜色、字号须核对，无法保真则规划降级，不以“容器”概括为无损 |
| SVG/PNG 降级 | 已有 use 展开、颜色固化、PNG 非空检查；保持净化、源映射和一次确认，不扩大导入 SVG 白名单 |

当前转换器的子组递归、元素参数个数、定界符伸缩与分隔符语义应列入专项回归；如发现结构或视觉语义丢失，单独小步修复。Word/WPS 对公式可编辑、保存重开、版面和字体的支持分别验收；结构断言不替代应用实际打开。
