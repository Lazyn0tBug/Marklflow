# HTML 兼容性改造计划

日期：2026-10-24。分支：`html`。起点：`fae43767c2fc5f4d0957b0c610f573e2bfda661f`（标签 `0.9`）。

状态：A0–A7已实施并完成首轮本地验证；R0–R4完整审查与修复见 ../reviews/html-review-2026-10-24.md。部分环境/格式仍未验，不代表1.0放行。基线：本目录 `html-compatibility-baseline.md`，摘自总体设计方案 V0.2.10 第16章，以其最新色彩、布局和分期约束为准。

## 1. 目标与边界

先完成 H0/H1 静态文档闭环：同一 Markdown 在阅读预览、独立 HTML、A4/打印和基础 DOCX 的能力边界清楚，输出资源完整、内容不丢失、布局可验证。应用 UI 保留 OKLCH；文档预览和独立 HTML 默认 HEX/RGB，不强制转换 Mermaid 等已有有效配色。

现代化优先语义 HTML、Flex/Grid、媒体查询、尺寸容器查询、可靠字体回退和流式排版；不以“浏览器能解析”代替实际布局和打印验证。工作台显隐、同步滚动、默认1024px内容最大宽度及配置弹窗保留；工作台偏好不泄漏进独立输出主题。视图仍由用户控制，开启视图不按断点自动隐藏。

本分支不重新定义0.9产品路线，不移动0.9标签，不把计划视为1.0验证通过。H0/H1中已有基本要求的缺口作为兼容性补齐；H2–H4属于后续能力，须另行确认发布版本与范围。不要将新增模板/脚本当作0.9→1.0验收阶段的必要修复。

不同时升级 MathJax 主版本、重做编辑器、加入公式 Worker/精细增量缓存、实现 PPTX/EPUB、Tauri、自动PDF或任意作者脚本。本计划只标明这些输出/宿主的未来接口，不创建假实现。

## 3. 实施顺序

每一步是独立可审阅的工作包，不要求全部同时实施。建议先审阅本计划，再按A0→A7执行。A2/A3契约确定后可分别开发，合入时先保证A1边界与回归有效。每步提交代码、对应测试、能力记录和未验项；未完成的功能不得在UI显示“支持/导出成功”。

### A0（H0）：冻结能力契约与回归样例

- 建立 `docs/contracts/html-capabilities.md` 和机器可读能力schema，记录 featureId、内容模式、阅读/打印/各目标格式、native/mapped/static/unsupported、环境/版本、日期和证据状态。
- “未测试”“不支持”“规划”分别记录；文字可选取、对象可编辑、交互保留、视觉效果分开记录。
- 建立HTML、SVG、MathML、链接/图片、长表格、代码、公式、图表、中文/emoji、重复标题、源载荷、错误内容的固定fixtures。
- 增加Vitest契约测试及Playwright生产构建测试入口；精确锁定新增开发依赖，不替换现有Bun锁文件或使用无测试占位步骤。
- 记录当前样例预览、导出和打印差异；当前不正确行为登记缺陷，不作为永久截图基线。

退出：每项首批能力有作者入口、输出策略、异常与验收样例；契约测试能运行；关键现状问题有可复现记录。暂不实施高级布局内容或脚本。

### A1（H1前置）：统一内容与资源允许边界

- 普通Markdown默认无作者脚本；明确允许的语义HTML、SVG、MathML元素/属性，链接协议、图片来源及事件属性处理。
- 统一清理/验证入口供预览和导出使用；优先评估DOMPurify，版本与MathML/SVG保留样例须验证。不要把Shadow DOM、Worker或React类型当安全边界。
- 解析与生成时区分文本、属性、URL、CSS值；校验theme.primaryColor、字号/行高等主题字段，避免直接字符串插值形成任意样式内容。
- 修正代码围栏/公式/分页符优先级和错误恢复；避免代码中的标题/HTML被误当文档内容。若现有解析器不能稳定支持契约，先ADR比较原位修正与既定unified迁移，不以现代HTML改造名义直接重写全栈。
- 独立定义CSS策略，未来保留批准的@container/@layer，URL/@import由资产策略解析，不用正则删未知CSS。

退出：正负样例均通过；批准MathML/SVG不被清理破坏，原文可恢复；危险内容有拒绝/清理诊断，预览与导出同策略。未知语法不静默丢弃。

### A2（H1）：提取共享文档结构、CSS与主题

- 建立 `src/core/render/documentPresentation.ts` 和 `src/styles/document.css`（文件名建议，按ADR固化），输出稳定 `.mf-doc-*` 语义类及独立变量。
- 标题、列表、引用、table/thead/tbody/th、图文容器、代码、公式/图表结构规范化；去除文档依赖应用dark/hover/Tailwind工具类的路径。
- 阅读/A4/HTML使用同一文档样式源；HTML内嵌其生产构建结果，而不是抓取应用CSS或再维护一份字符串样式。主题HEX/RGB，图表有效配色保留。
- 导出完整语义文档根和必要元数据，普通阅读版不含编辑器React/store或作者运行脚本；源载荷为非执行数据，保持旧格式可读。
- 首批采用命名空间文档根，验证全局选择器影响；若无法隔离，记录缺口并以ADR选择iframe宿主，不在A2直接引入未规划的任意HTML运行平台。

退出：同样主题在阅读与独立HTML的结构/CSS来源一致，应用切深浅色不意外改变文档；独立打开不丢表格对齐或代码样式；旧文档/源定位基本行为不回归。

### A3（H1）：命名容器与响应式排版

- 显式定义文档容器 `mf-document`，`container-type:inline-size`；尺寸查询作用于后代，媒体查询处理独立视口，二者不能混用。
- 首先用受管理模板/fixture验证Grid/Flex两栏→一栏；不为测试布局提前开放任意作者HTML/CSS。普通Markdown主题同时受益于行长、流式间距、图片/表格/代码溢出规则。
- 预览、独立HTML、A4内容区建立等价容器链；rem/em/ch/ic/lh、clamp及容器单位各自有明确参考空间。工作台最大宽度不写入文档纸宽。
- 分隔线、最大宽度、字体和图片尺寸变化后重建必要测量并保持源锚点；禁止用旧屏幕高度直接计算打印页码。
- 不改变用户视图显隐：宽度不足仅工作台内部横向滚动，独立文档阅读仍需自身响应式，二者不混为一个overflow策略。

退出：窄右栏/宽右栏/单HTML视图/独立文件/A4内容区均通过；容器缺失有测试失败信号；文档无非预期全页溢出，局部滚动明确；同步滚动目标不因容器断点跳错章节。

### A4（H1）：冻结修订、渲染就绪与静态化

- 将HTML导出从同步函数改造为可等待的协调接口；冻结documentId/revision/选定公式模式/主题/资源，用户继续编辑不混入导出。
- 为公式/图表返回成品、诊断、资源依赖和就绪状态；Mermaid等待生成SVG后收集，导出不带“正在渲染”占位。仅收集已见DOM不算全文渲染。
- 阅读/A4异步任务校验修订；清理旧预览不取消独立导出。错误代码和诊断转义后显示，不被当HTML重新执行。
- 图片decode、实际字体可用性与必要布局完成后才进入分页/打印；移除把150ms当完成屏障的做法。超时、取消、错误有可恢复结果。
- SVG验证引用ID、defs及自包含字形；多个相同公式/图表不产生冲突。公式解析失败应明确诊断，不把LaTeX文本MathML回退当最终成功。

退出：未滚到的Mermaid/公式也完整导出；连续修改后预览不被旧结果覆盖；导出进行中编辑仍得到单一快照；失败不报成功。本步骤是内容完整性要求，不引入MathJax专项优化。

### A5（H1）：资产清单与单文件离线

- 资产登记来源、MIME、字节、哈希、许可、所属节点、是否必要及封装方式；识别img/SVG引用、CSS url/@font-face和批准的@import，限制类型、大小和递归循环。
- 资源下载/CORS/权限失败时产生未完成依赖诊断，不自动声明离线，也不自动代理上传文档。第三方URL需遵循产品明确网络策略。
- 阅读HTML内嵌或明确替代全部必要资产，消除blob及应用相对路径依赖；可编辑HTML包含可重建文档的必要资源，普通无源载荷HTML仍不承诺恢复Markdown。
- 第一批使用可靠系统回退；字体内嵌须有许可及字形覆盖证据。高级字体导入/轴控制/子集化留到H2，不提前加包体优化。
- 为源载荷增加完整schema验证和旧版本迁移/拒绝规则；保留Markdown原文及有效元数据，导入时允许有意分配新文档ID，不将其误判为内容变化。

退出：断网实际打开单文件，图片/图表/公式无缺失；资源清单哈希及重开原文一致；外链未解决时准确阻止或显式降级。file://路径单独验证，不由localhost通过推断。

### A6（H1）：打印与现有DOCX适配

- 文档print.css与阅读CSS分工，配置@page/@media print、表格续页、标题孤行、宽代码/超高公式/图表、分页指令；控制界面和临时标记不进输出。
- 先暴露当前显式分段和长页缺口，禁止overflow:hidden截断后称为分页完成；自动分页修复先独立ADR，比较原方案Paged.js与现实现，不直接自研增量分页。
- 保持分页器移动/克隆节点后的容器上下文；显式分页不得切断公式/代码语义或破坏源行映射。
- DOCX按自身原生对象能力映射；Grid/容器布局可重排或明确降级，公式维持图片路径。inspect按节点报告unsupported/static/mapped，选择后执行，不静默图片化或丢正文。
- 仅列出PPTX/EPUB未来矩阵，不实现导出器。

退出：真实A4预览、生成PDF文字/资源完整性、指定Word及替代阅读器验收分别记录；未取得环境则标未验。实体打印与系统预览/PDF检查不互相冒充。

### A7（H1收口）：兼容证据与CI门禁

- CI保持冻结安装、类型检查和构建；接入已新增的Vitest、Playwright生产构建与独立导出测试，失败上传trace/截图。PR检查应包含html分支目标，分支push触发策略在CI变更中明确；不靠无触发的工作流宣称受保护。
- 固定浏览器/字体/样例，先Chrome/Edge，再记录Firefox/WebKit及实际Safari需求；CSS.supports/API存在检查加真实几何/显示测试，WebKit不等于Tauri实机。
- 证据包含提交SHA、featureId、阅读/打印/格式、运行环境、样例、检测、实测、日期与限制。截图更新必须Review，禁止用刷新基线隐藏回归。
- 验证既有导入/保存/恢复、同步滚动、七种显隐组合、配置弹窗、1024px可配置和DOCX，避免HTML改造破坏工作台。

退出：H0/H1支持清单逐项有证据，核心数据/输出错误阻塞项关闭，文档准确标记限制。只对通过的能力给出支持声明；不更改0.9标签，不自动合并/发布1.0。

## 4. 后续路线：不是A0–A7的实施清单

| 阶段 | 后续能力 | 启动门槛 |
|---|---|---|
| H2 | 独立HTML/CSS模板宿主、受控作者入口、主题包及变量字体导入/轴、完整资产包 | H1通过；先ADR选择宿主和语法，验证隔离/迁移/打印及非HTML降级后逐项开放 |
| H3 | 注册交互组件，initialize/whenReady/serializeState/pause/renderStatic/dispose；之后才评估自定义JS | 与静态模式分开；独立来源/sandbox及消息schema，不能同时给不可信srcdoc任意脚本与同源权限；无Tauri桥接权限 |
| H4 | 滚动/样式容器查询、新CSS、复杂多栏/纵排、Canvas/WebGL/媒体静态化与多平台覆盖 | 有真实需求和独立样例；读取/打印/各格式分别适配，失败不阻塞静态能力 |

H2–H4各自批准范围后规划实际版本。脚本交互、单文件可打开、完整离线是三个验收维度，不因保存innerHTML就认定成立。

## 5. 建议提交拆分与执行门禁

建议每个A步骤至少一项独立变更；需要多个提交时保持可运行中间态，不一次提交全栈重写。消息可使用 `docs(html): ...`、`test(html): ...`、`fix(html): ...`、`feat(html): ...`。

实施前先Review契约/ADR，代码后Review数据边界、异步与清理，输出再Review浏览器和实际文件。每步运行相应类型、测试、构建及输出验证，记录失败/未验范围；尚未实现的H2–H4不作为当前门禁。依赖与schema变化同步锁文件/样例/迁移说明。不得通过静默降级、延时或清空诊断使测试通过。

初始规划时创建本地html分支，仅新增基线摘录和计划；该句为历史记录，当前已完成A0–A7实施及R0–R4审查。用户随后授权每完成并验证一个步骤创建一次本地提交，禁止推送。实施状态见 html-implementation-status.md。
