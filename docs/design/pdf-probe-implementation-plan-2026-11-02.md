## 1. 范围与目标

| 项 | 内容 |
| --- | --- |
| 目标 | 验证 Windows 上能否用隐藏 WebView2 加载冻结分页 HTML 并经 `PrintToPdf` 静默产出 PDF，以及输出宿主与业务 IPC 之间的隔离是否成立 |
| 范围 | D0 基线与产物核对；D1a 最小来源限制；D1b 授权夹具与权限探针；D1c 隐藏宿主与原生输出；D1d 内容核验与总阶段结论 |
| 不在范围 | Web 打印路径变更；D2 契约改动；EX-T/EX-W3 门槛放宽；macOS/Linux；字体打包；跨卷搬运分支；D7/D8 生产接入 |
| 平台 | Windows。本路线其余平台不变，Mac/Linux Future 仍在 D9 之后 |
| 结论 | 三类：通过 / 当前形态不可行 / 未能确认。后两者结束本轮探索，Windows 静默 PDF 标待验证，D7/D8 暂停，Web 路径不受影响 |

**不在前半段的已知不确定性**：D1c/D1d 的原生输出与内容保真依赖尚未验证的平台能力；D1a/D1b 的依据已足，故本方案从前半段起排。

## 4. D1a 最小来源限制

生产代码，**不受 `pdf-probe` 控制**，D8 生产接入复用。

### 4.1 动作

1. 保留现有 async 命令签名，注入 owned `tauri::Webview`，在文件与对话框副作用**之前**执行来源限制。
2. 明确主界面与输出宿主的精确身份映射，并据此定义允许范围。
3. 判定逻辑收在一处（共享守卫函数），各敏感命令调用它。不引入注册表、配置层或权限平台。
4. 输出宿主的身份由生产侧具名常量定义（label 与形态同源），允许范围引用该常量；D1b、D1c、D8 使用同一常量与同一创建路径。宿主创建归 D1b，D1c 复用该创建路径而非另建形态。

   两条一致性断言：编译期——实现使用的即该常量，不存在第二份字面量；运行期——创建出的宿主 label 等于常量值。

### 4.2 断言

| # | 断言 | 判定依据 |
| --- | --- | --- |
| D1a-1 | 注入类型与宿主形态一致 | 类型检查通过；`Webview` 与 `WebviewWindow` 的解析行为与 D0-4 一致。**本断言在 D1a 只覆盖主窗口路径**：输出宿主在 D1a 时尚不存在，其对应部分由 D1b 的证据矩阵承担 |
| D1a-2 | 允许范围按真实身份映射表达，不假设 label 相等、不以枚举即允许 | 允许范围含窗口与 WebView 的身份对；同窗新增 WebView 不自动被允许 |
| D1a-3 | 主窗口允许路径在该允许范围下仍可用 | 主窗口 `get_platform_info` 与既有文件命令可调用 |
| D1a-4 | feature 关闭时来源限制仍生效 | 以默认 feature 集构建，主窗口允许路径仍可用、限制仍在 |
| D1a-5 | 限制发生在副作用前 | 敏感命令在读取文件或弹出对话框前被拒 |

### 4.3 退出条件

D1a-1 至 D1a-5 全部成立；类型检查通过；定向回归通过。完整双宿主调用证据在 D1b 取得，本步不要求。

## 5. D1b 授权夹具与权限探针

仅测试路径受默认关闭的 `pdf-probe` feature 控制。**正常授权释放、来源检查与业务清理始终保留**，不得随 feature 一并消失。

### 5.1 动作

1. `pdf-probe` feature 默认关闭，显式启用；不以 `debug_assertions` 替代。
2. Rust 受限初始化铸造受控授权：**不经 IPC**，不改 `invoke_handler`，不新增前端铸造命令。【待定 TBD-14：签发的具体形态与 key 向探针页的交付方式尚未定义】
3. 读、写两种角色分别签发（`files.rs` 按 `writable` 校验角色）。
4. 创建输出宿主作为探针载体：使用与 D1c 相同的创建函数、同一常量与同一形态；断言创建出的 label 等于常量值。
5. 独立探针页：带脚本，与交付用样本分离；不为测试放宽生产 CSP。
6. 记录实际构建命令与有效 feature 集合；核 feature 关闭构建中测试入口确实不存在。

### 5.2 证据矩阵

| # | 证据 | 判定依据 | 作废条件 |
| --- | --- | --- | --- |
| D1b-1 | 通道阳性 | 主窗口 `get_platform_info` 成功 | 阳性不成立则 D1b-3 与 D1b-4 一律作废 |
| D1b-2 | 主窗口同命令允许 | `read_native_text` 配受控 key，返回**准确内容** | 返回内容与夹具不符则不作数 |
| D1b-3 | 输出宿主同命令拒绝 | 同合法 key，明确拒绝原因；记录真实调用方身份、拒绝层（ACL / Rust 来源检查 / 未确认）与对应代码与配置版本 | 拒绝层为"未确认"不算通过；ACL 先拒绝只证明该层拦截，不证明 Rust 检查已被实际调用。【待定 TBD-05：两类拒绝的错误形态能否在运行期区分尚未核对，若不可区分则本行的拒绝层字段落空，Q26决定需退让】 |
| D1b-4 | 选择器补充 | 输出宿主调用选择类命令被拒，且**不弹出任何原生对话框** | 弹出对话框即不算通过。【待定 TBD-06：如何自动观察"未弹框"未定，超时判定与人工观察的取舍未定】 |
| D1b-5 | feature 关闭构建 | 生产来源限制与主窗口允许路径仍有效；测试入口不进入正常构建 | 任一不成立则不算通过 |
| D1b-6 | 清理证据 | 探针专用回收生效；正常 `release_native_file` 等业务清理未被一并移除 | 未移除或失效即不算通过 |

不触碰用户文件。拒绝时不得泄露被拒内容。

### 5.3 退出条件

D1b-1 至 D1b-6 全部成立；拒绝层可识别；探针无效不算通过。

## 6. D1c 隐藏宿主与原生输出

### 6.1 动作

1. 输出宿主：**用与 D1b 相同的创建函数、同一常量与同一形态创建**（独立 label、`visible(false)` 的专用 WebviewWindow），复用其 WebView2 控制器；不并行建设其他宿主形态，不自动换宿主。每次运行各自创建一台，走同一路径而非共用实例。
2. 原生接口访问与转换、`PrintToPdf` 异步完成回调、COM 引用与回调生命周期、加载与基本清理。
3. 受控就绪检测：目标顶层导航成功且文档加载完成、`document.fonts.ready`、图片成功加载或解码、页面盒数量与尺寸核对。HTML `img` 与 SVG `image` 按实际 API 分流。**不使用固定睡眠，也不以 rAF 为必需就绪条件**；不开放作者脚本；须证明受控检测与 CSP 兼容。【待定 TBD-11：原生受控脚本执行是否受冻结 HTML 的 `default-src 'none'` 约束未核，若受限则就绪检测路径需另找】
4. `PrintToPdf` 输出到受控临时文件；默认与目标同目录、同卷提交，参考 M3 `commit_bytes` 的 `new_in(parent)` / `sync` / `persist` 保护原则；不默认走系统临时卷 rename，不默认引入跨卷复制分支。【待定 TBD-12：原生输出能否指定目标目录未核；TBD-15：`commit_bytes` 接 bytes，把其保护原则套到原生 PDF 文件输出属新适配，非既有实现】
5. 清理：成功、失败、超时、关闭均释放宿主与临时资源。超时后须先使原生任务不能再提交或写入目标，再清理临时文件；迟到回调不得报成功。

### 6.2 断言

| # | 断言 |
| --- | --- |
| D1c-1 | 目标文档加载完成且就绪判据成立，未使用固定睡眠或 rAF |
| D1c-2 | 取得实际 PDF，或取得明确失败证据（含错误与环境） |
| D1c-3 | 临时文件与目标同卷，提交受控；失败时原文件保持不变 |
| D1c-4 | 清理完成，无残留宿主与临时文件；迟到回调未改变回执 |
| D1c-5 | 无窗口闪现、无打印面板 |

### 6.3 退出条件

D1c-1 至 D1c-5 成立，或取得明确失败证据。**取得文件不等于整体通过**；运行闭环与内容正确分开判定，内容正确归 D1d。

## 7. D1d 内容核验与总阶段结论

### 7.1 断言

| # | 断言 | 判定依据 |
| --- | --- | --- |
| D1d-1 | 输出 PDF 物理页数等于固化 HTML 的 `data-export-pages` | 页数相等是必要条件而非充分条件 |
| D1d-2 | 首页与末页渲染非空；首尾标记位于预期页 | 用样本标记断言，不以含糊的"第一行"代替 |
| D1d-3 | 关键首尾正文与 CJK 可提取 | 实际提取结果；`uni=no` 不必然表示不可提取，以提取与字形核对判断。【待定 TBD-13：文本提取与字体报告依赖 poppler 工具，尚未安装且需另行授权】 |
| D1d-4 | 字体报告完整 | `pdffonts` 的类型 / emb / sub / uni；字体报告不能替代 D1d-3 与 D1d-5 |【待定 TBD-13】 |
| D1d-5 | 代表页的公式与图表渲染正确 | 代表页实际渲染核对 |
| D1d-6 | 无额外空白页、无截断、无闪现、无打印面板 | 与 D1c-5 合并核对 |
| D1d-7 | 既定 IPC 隔离证据、静默证据与清理证据齐备 | 引用 D1b 与 D1c 的阶段记录 |

### 7.2 结论

| 结论 | 条件 | 后果 |
| --- | --- | --- |
| 通过 | D1d-1 至 D1d-7 成立，且 D1a、D1b、D1c 证据齐备 | 允许进入 D7 评估；不自动推进 |
| 当前形态不可行 | 存在明确可复现的原生加载 / 接口 / 输出机制限制 | 结束探索；Windows 静默 PDF 标待验证；D7/D8 暂停；Web 路径不受影响 |
| 未能确认 | 权限、探针、环境或清理问题未排除 | 同上；不得记为通过 |

生成失败也可归档阶段结论，内容检查标"未执行"，**不伪称通过**。

## 8. 失败归类与证据复用

| 失败类型 | 归类 | 说明 |
| --- | --- | --- |
| 权限配置不满足 | 未能确认 / 阻塞 | 不是宿主形态问题 |
| 探针无效或阳性无效 | 未能确认 / 阻塞 | 阴性证据一律作废 |
| 环境或依赖缺失 | 未能确认 / 阻塞 | 不是路线证伪 |
| 清理失败 | 阻塞 | 须记录阻塞并停止后续接入，不能称基本清理通过 |
| 原生加载 / 接口 / 输出机制限制 | 当前形态不可行 | 须有明确可复现证据 |

**证据复用**：D1c/D1d 的 PDF 失败不自动作废 D1a/D1b 的来源与权限证据。仅在相关代码、配置、依赖、宿主身份与来源、调用路径等前提仍匹配时可复用；后续变化影响其结论须补受影响验证。不得简化为"Rust 代码还在即可复用"，也不要求一轮探针对未到达的所有层都给运行通过。

## 10. 未验证的边界

以下事项在本方案结束时仍属未验，不得在支持表中宣称已支持：

- 冻结分页 HTML 跨环境重新输出的版式一致性（仅本机生成与交付验证）。
- PDF 成品的字体嵌入、显示与可选文字的跨机保证（嵌入字体只是一层证据）。
- Windows 静默 PDF 的完整产品化保真（归 D7/M8）。
- 系统默认文件名、路径与实际保存证据（归 D5 与 D6）。
- Word/WPS 的公式可编辑、保存重开与版面支持。
- macOS/Linux 的原生 PDF。

### 13.6 TBD-07 的三个走法（待确认）

固化分页 HTML 的产出需要跑一次前端生成路径，而 D0 定位为只读核对。

| 走法 | 内容 | 影响 |
| --- | --- | --- |
| (a) | D0 允许一次受控的前端生成路径产出固定文件，不改产品代码 | D0 的"只读"约束的是不修改被检查的代码，不排除运行既有生成路径；产样本是取证不是实施。**倾向此路** |
| (b) | 样本产出单列为 D0 之前的一个小步 | D0 保持严格只读，但增加一个阶段 |
| (c) | D0 允许一次产物生成，并明确其不算实施 | 与 (a) 接近，差别在表述而非实质 |

无论选哪一种，样本交接物都须包含：SHA-256、`data-export-pages` 预期值、首尾标记的期望页码、生成提交与 OS/WebView/字体环境说明。
